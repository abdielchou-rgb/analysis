# 圆桌评审 Skill

## 触发
报告初稿完成后，自动触发多角色独立评审。

## 核心原则
评审 Agent 与写作 Agent **隔离**（不同上下文），天然对抗，解决"单 Agent 自己写自己改"的质量天花板。

## 评审角色（4+ 席）

| 角色 | 视角 | 重点查 |
|------|------|--------|
| 投行分析师 | 财务模型纪律 | NPV主指标唯一/敏感性完整/估值口径/终值假设 |
| MBB 合伙人 | 战略框架 | 波特五力/生命周期/利润池/商业模式/假设可证伪 |
| 券商 MD | 合规与叙事 | 关联交易/持股比例/商誉表述/信息披露口径 |
| 会所合伙人 | 审计可追溯 | 数字可复算/标注完整/底稿可溯/税务口径 |

## 评审流程
1. 独立复算：NPV/IRR/盈亏平衡/三情景加权/敞口——每个数字重算，找"披露值之间的隐含关系矛盾"
2. 框架审计：对照 SAC 维度 + 框架适配清单，找"该用未用"（如漏波特五力）
3. AI 痕迹扫描：工作过程语言/元评论语言/版本迭代说明（用 2hao template_blacklist）
4. 分级输出：Critical（必修）/Warning（应修）/Nit（可选），每条附修复建议

## 输出格式
```
### Critical（必修）
| 编号 | 位置 | 问题 | 修复建议 |
### Warning（应修）
### Nit（可选）
### 总评级
评级：xx（通过/附N项必修/有条件推进）
```

## 落地
- 评审角色用独立 Subagent（隔离上下文）
- 评审用 2hao 门禁工具辅助（data_caliber/verify_report/metacomment扫描）
- 评审结果回流写循环（只重跑受影响模块）

## 实战教训（油位14版）
- 单 Agent 反复 patch 会引入元评论语言 → 评审必须独立
- Marvis 三轮圆桌发现的问题（悲观情景矛盾/税务敞口/表内残留）→ 复算要覆盖"披露值之间隐含关系"
