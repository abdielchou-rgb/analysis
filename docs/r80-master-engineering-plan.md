## 一、执行总纲

### 战略目标
从"结构正确的模板机"进化为"有洞察、有信息增量、像人、可验证、可规模化"的超级分析师。

### 五大工程支柱
| 支柱 | 解决 | 对应问题 |
|------|------|---------|
| A. 生成端约束 | 一次写对，非写了再打回 | 模板/反方空壳/硬凑/慢 |
| B. 评估端独立 | 外部标杆+LLM-judge | 自我印证/测试虚假安全感 |
| C. 数据端穿透 | 二手极致化+合规分级 | 无一手数据/溯源表演性/合规 |
| D. 交付端唯一 | 唯一渲染管线+产物验证 | 排版复发/PDF无图/打地鼠 |
| E. 系统端治理 | 回测闭环+成本预算+架构瘦身 | 验证未运转/成本失控/熵增 |

### 执行优先级矩阵
```
高影响
  │
  A 生成端约束 ─────┬───── D 交付端唯一（排版/出口）
  （治本，见效快）   │     （立即止血）
  │                 │
  B 评估端独立 ─────┤     C 数据端穿透
  （外部标杆）       │     （二手极致化）
  │                 │
  E 系统端治理 ─────┘
  （回测/成本/瘦身）
  │
低影响
  低工作量 ←──────────→ 高工作量
```

## 八、执行顺序与依赖

```
Phase 0（止血）→ Phase 1（生成端）→ Phase 2（评估端）→ Phase 3（数据端）
→ Phase 4（交付端）→ Phase 5（系统端，持续）
```

**依赖关系**：
- Phase 1 依赖 Phase 0（先生成能写对，再约束生成）
- Phase 2 依赖 Phase 1（先有好的生成，才能评估）
- Phase 3 独立可并行
- Phase 4 独立可并行
- Phase 5 持续，与各阶段并行推进

## 十一、风险与对策

| 风险 | 对策 |
|------|------|
| 外部 golden 采集困难 | 从东方财富/慧博下载公开券商PDF，5份即可起步 |
| LLM-judge 也模板化 | judge 用对侧 provider + rubric，且定期校准 |
| 合规分级误伤访谈 | 敏感信息只影响方向判断，不入正文，显式标注 |
| 成本预算卡死质量 | 预算动态：质量达标才放松预算 |
| 重构引入回归 | 每个 R80 改动过端到端回归 |
