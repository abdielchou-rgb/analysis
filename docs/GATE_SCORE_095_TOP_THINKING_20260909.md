# Gate 0.95 顶级思考 — 分数背后的系统论

**日期**：2026-09-09
**性质**：不是修复方案（那是 `GATE_SCORE_095_THINKING_20260909.md`），是修复方案背后可迁移的原理层
**证据**：本次会话全部诊断数据 + 昨日 smoke test 实测

---

## 〇、先重构问题："怎么到 0.95"是个错误的问题

0.95 的原始问法假设：分数 = 质量，提分 = 提质量。诊断推翻了这个前提。真正的问题是三个：

1. **这个分数在测什么？**（测量有效性）
2. **失分从哪里来？**（归因）
3. **0.95 够不够、1.0 要不要？**（决策相关性）

以下五条思考按深度递进。

---

## 一、LLM 管线的质量瓶颈是管线，不是模型

**发现**：本会话累计 9 个质量问题，8 个是确定性工程缺陷，1 个是模型能力问题。

| 问题 | 类型 |
|---|---|
| compute_results 不进写作上下文 | 接线 bug |
| KB retrieved 计数缺失 | 观测 bug |
| earnings_notes 无维度分组 | 配置缺失 |
| earnings_notes 无图表模板 | 配置缺失 |
| rewrite 丢锚卡（260 vs 300） | 管线 bug |
| so_what 分母混入合规段 | 检查器 bug |
| anti_patterns 黑名单过期 | 检查器 bug |
| data_dict 冲突未消解 | 后处理 bug |
| **归因深度不足** | **唯一的模型问题** |

**原理**：模型决定质量上限，管线决定质量下限；用户和 Gate 体验到的几乎全是下限。LLM 正确写出毛利率 26.27%(A)，管线随后让 rewrite 把它写成 44%——再好的模型也扛不住这种"内部攻击"。

**推论**：在集成型 LLM 系统里，"提升写作质量"的最短路径经常是修管线。"换更强模型"的正确时机是管线零缺陷之后——否则你分不清新模型的增量和旧 bug 的噪声。

**处方**：质量工作排期按"确定性 × 失分"排，不按"听起来重要"排。确定性 100% 的管线 bug 永远先修。

---

## 二、缺陷不能平均：0.885 通过了一份带硬伤的报告

**发现**：本次 0.885 通过的报告里，正文存在"2022 毛利率 44% vs 数据库 20%"的**事实性矛盾**。它没被阻断，因为它以 0.40 的分数被平均进 error_mean，其余 22 项的高分把它"稀释"过了阈值。

**原理**：平均化适合密度型指标（So What 密度、引用密度——多一段好的，少一段差的，均值有意义），对缺陷型指标是**设计出来的假阴性**：

```
缺陷（数据矛盾/编造/目标价冲突）→ 二值的：有或没有，一个就能摧毁整篇可信度
密度（So What/引用/图表分析）→ 连续的：均值有意义

把缺陷平均进总分 = 允许 22 项好成绩给 1 项致命伤"背书放行"
```

真实投行的运作正是二分的：事实错误过不了合规（一票否决），文笔不够好是编辑意见（不打回）。IronGate 的 error/warning 分级已经存在，但分错了类——`data_dict_refs` 应该是一票否决项，不该参与平均。

**推论**：本次"Gate 通过"存在幸存者偏差——如果客户先看到 44% vs 20% 的矛盾，Gate 的 0.885 就不是质量证明而是责任问题。

**处方**：Gate 拆成两层——
- **合规层**（一票否决）：数据矛盾、编造来源、目标价冲突、体系性泄漏。任一触发即 block，与总分无关。
- **编辑层**（平均打分）：密度类检查，均值 + 阈值。

这是从"分数门槛"到"零缺陷 + 高均值"的范式转换，也是 0.95 问题的真正答案：**追 0.95 之前先让硬缺陷不可能随分数漂出去。**

---

## 三、三工件漂移：质量系统=三个必须同步的工件

**发现**：三个检查器 bug 不是孤立的，是同一个模式的三个实例：

```
生成器（writer/rewriter）—— 工件（报告格式）—— 校验器（Gate 检查）
```

| Bug | 哪两个工件漂移了 |
|---|---|
| so_what 把评级表/合规段算进分母 | 报告格式演化了（加了合规段），检查器的假设没跟上 |
| rewrite 丢锚卡 | write 节点有约束，rewrite 节点没继承 |
| anti_patterns 漏掉"(反身性)"后缀 | LLM 输出分布漂移了（新逃逸变体），黑名单没跟上 |

**原理**：任何质量系统都由三个工件构成，三对边界各自会漂移。同步是暂态，漂移是稳态——除非有机制强制同步。这次三个 bug 全部是"曾经同步，后来没人维护同步"。

**推论**：修三个 bug 只是还债。不欠新债的方法是**给校验器写测试**：

```
金样本测试：一份已知"完美"的合成报告 → Gate 全绿
毒样本测试：注入已知缺陷（合规段So What陷阱/新句式变体/矛盾数字）→ 对应检查必须亮红
```

这就是元测试（测测量系统）。LLM 管线界几乎没人做——大家测代码，不测"判断代码对错的代码"。但 so_what 分母 bug 恰恰只有毒样本测试能拦住：你写个含评级说明表的报告喂进去，断言 so_what 不惩罚它。

**处方**：`tests/gate_meta/` 建金/毒样本对，Gate 每次改检查逻辑必须过元测试。校验器从"不可测的黑盒法官"变成"被测系统"。

## 四、约束卡架构：rewrite 丢锚是必然，不是意外

**发现**：write 的 prompt 有"全文所有数值以锚卡为准，禁止同指标两值"。rewrite 的 prompt 没有。为什么？

**原理**：这套约束不是设计遗漏，是**结构必然**——约束散落在各节点的 prompt 文本里（隐式契约），新增节点（rewrite 是 P2 后加的）时没有任何机制提醒"你要继承 write 的全部约束"。逐条打补丁的结果永远是"最后修的那条有约束，之前的都忘了"。

**推论**：同类问题以后还会出现：(A)/(E)/(F) 标注、图表引用格式、禁语清单——rewrite 都可能丢。逐条修是打地鼠。

**处方**：把"所有文本产出节点必须遵守的不变式"提为**单一共享工件**（约束卡：锚定数值表 + 数据字典口径 + 标注规范 + 禁语黑名单），write/rewrite/任何未来节点一律从这同一对象渲染约束段。然后配**改写后不变式复验**：rewrite 完成后跑廉价校验（数字与 data_dict 对账、目标价唯一性），违例自动回退原稿。

这就是数据库迁移的安全模型：不是只跑受影响的断言，是 ALTER 之后**跑全量测试套件**。"回归即回滚"应用到文本。

> 本次 Delta-Only Rewrite 已经做到"给失败维度精准证据"，缺的正是后半件——重写后的不变式复验。两者合起来才是完整闭环。

## 五、先给测量系统装仪表，再对着它优化

**发现**：`diagnose_gate.py`（30 行）一次运行就揭示了 85/15 分割、三个检查器 bug、修复优先序。在此之前，Gate 只输出一个总分，所有人都只能对着总分猜。

**原理**：这与性能优化界的铁律同构——**measure, don't guess**。对着不透明的分数优化会产生两种病：

1. **指标游戏**：猜测 Gate 喜欢什么，堆模板句式骗 So What 密度（分数涨了，质量降了）
2. **归因巫术**：报告变差→"模型不行"，实际是 rewrite 丢锚

Gate 越权威，黑盒危害越大。任何评分系统上线时必须自带解释模式：哪个检查、扣了多少、为什么、怎么修。

**处方**：`diagnose_gate.py` 升级为 `gate --explain` 子命令进 main.py。以后任何人看到低分，第一动作是跑 explain，而不是改 prompt。

## 六、终局：0.95 之后是什么

**决策相关性检验**：0.95→1.0 意味着 23 项全满分且每轮稳定——这是在对抗 LLM 方差，而方差有不可压缩下限。正确的停止条件不是分数而是：

```
合规层：硬缺陷 = 0（一票否决保证）
编辑层：均值 ≥ 0.90 且 p95 单项 ≥ 0.85（方差受控）
人的抽检：每周抽 1 份盲评，与 Gate 分数相关性跟踪
```

当 Gate 分数与人类盲评持续脱钩，说明测量系统漂移了（回到思考三），该修的是 Gate，不是报告。

## 七、可迁移清单（超出本系统）

| # | 原理 | 一句话 |
|---|---|---|
| 1 | 下限定律 | 模型定上限，管线定下限；先让管线零缺陷，再谈模型能力 |
| 2 | 缺陷不可平均 | 缺陷二值否决，密度均值打分；平均缺陷=设计出来的假阴性 |
| 3 | 三工件漂移 | 生成器/工件/校验器三对边界必然漂移；元测试（金/毒样本）是强制同步机制 |
| 4 | 约束卡 | 节点间隐式契约必丢；不变式提为单一共享工件+改写后复验+违例回退 |
| 5 | 仪表先行 | 对不透明分数优化=指标游戏；每个评分系统自带 explain 模式 |

---

## 八、一句话

> 用户问的是"怎么到 0.95"，诊断给的答案是"你追问错了刻度"。0.885 里 85% 的失分是管线在漏，不是模型在弱；真正致命的那个数据矛盾不是分数不够高，而是**它根本就不该被允许参与平均**。顶级系统不是分数更高的系统，是"硬缺陷零漂出 + 密度稳定 + 测量系统自证有效"的系统——分数只是这三件事的副产品。
