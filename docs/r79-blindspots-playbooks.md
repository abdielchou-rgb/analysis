# 2号分析师盲区的顶级打法调研

> 针对 r79-blind-spots.md 的 6 个结构性盲区，对标顶级实践
> 日期：2026-08-06

---

## 盲区 1：FP5 验证闭环从未运转 → 预测回测体系

**顶级打法**：

### 1.1 量化基金的策略回测（最成熟）
- **walk-forward 分析**：把历史数据分段，滚动训练+测试，模拟真实时点判断。不是一次性测，是不断前移窗口
- **点估计 + 置信区间**：每条预测记录"预测值/方向/置信度/到期日"，到期后对比实际，算命中率
- **校准曲线（Calibration Curve）**：预测"70% 概率"的事件，实际是否 70% 发生？偏了就调阈值
- **Brier Score / Log Loss**：衡量概率预测准确度，比"对错"更细

**落地 2hao**：
- 3M/6M 短周期信号（R78 已建台账）作为回测样本
- 到期后自动对账：预测 vs 实际股价/招标量/执行率 → 算命中率 + 校准曲线
- 用校准结果回写 Gate 阈值（如 DES 阈值从 30% 调到实际最优值）

### 1.2 AlphaGo 自我对弈 + 验证
- 系统先自我生成判断 → 等结果 → 用结果更新评估标准
- 关键：**评估标准本身也要被校准**，不是固定的

### 1.3 预测市场 / 竞技预测（Superforecasting）
- Philip Tetlock 的超级预测者：把大问题拆成可验证子问题，每条带概率和到期日
- 事后逐条复盘"为什么对/错"，沉淀为校准经验

**核心**：验证不是"事后看一眼"，是**闭环系统**——预测→到期→对账→校准阈值→改进生成。

## 盲区 2：golden dataset 自我参照 → 外部基准

**顶级打法**：

### 2.1 LLM Eval 的基准集方法
- **SuperGLUE/MMLU 模式**：用**外部权威基准集**（非自产）评估模型，对比 SOTA
- 2hao 应采集 5-10 份真实券商研报（中金/国泰君安/天风 同行业）作为 **外部 golden**，和自产报告同指标对比
- 指标：洞察密度/反方强度/数据溯源/排版质量，逐项比差距

### 2.2 人类专家评审（Human Eval）
- 把 2hao 报告和真实研报**匿名混合**，请资深分析师盲评"哪份更像人写的、哪份更有洞察"
- 这是图灵测试的落地——R42 的双阈值图灵测试应该有**真人对标**

### 2.3 Rubric 外部化
- 评审标准不自己定，参考**权威评估框架**（如 CFA 研究报告评分标准、投行内部研报考核表）
- 用外部 rubric 打分，而非自定"判断密度 1.2"这种自造指标

**核心**：标杆必须来自外部（真实研报 + 真人盲评），否则永远是自我感觉良好。

## 盲区 3：专家访谈内幕交易风险 → 券商合规体系

**顶级打法**：

### 3.1 券商研究的合规三原则
- **信息分级**：公开信息 / 半公开信息（付费数据） / 敏感信息（内幕）
- **敏感信息隔离**：访谈获知的未公开信息（"某客户下季度翻倍"）**禁止入正式报告**，只能用于内部判断方向
- **留痕审计**：访谈记录/时间/对象全留痕，可追溯（一旦出事能自证清白）

### 3.2 信息隔离墙（Chinese Wall）
- 研究部与投行部隔离，防止内幕信息跨部门流动
- 2hao 的 enrich-file 应设"信息来源分级"字段：公开(A)/付费(B)/访谈未验证(C-敏感)
- **C 级信息一律不入报告正文**，只能影响判断方向，且必须显式标注"基于非公开信息的方向性判断"

### 3.3 监管红线认知
- A股内幕交易认定：内幕信息 + 利用该信息交易 = 违规
- 报告引用非公开信息 = 可能构成"泄露内幕信息"
- **底线**：报告的每个信息点必须**公开可查**，这是合规的生命线

**核心**：如果要做专家访谈，先建"信息来源分级 + 敏感信息隔离 + 全留痕"，否则宁可不做访谈。

## 盲区 4：成本失控 → token 预算制

**顶级打法**：

### 4.1 成本感知的级联模型（Cascading）
- 简单任务用小模型（Haiku/本地 Ollama），复杂任务才用大模型
- 分级：格式检查→本地规则；段落写作→小模型；战略判断→大模型
- 已有三算力架构（R13），缺的是**任务-模型匹配策略**

### 4.2 Prompt Caching
- 系统提示词（SAC+注入）稳定不变 → 触发 KV cache → 省 80-90% 重复处理
- DeepSeek context caching 自动，确保系统提示词部分恒定

### 4.3 预算上限 + 降级策略
- 每份报告设 token 预算（如 100 万），超支触发降级：
  - 全量重写 → 局部修订
  - LLM 检查 → 确定性检查
  - 3 轮迭代封顶 → 2 轮 + 最佳稿
- **成本阈值也是 Gate 指标**：cost_per_report 超标 → warning

### 4.4 推理成本可视化
- 每次运行记录 token 消耗/费用/耗时，形成成本面板
- 让"慢/贵"可量化，优化有据可依

**核心**：质量优化必须配成本预算，否则每优化一层贵一层。

## 盲区 5：测试虚假安全感 → 端到端回归

**顶级打法**：

### 5.1 E2E Testing（端到端测试）
- 不只测单元（检查项），测**整份报告**：真实跑一份 golden 报告过全量 Gate
- `test_r79_e2e_report.py`：输入真实素材 → 跑管线 → 校验验收指标（模板/DES/硬凑/空段/PDF含图）
- 每次改代码必须过端到端，否则视为未完成

### 5.2 Golden Regression（黄金回归）
- 3-5 份 golden 报告每次跑全量，比对验收指标
- 指标退化（DES 从 30% 掉到 0%）→ 立即拦截
- 防止"修了这个，坏了那个"

### 5.3 Canary Release（金丝雀发布）
- 新改动先跑 1 份报告验证，通过再全量
- 大改动分阶段：先跑 1 份 → 3 份 → 全部

### 5.4 覆盖率审计
- 70+ 检查项，逐项统计"过去 10 份报告里触发了几次"
- 从未触发的检查项 = 死代码，删除
- 触发但从不拦截的 = 阈值太松，调紧

**核心**：测试必须覆盖"整份报告质量"，不是"零件能转"。

## 盲区 6：架构熵增 → 技术债治理

**顶级打法**：

### 6.1 Boy Scout Rule（童子军规则）
- **每次改动让代码比来时更干净**：加一个功能，顺手删一个冗余
- 每 R 版本强制"加一删一"（新增检查项必须删一个旧检查）

### 6.2 复杂度预算（Complexity Budget）
- 设上限：section_writer ≤1500 行、检查项 ≤60 个、注入变量 ≤25 个
- 超限强制重构，否则禁止加新功能

### 6.3 依赖倒置 + 模块化
- 上帝模块拆解（R78 转发模式）持续，把可独立逻辑抽到独立模块
- 新代码必须模块化，禁止继续膨胀主文件

### 6.4 定期重构迭代
- 每 3-5 个 R 版本做一次"清理迭代"：删死代码、合并重复、简化逻辑
- 类似大厂的"技术债周"

### 6.5 死代码检测
- 覆盖检查：70+ 检查项里，找出从未触发/从未拦截的，删除
- 30+ 注入变量里，找出从未被 LLM 消费的，删除

**核心**：系统要能"瘦身"，不能只涨不缩，否则最终无人敢改。

## 总结：6 个盲区的顶级打法总览

| 盲区 | 顶级打法 | 核心工具 |
|------|---------|---------|
| 验证闭环 | 量化回测 + 校准曲线 + 超级预测 | walk-forward、Brier Score |
| 自我参照 | 外部基准 + 真人盲评 | 真实研报 golden、图灵测试 |
| 合规风险 | 信息分级 + 隔离墙 + 留痕 | 来源分级、敏感隔离 |
| 成本失控 | 级联模型 + 预算制 + 缓存 | 任务-模型匹配、token预算 |
| 测试虚假 | 端到端 + 金丝雀 + 覆盖率审计 | golden regression、canary |
| 架构熵增 | 童子军规则 + 复杂度预算 + 重构 | 加一删一、清理迭代 |

**一句话**：这 6 个盲区全是"系统工程"问题——验证要闭环、标杆要外部、合规要分级、成本要预算、测试要端到端、架构要瘦身。每个都有成熟行业打法，2hao 需要的是**停止只修报告表面，开始治这 6 个系统层面**。
