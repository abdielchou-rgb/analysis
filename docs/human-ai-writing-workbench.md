# 人机协作写作工作台——深度报告方法论 V1

> **定位**：可复用的深度报告写作产品/方法论，替代传统"管线调度"模式
> **核心理念**：人定意图、AI 写、代码算、工具校验、记忆纠偏
> **来源**：油位传感器报告 v0.86→v2.3 的实战迭代（8版打回→4版收敛）提炼
> **日期**：2026-08-07

---

## 一、为什么传统管线低效

传统管线（如 2hao 的 SAC/section_writer/IronGate）的核心问题是**意图在传递中丢失**：

```
用户心智 → 写作计划 → SAC维度 → LLM生成 → Gate校验
   │          │          │        │         │
   └─意图 100%  └─压缩 70%  └─猜 50%  └─写 40%  └─只查结构不查意图
```

每层都在压缩意图，最终 LLM 拿到的是"维度清单"而非"你要什么"。这就是为什么 v0.86-v1.0 改了 8 版仍被圆桌打回——**Gate 检查的是"结构对不对"，不是"符不符合你想的"**。

直接写作高效的原因：**反馈回路最短**。你说一句，AI 直接改，意图零损耗。这是人类与 AI 协作最自然的形态。

## 二、产品形态：人机协作写作工作台

### 2.1 四层架构

```
┌─ 第一层：写作层（AI 直接写）───────────────┐
│   意图直达：用户口述 → AI 直接产出          │
│   效率来源，也是与传统管线的本质区别          │
├─ 第二层：数据锚定层（防"编造"）─────────────┤
│   数据分级：verified / corrected / unverified│
│   数字外置：财务模型用代码算，AI 只引用       │
│   事实库：行业数据可检索，AI 不能凭空写       │
├─ 第三层：校验工具链（防"错而不自知"）────────┤
│   校验脚本：算术复算/实体锚定/数字一致性      │
│   渲染校验：表格非空/图片嵌入/字体显式        │
├─ 第四层：迭代记忆层（成长）──────────────────┤
│   每次用户纠偏沉淀为规则                      │
│   "华虹与命题无关"→记忆；"终值要算"→规则     │
└───────────────────────────────────────────┘
```

### 2.2 与多 Agent 产品的区别

**本工作台不是多 Agent 产品**。多 Agent 的核心假设是"让多个 AI 互相评审提升质量"，但这轮证明：**最高质量的评审信号来自用户本人**——用户一眼看出"华虹无关""数字空""终值差10倍"，任何 agent 都做不到，因为评审依据是用户的意图。

多 Agent 的三个问题：①意图在 agent 间传递再次损耗（重蹈管线覆辙）；②复杂度指数上升；③"AI 评 AI"容易同源偏差。

## 三、幻觉防线（四层）

幻觉无法"消除"，但可以被"隔离"。核心认知：**AI 幻觉的根源是让它干了它不该干的活**。

长文中 AI 最易幻觉的三类：**数字算术、事实记忆、跨章节一致性**——全部可用确定性手段（代码）兜底。AI 真正擅长的是**组织语言、判断逻辑、权衡取舍**——这三类幻觉概率低、人类一眼能识别。

### 3.1 算术外置（最关键）

LLM 心算是幻觉第一来源（v2.1 终值差10倍就是它"算"的）。**所有财务数字由代码算好喂给 AI，AI 只负责引用。**

```
示例：NPV/IRR/盈亏平衡 全部用 Python 脚本算 → 喂给 AI → AI 只写"经营期NPV+3,116万"
```

### 3.2 数据锚定（RAG/知识库）

AI 编 TDK、编 2019 防渗改造，是因为在用训练记忆。**外部事实库 + 强制检索**。数据分级：

| 级别 | 含义 | 使用规则 |
|---|---|---|
| verified | 与外部事实一致 | AI 可直接引用 |
| corrected | 已修正的幻觉 | 报告必须用修正值（如爱知制钢/VAC 而非 TDK） |
| unverified | 内部测算 | 必须标 (E) 或"待尽调"，不得冒充权威 |

### 3.3 程序化校验器（事后）

生成后跑确定性校验脚本（非规则 Gate）：

```
1. 算术复算：财务公式用代码重算，与报告数字比对
2. 实体锚定：must_contain（必须出现）vs forbidden_swap（禁止出现）
3. 数字一致性：同一指标全文口径统一（风险上限/份额/增速）
4. 渲染校验：表格非空、图片嵌入、字体显式
```

### 3.4 人类在环（最有效）

用户反馈是最高质量的校验信号。**每次纠偏沉淀进"事实库"**，下次不再犯。

## 四、工作流规范

### 4.1 六步工作流

```
① 意图对齐：用户口述目标+受众+必答问题（2-3分钟）
② 数据准备：从数据层提取（akshare/enrich/决策引擎），分级标注
③ AI 直接写：上下文工程（完整背景+数据+约束+示例），一次产出
④ 程序校验：跑校验脚本（算术/实体/一致性/渲染）
⑤ 用户审核：专业冷峻笔触、去AI感、纠偏
⑥ 迭代沉淀：纠偏写入记忆规则，更新事实库
```

### 4.2 上下文工程要点（Anthropic 方法论）

不把意图写进代码/模板，而是写进**一次性上下文**：

```
完整背景（业务命题/读者是谁）+
数据（分级标注的事实库）+
约束（口径/禁项/must_contain）+
示例（顶级报告写法片段）
```

让 AI 自主组织，而非用规则约束。

## 五、与 2hao 的关系：混合模式

```
2hao 数据层（可靠）→ Claude 直接写（意图）→ 用户审核（判断）→ 迭代
```

**保留**：2hao 的数据采集、确定性计算、事实库（akshare/enrich/决策引擎）
**替换**：写作调度层（SAC/section_writer/IronGate）→ "Claude 直接写 + 用户审核"

既拿到数据严谨性，又拿到意图理解力。

## 九、一句话总结

**人机协作写作工作台 = 人定意图 + AI 写 + 代码算 + 工具校验 + 记忆纠偏。**

核心哲学：**把 AI 的自由度限制在它擅长的事（组织语言、推演逻辑）上，把算术、事实、一致性交给代码和工具，把最终判断交给人。** 这既解决了传统管线的意图丢失（效率），又解决了裸写作的幻觉失控（可信）。
