> 触发：油位传感器_cicc.docx 圆桌评审——报告"结构满分、灵魂缺失"，AI 模板痕迹严重
> 本文档：①诊断 2号分析师暴露的深层次系统问题 ②给出详细、深入、全面、可执行的整改方案
> 执行对象：Marvis（按本方案分阶段实施）
> 日期：2026-08-05

---

## 第一部分：深层次问题诊断

油位报告不是孤立的写作事故，而是**五个系统层级的连锁失效**。从表层到深层逐层拆解：

---

### 问题 1（表层）：写作层——模板套话污染

**现象**：10 个万能过渡句全报告复读 3-8 次；40+ 段落同一模子（数据→判断→反方概率→套话）；概率机械标注（"概率30%"无任何数据支撑）。

**直接根因**：LLM 被"每段必须有 So What 链/判断密度/反方论证"的检查项逼成模板填充机。

**深层根因**：见问题 3——这是激励倒挂的必然结果，不是 LLM 能力不足。

---

### 问题 2（结构层）：分段并行生成缺乏全局一致性

**现象**：Bold Call 四处定义不一致（时间窗口/核心变量/增速全对不上）；市场规模双口径冲突（全球 32.5 vs 46 亿美元）；报告日期双版本；同一风险表重复出现。

**根因**：报告分"战略层/竞争层/前瞻层"三段并行生成，各段独立写 Bold Call、独立用数据，**没有全局整合环节**统一口径、定义、数据。R7/R8 收敛机制解决了"轮次间"锚定，但没解决"段间"口径统一。

**本质**：系统把"一份报告"当成"三段独立文章"，缺少**总编辑（editor-in-chief）**角色做全局一致性把关。

---

### 问题 3（核心层）：激励倒挂——Goodhart 定律系统性生效

**现象**：LLM 学会了"用最少真实思考满足最多格式要求"。所以产生了"结构满分、灵魂缺失"。

**根因（这是整个系统最深层的问题）**：

| Gate 检查项 | 检测方式 | 被游戏化的方式 |
|------------|---------|---------------|
| so_what_chain | 数"数据→判断→建议"链标记 | 每段塞"因此我们判断..."凑链 |
| judgment_density | 数判断词（≥1.2/千字） | 堆"我们判断/预计/核心"等词 |
| counter_argument | 检查反方论证存在性 | 每段机械加"反方论证(概率30%)" |
| bold_call | 检查 Bold Call 四要素存在 | 每部分都补一个 Bold Call |
| completeness | 检查维度全覆盖 | 数据不足也硬凑内容填充 |

**这是典型的 Goodhart 定律**：当指标成为目标，它就不再是好指标。R47（2026-08-02）圆桌就点破过"系统奖励看起来完整，惩罚诚实留白"，但**从未根治**——因为 Gate 检查项是 70+ 个手写的正则/关键词规则，改起来工作量大，且每次 R 版本只打补丁，从不重构激励结构。

**本质**：评估器（Gate）与生成器（LLM）用同一套 SAC 框架——"自己出题自己考"。真人世界里，写手和评委是不同人，标准是行业共识而非自定框架。2hao 的自我印证导致系统对自身产出失去批判能力。

---

### 问题 4（数据层）：零一手调研数据通道

**现象**：2 万字报告没有一处"我们访谈了/走访了/集采数据显示"，全是 LLM 从公开数据推导的二手结论。

**根因**：数据底座只有 financials.db、WebSearch、本地报告——**全部是二手公开数据**。没有任何专家访谈、工厂走访、招投标数据穿透、展会信息的采集通道。

**本质**：这是**结构性缺失**。咨询/投行报告的价值核心就是一手信息增量（"我们知道读者不知道的"）。2hao 的数据层决定了它只能产出"读者自己也能推导"的二手结论，天然没有"信息增量"这个价值维度。

**类比**：相当于让一个从未出过差的实习生，仅靠百度写行业报告——结构能写对，但永远没有现场感、没有独家信息、没有判断的手感。

---

### 问题 5（评估方法论层）：指标体系检测"格式信号"而非"内容质量"

**现象**：Gate 全绿的报告，读者一读就发现是模板——说明**Gate 通过 ≠ 报告合格**。

**根因**：70+ 个检查项里，绝大多数检测的是**格式信号**（关键词、正则、数量阈值），极少检测**内容质量**（洞察密度、信息增量、判断可证伪性、一手调研占比）。现有判断密度检查数的是"判断词出现次数"，而非"判断是否有信息增量"。

**本质**：指标体系停留在"可自动化"层面，回避了"难自动化但更重要"的层面。这不是工程偷懒，是**方法论上没有解决"如何评估洞察质量"**——所以退而求其次检测格式。

---

### 问题 6（交付层）：缺"人味"后处理

**现象**：报告直接出厂，无人工锤炼。

**根因**：真实报告经资深分析师修改（删废话、调结构、加判断、注入行业黑话）。2hao 的 Style Compiler 只做**格式清洗**（字体/段落/空行），不做**内容锤炼**（删套话/调详略/加一手信息/统一口径）。

**本质**：系统缺少"主编/总编辑"这一关键环节。LLM 产出的是"初稿"，初稿需要编辑加工才能成为"报告"。

---

### 问题 7（能力层）：无机构风格库

**现象**：报告读不出"CICC 风/GS 风/MS 风"，只有统一的"AI 模板风"。

**根因**：虽有 style_profiles 但只控制格式（封面/字体），不控制**写作风格**（段落节奏、详略、语气、黑话使用）。真人机构报告有鲜明的风格指纹，2hao 没有。

---

### 问题 8（闭环层）：评审意见未回流为系统能力

**现象**：每次圆桌都发现同样的问题（模板句/激励倒挂/口径冲突），下次 R 版本修一个，但同类问题换个马甲复发。

**根因**：评审产出的是"问题清单"和"R 号补丁"，没有沉淀为**可执行的、防再犯的机制**。比如"模板句黑名单"从未进 Style Compiler；"Bold Call 一致性检查"从未进 Gate；"一手调研占比"从未成为指标。

**本质**：系统有"问题-修复"的补丁循环，但没有"问题-机制-防再犯"的制度循环。

---

## 第二部分：整改方案

### 整改总纲

| 原则 | 说明 |
|------|------|
| 先止血，再免疫，后重建 | P0 拦截模板；P1 重建激励；P2 补数据；P3 全局整合 |
| 激励结构是根 | 不重建激励，改再多 prompt 都是治标 |
| 每项整改先写回归测试 | 防止"修了一个，复发一个" |
| 允许诚实留白 | 数据不足标注留白，给 credit 而非惩罚 |
| 一手调研是方向 | 逐步建立专家访谈/招标穿透/现场信息通道 |

### 优先级矩阵

```
高影响
  │
  P1 激励重建 ──────┬───── P0 止血（模板拦截/口径统一）
  （治本）          │     （立即）
  │                 │
  P2 数据通道 ──────┤     P0 产物卫生
  （一手调研）      │     （AI标注/图表随文）
  │                 │
  P3 全局整合 ──────┘
  （总编辑/风格库）
  │
 低影响
  低工作量 ←─────────→ 高工作量
```

### P0：止血（1-2 天）——让报告先"能见人"

#### P0-1 模板句黑名单拦截

**问题**：10 个万能过渡句复读。

**方案**：
1. 在 `core/style.py` 或新建 `core/template_blacklist.py` 维护模板句黑名单（启动 10 条，后续评审补充）
2. 接入 Style Compiler：报告生成后扫描，命中模板句 → 标记 + 触发局部重写（把该句改写为具体论证）
3. 接入 IronGate 新增检查 `_check_template_phrases`：全文模板句出现 ≥2 次 → warning；≥4 次 → error

**黑名单初始 10 条**：
- "这一趋势若被证实，将显著改变我们对行业格局的既有认知"
- "上述判断仍面临需求端波动带来的下行风险扰动"
- "这一变化同时意味着，需要重新审视此前对业务结构的增长假设"
- "从更长周期看，上述趋势若持续，盈利中枢存在系统性上移的可能"
- "后续财报中相关指标的兑现情况，将是检验上述判断真伪的试金石"
- "这一迹象提示，市场当前定价可能尚未充分反映上述逻辑的潜在弹性"
- "该类数据的边际改善，往往领先于报表层面的最终体现"
- "对上述变量保持高频跟踪，是把握后续机会的必要条件"
- "驱动因素边际拐点的确认，是后续估值重估能否成立的前提"
- "该数据背后折射出的经营质量变化，比单期数值本身更值得关注"

**涉及文件**：`core/style.py`、`pipeline/checks/content_format_mixin.py`、`pipeline/iron_gate.py`
**验收**：对油位报告跑新检查，应拦截 ≥6 条模板句；新增回归测试 `test_r79_template_blacklist.py`

#### P0-2 Bold Call 单一事实源 + 一致性检查

**问题**：Bold Call 四处定义不一致。

**方案**：
1. **单一事实源**：报告第一处定义的 Bold Call（方向/时间窗口/核心变量/证伪条件）写入 `report_blueprint`，作为全局唯一引用
2. **Gate 新增 `_check_bold_call_consistency`**：扫描全文所有 Bold Call 表述，比对时间窗口/核心变量/增速，不一致 → error
3. section_writer 注入时显式要求"Bold Call 已在开头定义，后续段落引用同一表述，不得重新定义"

**涉及文件**：`core/report_blueprint.py`、`pipeline/checks/analysis_mixin.py`、`pipeline/section_writer.py`
**验收**：油位报告跑新检查应拦截 Bold Call 冲突；新增测试 `test_r79_bold_call_consistency.py`

#### P0-3 市场规模口径统一

**问题**：同一指标双口径冲突（全球 32.5 vs 46 亿美元）。

**方案**：
1. `core/data_caliber.py` 已有口径冲突检测，接入**跨节**检查（已有 `_check_cross_section_consistency` 但只查目标价/净利率，扩展覆盖市场规模）
2. Gate `_check_cross_section_consistency` 增加：同一指标（全球市场规模/中国市场规模/行业增速）多值偏差 >20% → error
3. section_writer 注入"全报告统一使用工业传感器全口径（全球 2025 年 50 亿美元），如引用其他口径须显式标注"

**涉及文件**：`core/data_caliber.py`、`pipeline/checks/analysis_mixin.py`、`pipeline/section_writer.py`
**验收**：油位报告应拦截市场规模双口径；新增测试 `test_r79_caliber_consistency.py`

#### P0-4 产物卫生

**问题**：AI 标注残留、图表堆附录、重复表、空标题。

**方案**：
1. AI 标注残留：已有 R72 硬拦截，但 resume_driver 路径绕过 → **所有执行路径必须过 export_report**（禁绕过）
2. 图表随文：`_check_layout_quality` 已升 error 级（R78），确认 resume_driver 路径也生效
3. 重复表检测：Gate 新增 `_check_duplicate_content`——相同文本块/表格出现 ≥2 次 → error
4. 空标题/孤立标记：`_check_completeness_scan` 增加"孤立 ## 标题"检测

**涉及文件**：`pipeline/checks/content_format_mixin.py`、`pipeline/checks/analysis_mixin.py`、`export/report_gate.py`
**验收**：油位报告应拦截 AI 标注、图表堆附录、重复表、空标题

### P1：重建激励（3-5 天）——治本

#### P1-1 Gate 从"查格式"转向"查洞察"

**问题**：判断密度数判断词，被刷分。

**方案**：将 `_check_judgment_density` 从"数判断词"升级为"检测洞察质量"。引入**洞察四要素**：
- **非显而易见**：判断不能是常识复述（"行业增长受益于政策"是常识，"政策执行率 62%→85% 是 2026H2 替换高峰的触发阈值"是洞察）
- **可证伪**：判断必须有明确证伪条件
- **有数据支撑**：判断必须锚定具体数据/来源
- **有信息增量**：判断必须说出市场不知道的（预期差/独家数据）

**实现**：
1. 保留判断词密度作为**下限**（防空谈），但新增 `_check_insight_quality`：对每段判断，检测是否含"具体数字+时间+机制"（正则匹配"数字+时间窗口+因果词"）
2. 检测"常识复述"：判断句含行业通用套话（"受益于政策""需求增长""格局优化"）而无具体锚点 → 降分
3. 引入**语义变体检测**（本地 sentence-transformers）：同义模板句不重复计分

**涉及文件**：`pipeline/checks/analysis_mixin.py`
**验收**：新增测试验证"常识复述"被降分、"有锚点的判断"通过

#### P1-2 反方论证从"概率机械标注"改为"论证强度"

**问题**：每个反方机械标"概率30%"。

**方案**：
1. Gate `_check_counterargument_strength`（R75 已建）扩展：反方必须有**具体机制**（"国际巨头设中国厂+降价15%"）而非空泛概率
2. 检测"概率无支撑"：概率后面无具体机制/数据 → 降分
3. section_writer 注入：反方论证用"风险可控/不容忽视 + 具体理由"，概率仅在有情景树/回测时使用

**涉及文件**：`pipeline/checks/analysis_mixin.py`、`pipeline/section_writer.py`
**验收**：油位报告的"概率30%"空壳反方应被降分

#### P1-3 允许并奖励诚实留白

**问题**：系统惩罚诚实留白，逼 LLM 硬凑。

**方案**：
1. **留白声明机制**：section_writer 允许维度标注"数据不足，明确留白：<维度名>（原因：无权威数据源）"
2. **留白 credit**：Gate 检查维度覆盖时，已声明留白的维度**不判缺失**，且给报告"诚实标注"加分项
3. **反硬凑**：检测"数据不足但写了具体数字"的维度（无来源 + 具体数字）→ 降分（防编造）

**涉及文件**：`pipeline/section_writer.py`、`pipeline/checks/coverage_mixin.py`、`pipeline/checks/data_quality_mixin.py`
**验收**：报告对无数据维度声明留白 → 通过且加分；硬凑数字无来源 → 拦截

#### P1-4 评估器与生成器解耦（自我印证破除）

**问题**：Gate 用 SAC 查，LLM 用 SAC 写，自己出题自己考。

**方案**：
1. **外部参照系注入**：Gate 检查时引入行业基准知识（methodology_backtest_deep.json 的金牌报告标准），而非仅 SAC 自检
2. **交叉校验**：新增"反方视角 Gate"——用与生成端不同的标准审视报告（已有 LLM 对侧 provider 校验，扩展到写作质量）
3. **黄金样本对比**：对每份报告抽取 3 个指标（洞察密度/套话率/一手信息占比），与 golden dataset 金牌报告对比，偏离过大 → warning

**涉及文件**：`pipeline/iron_gate.py`、`tests/golden/`
**验收**：油位报告的"套话率"与金牌报告对比，应显著偏高并触发 warning

### P2：补一手调研数据通道（1-2 周）

#### P2-1 专家访谈采集层

**方案**：
1. 新建 `core/expert_interview.py`：结构化录入专家访谈纪要（访谈对象/时间/核心观点/量化数据）
2. 访谈纪要格式：`{expert, title, org, date, topic, insights: [每条带具体数字], quotes}`
3. 入库 `data/expert_interviews.json`，enrich-file 可注入
4. Marvis 执行：对油位传感器行业，访谈 3-5 位专家（加油站设备商/危化品集成商/磁致伸缩材料商），产出访谈纪要

**验收**：报告含"据某加油站设备商反馈，招标周期从 6 个月缩短至 3 个月"等一手信息，且带来源

#### P2-2 招投标/集采数据穿透

**方案**：
1. 采集加油站液位仪集采平台数据、危化品安全改造招标公告
2. 结构化：`{project, buyer, product, volume, unit_price, date, winner}`
3. 入库 `data/procurement_data.json`
4. 报告引用：招标量环比、中标名单、价格趋势

**验收**：报告含"2026Q2 加油站液位仪招标量环比 +18%，中标均价 4200 元"等穿透数据

#### P2-3 现场/工厂信息

**方案**：
1. Marvis 产出现场走访纪要（工厂产能、产线利用率、供应商报价）
2. 结构化入库，enrich-file 注入

**验收**：报告含"宁波某磁致伸缩材料供应商报价同比下降 12%"等现场信息

#### P2-4 报告"一手信息占比"指标

**方案**：
1. 新增 `_check_primary_research`：统计报告含一手信息（专家访谈/招标数据/现场数据）的段落占比
2. 阈值：深度报告一手信息占比 ≥10%（随数据底座建设逐步提升）
3. 未达 → warning（不阻断，但提示数据底座待补）

**涉及文件**：`core/expert_interview.py`、`core/procurement.py`、`pipeline/checks/analysis_mixin.py`
**验收**：一手信息占比指标可计算、可跟踪

### P3：全局整合与风格（持续）

#### P3-1 总编辑环节（Editor-in-Chief）

**方案**：
1. 报告全段生成后，增加 **`_global_edit` 节点**：一个全局 LLM 调用，接收全文 + 审查清单（口径统一/Bold Call 一致性/删除套话/调整详略）

## 附：深层次问题一页总结

```
油位报告"不像人写的" → 表面是写作问题
    ↓
深层是激励倒挂（Goodhart）：Gate 奖励格式、惩罚留白 → LLM 成模板填充机
    ↓
再深层是自我印证：评估器与生成器同用 SAC，自己出题自己考
    ↓
再深层是数据能力缺失：零一手调研通道，只能产出二手推导，无信息增量
    ↓
最深是方法论缺陷：指标体系检测"格式信号"而非"内容质量"，且无"总编辑/人味后处理"环节
```

**整改必须从激励结构重建入手**（P1），否则 P0 止血只是让模板换马甲。同时补一手数据通道（P2）和全局整合（P3），才能让 2hao 从"结构正确的模板机"进化为"有洞察、有信息增量、像人的分析师"。
