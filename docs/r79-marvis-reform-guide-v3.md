# 2号分析师深层次问题诊断与整改建议（R79第二轮）

> 触发：油位传感器重做报告圆桌评审——模板已根除，但反方空壳/硬凑数据/PDF无图/排版空白暴露更深问题
> 本文档：①诊断第二轮暴露的深层次系统问题 ②给 Marvis 的具体、可执行的 Word 文档整改建议
> 日期：2026-08-06

---

## 第一部分：深层次问题诊断

### 问题 1：拦截器效应——Gate 能拦，生成端不改

**现象**：反方空壳 DES=0%、硬凑数据 51 处。R79 的 Gate 检查能拦截（DES 阈值 30% 会打回），但 LLM 照旧写空壳反方，靠"写出来→被打回→再修"迭代。

**根因**：R79 只改了**评估层**（Gate 检查），没改**生成层**（section_writer 的 prompt）。LLM 的写作指令还是"写反方论证（概率XX%）"，它不知道新规则。**检查项没有传导到 prompt 约束，等于交警设了路障但没告诉司机。**

**证据**：Marvis 执行报告说"反方论证强度 0%→加 3 段有条件有杀伤力的反方段落"——这是靠**手工补**，不是生成端自动产。下次跑管线又会写空壳。

### 问题 2：数据标注的表演性——"补(E)"是给幻觉披外衣

**现象**：51 处具体数字无来源。Marvis 建议"批量补 (E)/(A) 标注可升至 0.5+"。

**根因**：把"诚实标注"做成了"表演严谨"。一个数字没有来源（不知道哪来的），贴个 (E) 标签就"合规"了——但 (E) 是估算，估算也要有**估算依据**（"基于 A 数据 × B 假设"），不是凭空写个数字标个 E。**数据溯源机制只查"有没有标签"，不查"标签背后有没有依据"。**

**本质**：这是 R79 P1-3 诚实留白的反面——系统本应"无来源就留白"，但被玩成了"无来源就贴个 E"。

### 问题 3：交付链路脆弱——多套导出并行、无端到端验证

**现象**：PDF 25KB 无图（LibreOffice 没装，走 reportlab fallback）；docx 空段率 16% + 连续 55 空段。

**根因**：
1. 导出不是唯一出口：LibreOffice / reportlab / pandoc / Word COM 多套并行，环境缺依赖就静默降级（reportlab 无图也"成功"）
2. **没有端到端验证**：导出后不验证"PDF 是否含图""docx 是否无空段"，四件套质量靠运气

**本质**：R78 就修过"手动导出绕过出口门禁"，但环境缺依赖导致的降级路径没有被门禁拦截——降级成无图 PDF 照样"导出成功"。

### 问题 4：激励的负效应——洞察检查反而压低判断密度

**现象**：有锚点判断 24%（上版 35%），不升反降。

**根因**：R79 的 `_check_insight_quality` 对"常识复述判断"降分。LLM 的应对是**少写判断句**（写多了可能被降分），而不是写更好的判断。这是 Goodhart 的新变体：**惩罚劣质判断 → 减少判断产出**。

**本质**：激励结构只做了"惩罚坏的"，没做"奖励好的"。系统需要"留白 credit"和"优质洞察 bonus"并重，让 LLM 知道"写一个有锚点有可证伪条件的判断"比"不写"得分更高。

### 问题 5：迭代修复是打地鼠——缺"一次写对"的总编辑

**现象**：Marvis 靠"Gate 打回→手工补→再跑"迭代，每轮修几个，新的又冒出来。

**根因**：没有"总编辑"环节。真实报告由资深分析师**一次整合**：统一口径、删套话、补反方、查数据、控排版。2hao 是"LLM 分段写 → Gate 逐项查 → 打回重写"，永远在修，永远有漏。

**本质**：`_global_edit` 节点（R79 P3-1）未落地，缺最后一道"人味"整合。

## 第二部分：给 Marvis 的具体整改建议（Word 文档级）

### 整改总原则

1. **改生成端，不只改 Gate**——每个检查项对应一个 prompt 约束
2. **数据无来源就留白，不贴标签**——(E) 也要有依据
3. **导出唯一出口 + 端到端验证**——降级路径要显式阻断
4. **激励奖励优质，不只惩罚劣质**——优质洞察加分，留白加分
5. **总编辑整合**——最后一道统一口径、删套话、查数据

---

### 整改项 1：反方论证生成端约束（对应问题 1）

**现状**：`pipeline/section_writer.py` 的 prompt 让 LLM 写"反方论证（概率XX%）"→ 产出空壳。

**改法**：修改 `section_writer.py` 中反方论证的注入 prompt，强制三段式结构：

```
反方论证（必须三段式）：
① 具体情境：什么条件触发反方？（如"若国际巨头 VEGA 在中国设厂并降价 15%"）
② 传导机制：这个情境如何传导到本判断？（如"→ 国产替代成本优势被压缩 → 份额目标从 42% 降至 35%"）
③ 杀伤力评估：若成立，主判断/目标价下调多少？（如"→ 目标价下调 X%，评级从增持降为中性"）
禁止：只写"存在 XX 风险（概率 X%）"而无机制与杀伤力。
```

**涉及**：`pipeline/section_writer.py` 反方论证 prompt 段
**验收**：重跑后 `_check_counterargument_strength` DES ≥30%

---

### 整改项 2：数据溯源强制"无依据不写"（对应问题 2）

**现状**：51 处数字无来源；Marvis 打算补 (E) 标签。

**改法**：
1. **改 prompt**：section_writer 数据注入段加"每个具体数字必须紧跟来源标注（A/B/E/F + 依据）。无法给出依据的数字，不得写入，改为'数据不足，明确留白'。"
2. **改 Gate**：`_check_honest_gap` 从"数无来源数字"升级为"数字 + (E) 标签但无依据说明 → 仍算硬凑"。检测 `(E)` 前面是否有"基于/估算/假设"等依据词。
3. **删改优先**：对现有 51 处，**删除无依据数字**，不是补标签。保留的 (E) 必须带依据短语（如"约 50 亿美元(E，基于工业传感器 600 亿 × 物位占比 8%)"）。

**涉及**：`pipeline/section_writer.py` 数据注入 prompt、`pipeline/checks/coverage_mixin.py::_check_honest_gap`
**验收**：重跑后 `_check_honest_gap` 无硬凑数字；所有 (E) 均带依据

---

### 整改项 3：导出唯一出口 + 端到端验证（对应问题 3）

**现状**：LibreOffice 未装 → reportlab fallback 无图 PDF；docx 空段率 16%。

**改法**：
1. **导出前环境检查**：`export/report_gate.py::export_report` 开头检测关键依赖（LibreOffice/pandoc），缺失时**显式报错**而非静默降级：
   ```
   if not _has_libreoffice() and pdf_path:
       raise GateBlockedError("PDF导出", 0, ["LibreOffice 未安装，无法导出含图 PDF"])
   ```
2. **导出后验证**：PDF 导出后检查文件大小（<100KB 且无图 → 视为降级，报错）；docx 导出后跑空段检查（空段率 >5% → 报错）。
3. **排版清洗**：复用 R40 的 `clean_empty_paragraphs`，在 docx 导出前强制清洗。

**涉及**：`export/report_gate.py`、`export/exporter.py`
**验收**：四件套全部含图、docx 空段率 <5%、无静默降级

---

### 整改项 4：激励奖励优质洞察（对应问题 4）

**现状**：`_check_insight_quality` 只惩罚常识复述，导致 LLM 少写判断。

**改法**：
1. **优质洞察 bonus**：`_check_insight_quality` 增加加分档——判断同时含"数字+时间+机制+可证伪条件"（四要素齐全）→ score 1.0 + 标记"优质洞察"；只含数字+时间（无机制）→ 0.7；常识复述 → 0.3。
2. **留白 credit 保留**：数据不足维度声明留白 → 该维度不计入缺失且报告加分。
3. **prompt 明示收益**：section_writer 注入"每写一个有锚点、可证伪的判断，报告评分提升；写空泛判断或硬凑，评分下降；数据不足诚实留白，评分不降反升。"

**涉及**：`pipeline/checks/content_format_mixin.py::_check_insight_quality`、`pipeline/section_writer.py`
**验收**：有锚点判断占比回升至 ≥35%，且新增"四要素齐全"的优质判断

---

### 整改项 5：总编辑节点（对应问题 5）

**现状**：无 `_global_edit`，靠 Gate 打回迭代。

**改法**：落地 R79 P3-1：
1. 在 `pipeline/e2e_orchestrator.py` 新增 `_global_edit` 节点，全段生成后执行一次全局 LLM 整合，审查清单：
   - 统一所有市场规模/增速口径
   - Bold Call 单一表述
   - 删除模板套话（调用 `core/template_blacklist.py::rewrite_suggestions`）
   - 反方段落补"条件+杀伤力"三段式
   - 无依据数字删除或改留白
   - 调整详略（核心判断详写、次要略写）
2. 全局编辑后重跑 IronGate 全量。

**涉及**：`pipeline/e2e_orchestrator.py`、`pipeline/agent_graph.py`
**验收**：一次管线跑出接近终稿（Gate 失败项显著减少）

---

### 整改项 6：PDF 交付物达标（对应问题 3 具体）

**现状**：PDF 25KB 无图。

**改法**：
1. 安装 LibreOffice（Windows：`winget install TheDocumentFoundation.LibreOffice` 或手动安装）
2. 配置 `export/exporter.py` 优先走 LibreOffice 转 PDF（含图），reportlab 仅作无图应急且必须报 warning
3. 验证：PDF >100KB 且含图片引用

**涉及**：`export/exporter.py`、环境安装
**验收**：PDF 含图、大小正常

## 第三部分：整改顺序与验收

### Marvis 执行顺序

```
整改1 反方prompt → 整改2 数据溯源 → 整改3 导出验证 → 整改4 洞察激励
→ 整改5 总编辑 → 整改6 PDF → 整改7 回归测试
```

### 每项 Checklist
1. 读现状代码 → 2. 先写回归测试 → 3. 改代码 → 4. 跑测试 → 5. 用重做报告验收 → 6. 更新 roundtable-backlog

### 验收样例（重做报告复测）

| 检查 | 整改前 | 整改后目标 |
|------|--------|-----------|
| 反方强度 DES | 0% | ≥30% |
| 无来源数字 | 51 处 | 0 处（或全部带依据/留白） |
| PDF 含图 | 25KB 无图 | 含图 >100KB |
| docx 空段率 | 16%+55连续 | <5% |
| 洞察占比 | 24% | ≥35% |
| 模板句 | 0 | 保持 0 |

## 第四部分：一句话总结

**第一轮整改证明 Gate 拦截有效；第二轮整改必须证明生成端约束有效。** 5 项整改里，3 项是改 prompt（反方/数据/洞察激励）、2 项是改交付（导出验证/总编辑）、1 项是环境（LibreOffice）。核心心法：**让 LLM 一开始就别那么写，而不是写了再被打回。**
