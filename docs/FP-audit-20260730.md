## P0 级违规（8 项 — 违反宪法否决条件）

### P0-1 [FP2a] 数据编造无 writer 层防御

**违反**：FP2a 否决条件 "任何导致系统在无数据时产生‘看起来合理但无来源’的输出的逻辑"

**根因**：section_writer 的 prompt 要求"每段必须有数据支撑"（最小数据源规则），但**没有告诉 LLM "如果该数据点不可用，如实报告不可用"**。当 data_collector 返回空数据时，LLM 的"满足所有约束"驱动力会使其从训练数据编造数字。

**位置**：pipeline/section_writer.py:313-388（_build_prompt_v4 的 17 条全局硬性要求中无"允许承认数据缺口"条款）

**修复方向**：prompt 新增第 18 条："禁止编造。如果某个数据点不可用，明确标注‘此数据暂缺’或‘截至当前未获取到公开数据’。编造是对 FP2a 的违反。

---

### P0-2 [FP2a] 交叉验证完全断裂不可用

**违反**：FP2a "交叉验证是强制步骤"

**根因有三层**：
1. **调用时序错误**：cross_validate 节点读取 `context.get("final_text", "")`——此时 data 节点刚执行完，final_text 是空字符串。validate("") 传入空字符串给 data_points 参数，立即返回 passed=True。
2. **接口不匹配**：CrossValidator.validate() 期待 DataPoint 对象列表，e2e 传入了字符串
3. **结果不传递**：cross_validate 的输出不被 section_writer 使用

**位置**：pipeline/e2e_orchestrator.py:249-263（cross_validate 节点逻辑）; line 545（deps=["data"] 但读的是 report_text）

**修复方向**：
- 修正 cross_validate 的 deps：改为 deps=["data", "data_feeds"]，读取结构化数据而非 final_text
- 将 cross_validation 结果注入 ctx["data"]["cross_validation"] 供 writer 使用

---

### P0-3 [FP4] AI Tone LLM 判别完全缺失

**违反**：FP4 下阈 "由 StyleCompiler + AIScanner + AI Tone LLM 判别共同保证"——第三个组件不存在

**根因**：iron_gate.py 中无任何 LLM-level 的 AI 内容判别。现有 `_check_aigc_fingerprint`(9 个短语模式) 和 `_check_human_sense`(18 个关键词计数) 都是关键词级。任何避开"值得注意的是"类短语的 AI 文本都能绕过。

**位置**：缺失。需新增到 pipeline/iron_gate.py

**修复方向**：用阿里云 Qwen（已注册在 _registry 中）做 "这段文字像不像 AI 写的" 二判。取报告前 2000 字，system prompt 为"你是一个图灵测试裁判"，score < 0.4 阻断，0.4-0.7 警告记录。

---

### P0-4 [FP4] 上阈验证不存在

**违反**：FP4 "100% 的报告至少包含一个‘资深分析师无法独立完成’的分析"

**根因**：iron_gate 的 24 项检查中，无任何一项验证"输出是否包含人类分析师无法完成的深度"。_check_data_traceability 检查来源数量但无密度阈值，_check_bold_call 检查 5 要素但不验证推理深度。

**位置**：缺失。需在 iron_gate.py 新增 _check_human_impossible_dimension

**修复方向**：新增检查——验证报告是否在以下任一方面超越人类能力：数据点密度（>50 个不同来源）、推理深度（>5 层归因链）、覆盖广度（>20 家可比公司）。三者有其一即通过。

---

### P0-5 [FP5] 人工反馈回路完全断裂

**违反**：FP5 "每次人工反馈必须被吸收"

**根因**：core/edit_learn.py 拥有完整框架（EditClassifier → EditExecutor → EditDatabase），但管线和外部接口中无人调用它。engine 买好了没装进车里。

**位置**：core/edit_learn.py（孤悬模块）；pipeline/e2e_orchestrator.py（没有 import edit_learn）

**修复方向**：在 e2e_orchestrator 的 record_results 节点中接入 edit_learn.inject_preferences()，或在 scheduler 中提供 --feedback 接口。

---

### P0-6 [FP6] L1/L3-L6 推理透明无验证

**违反**：FP6 "每个 section 输出必须能被提取到 L1-L3（否则 IronGate 阻断）"

**根因**：当前仅 So What 链（L2 推理层）有间接检查。L1（结论显式存在）、L3（多变量归因权重）、L4-L6（证据/反证/元认知）完全无 Gate 验证。

**位置**：pipeline/iron_gate.py — 缺少 _check_explicit_conclusion、_check_attribution_depth、_check_counter_condition_probability

**修复方向**：新增三项检查。
- L1：检查报告开头是否有"建议买入/增持/中性/卖出"类结论句
- L3：检查是否有"主要驱动因素"类多变量归因段落
- L5：检查反方论证是否包含条件概率

---

### P0-7 [FP7] 优雅降级三级体系不存在

**违反**：FP7b "任何单组件失效不得导致管线输出为空"

**根因**：代码中无 L1/L2/L3 降级概念。data_collector 返回空直接抛异常，e2e_orchestrator 无基于失效程度的 fallback 路径，iron_gate 无动态 threshold 调整。

**位置**：缺失需新建。pipeline/e2e_orchestrator.py（fallback 路径）

**修复方向**：建立三级降级体系——
- L1：图表失败 → placeholder 替代，允许交付
- L2：数据源部分失效 → 头部标注"此报告基于 N 个来源"，降低 IronGate threshold 0.1
- L3：核心 LLM 不可用 → 不可交付，触发告警

---

### P0-8 [FP7] Gate 失败不触发自动学习

**违反**：FP7a "每次 IronGate 阻断必须自动注册为 FP5 学习案例"

**根因**：iron_gate 的 run_all 返回 GateReport 后就结束了。阻断信息的"学习"依赖 e2e_orchestrator 间接转发——LearningLoop 虽然有 after_report()，但调用链条是：IronGate → e2e → LearningLoop。IronGate 自身无任何"注册失败"的逻辑。

**位置**：pipeline/iron_gate.py:177-260（run_all 方法不写 learning_loop）

**修复方向**：IronGate.run_all() 在 overall_score < min_score 时直接调用 LearningLoop.after_report() ，或至少写入日志文件供 orchestrator 下次启动时批量处理。

## P1 级违规（9 项 — 重要，建议修复）

### P1-1 [FP2a] 数据来源标注 IronGate 语义不验证

prompt 要求"报告名称+发布日期"级别来源，IronGate 只做关键词计数。"数据来源：公开信息"就能通过。需升级到语义验证。

### P1-2 [FP2a] A/E/F/B 标注不完整

A/E 有 prompt 要求但 F/Forecast 和 B/Benchmark 无标注规则。IronGate 无对应验证。

### P1-3 [FP2b] So What 链平均分可绕过

当前按段落平均分 >= 0.6 通过。一篇报告 10 段中 5 段满分 5 段零分 = 0.5 分但通过了。需要求"每段不低于 0.3"的硬下界。

### P1-4 [FP2b] 反方论证无条件概率

IronGate 检查关键词（"然而/但是"）但不验证每个反方是否有成立条件概率。FP2b 要求"反方成立的条件概率"缺少 Gate 确认。

### P1-5 [FP2b] Bold Call 阈值过低

5 项要素中 3 项通过即可（60%）。允许缺"时限"和"置信度"——但 FP2b 要求"有时限的核心判断"。

### P1-6 [FP4] AIScanner 仅短语级

12 个 P0 指纹全部是短语级模式（"值得注意的是"、"综上所述"等）。语义级 AI 痕迹（均衡结构、模板化三列举、机械过渡）无检测。

### P1-7 [FP5] Gate 失败复发率无追踪

LearningLoop 的 report_scores 表有 timestamp 但从未做过 time-series 分析。无法回答"同类 Gate 失败的复发率是在下降还是上升"。

### P1-8 [FP6] 置信度标注无 Gate 验证

section_writer 的 prompt 要求 H/M/L 置信度标注，IronGate 无对应检查。LLM 可以不标，Gate 不干涉。

### P1-9 [FP7] LLM Provider 实际单点故障

deepseek_client.py 的 _registry 支持多 provider（含 circuit breaker/retry/信用分），但实际只启用了 DeepSeek 一个。如果 DeepSeek 挂了，系统全停。

## 核心建议（仅 3 条，每条对应一个 FP 簇）

### 建议一：Fix the Data Gap（FP2a）

这是当前系统最根本的 FP 违反。Data→Writer 的数据流在物理上断裂了：
1. cross_validate 读的是空字段 → 从不执行
2. section_writer 的 prompt 无"允许说不知道"条款 → 诱使编造
3. IronGate 的数据来源验证是关键词计数 → LLM 可以轻松绕过

修复只需要 < 50 行代码，但这是区分"AI 编造器"和"分析师系统"的分水岭。

### 建议二：Build the Tone Wall（FP4+FP6）

两条 FP 共享同一个架构缺口：**有输出规范（prompt），无输出验证（Gate）**。
- 下阈缺 LLM 判别层
- 上阈完全不存在
- FP6 的 L1/L3/L5 无 Gate 检查

建议集中建设 "Tone + Transparency Gate"——在 IronGate 中新增 3-4 个 check 方法覆盖 FP4 下阈（LLM 判别）+ FP4 上阈（超人类维度）+ FP6 L1/L3（结论+归因）。约 150 行代码。

### 建议三：Wire the Learning Loop（FP5+FP7）

两个孤悬系统需要接入：
1. **edit_learn.py** 有完整的编辑学习引擎，管线无人调用 → 加一行 import 就能激活
2. **IronGate 阻断 → LearningLoop** 的链路需要从间接（orchestrator 转发）改为直接（iron_gate 内调用）

这两条连线完成后，FP5（演化）和 FP7（反脆弱）的"从失败中学习"循环就连上了。
