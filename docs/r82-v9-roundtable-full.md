## 二、为什么会产生这些问题（根因）

### 2.1 写作层：评分驱动的结论倒置（最核心）
- Gate 只校验"结构完整"（有目标价/EPS/So What/反方），不校验"结论正确"
- LLM 为满足"核心判断含目标价"模板 → 硬造无标的的 EPS 0.52 元
- 为凑 So What 链 → 塞"机构配置意愿边际抬升"等注水句
- **本质：系统奖励"看起来正确"，惩罚诚实留白——LLM 学会了制造假象**

### 2.2 数据层：无跨章节一致性校验
- 渗透率/份额/增速/市场空间，各章节独立生成，无自动断言
- 来源标注"（数据来源：公司年报）"无具体实体 = 标注幻觉，比不标更危险

### 2.3 流程层：旁路门禁 + 扫描时机错误
- E2E 三轮 Gate 全失败（最高0.4）→ 旁路 TemplateEnforcer 手动导出，交付未过 Gate 的报告
- 去 AI 化扫描早于导出链路，未对最终 docx/pdf/pptx 复核
- checkpoint 残留未清 → 反复从旧 attempt 续跑 → 8 小时耗时

## 四、网上顶级打法

### 4.1 评估驱动 → 真值校验（根治激励倒挂）
- **黄金数据集回测**（Anthropic/OpenAI evals）：真实研报做外部真值，Gate 对比而非自评
- **Rubric 化评估**：好结论的标准定义，LLM-as-judge 按 rubric 打分，不数关键词

### 4.2 数字一致性 → 生成时断言
- **数据契约 + 跨表对账**（dbt/Great Expectations）：关键指标（渗透率/份额/增速）在生成时强制单一事实源
- **血缘追踪**：每个数字可追溯到来源字段，矛盾自动报错

### 4.3 来源标注 → 真名实姓
- **LSEG 数据溯源**：每个标注必须有具体来源实体（公司名/报告名/日期），"公司年报"视为无效
- **来源分级**：A官方/B第三方/C估算（必须带依据），无来源数字改留白

### 4.4 交付链路 → 唯一出口 + 终产物校验
- **CI/CD 理念**：export_report 唯一出口，Gate 失败禁旁路；产物验证（含图/无AI/完整）在导出后强制
- **金丝雀验证**：新改动先跑 1 份报告过全链，通过再全量

### 4.5 流程 → SOP + 测试先行
- **Gate 失败整改 SOP**：失败→定位→修复→重跑，禁手动导出
- **测试先行**：任何改动先跑 pytest（359 项），定位问题不靠手写脚本
