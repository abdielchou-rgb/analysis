## 一、结论先行

**不要再加第 106 项检查，也不要再写第 198 份 md。先做一件项目从未做过的事：
测量门禁本身的灵敏度和特异度。**

具体说：**建一个"金样本缺陷语料"，用变异测试（mutation testing）给 Gate 做体检。**

理由一句话：现在没有任何东西能否证"Gate 是有效的"。一个不可证伪的度量，
无论它输出 0.78 还是 0.95，都不构成质量证据。

这不是新工程——项目**已经同时拥有两个必需原料**，只是从未把它们接起来：

- **105 项检查** = 105 个已命名的失效模式（缺陷目录已存在）
- **`output/` 里 60 份真实报告 + `tests/golden/`** = 已知合格样本

接起来就是：**把每个已命名的失效模式，注入一份合格报告，看 Gate 认不认。**

## 二、外部顶级思考怎么说

### 2.1 LLM 评估工程：二元断言 > 连续打分，且必须验证裁判

Hamel Husain / Shreya Shankar 的评估工程方法论（业界当前事实标准之一）给出的几条
硬结论，逐条都命中本项目：

| 外部结论 | 对本项目的含义 |
|---|---|
| **"先用二元标签。数值标签是高级用法，通常不必要。"** 相邻档位（3 vs 4）的差异主观且标注者之间不一致；标注者会**躲进中间值**来逃避判断 | 本项目的 0–1 连续分 + 均值聚合，正是"可躲进中间值"的结构。它既不可复核，也不可证伪 |
| **必须用留出集测量裁判的 TPR / TNR**（每个失效模式 100–200 条标注；dev/test 各含 30–50 正例 + 30–50 负例） | 项目从未测量过任何一项检查的 TPR/TNR。`PASS_THRESHOLD=0.78` 是一个**未经标定的数字** |
| **"如果你通过了 100% 的评估，说明你很可能没有真正挑战系统。70% 通过率可能才是更有意义的评估。"** | 项目把 Gate 从 0.78 推到 0.95 当作成绩。按这条标准，**0.95 是危险信号，不是成就** |
| 错误分析（error analysis）应占开发时间 **60–80%**，且是"评估中最重要的活动" | 项目的投入分布恰好相反：算力/写手侧 15894 行 vs 验证侧 8893 行，且验证侧多为黑名单枚举 |

### 2.2 变形测试：没有标准答案时，用"关系"当裁判

LLM 输出的质量往往没有 ground truth。变形测试（metamorphic testing）的答案是
**不需要 ground truth——断言变换下的不变量**（LLMORPH、LGMT、MTF 等
2024–2026 年的工作都建立在这一点上：把"缺少 oracle"当作特性而非缺陷）。

对报告生成器的直接推论：

- **顺序不变性**：把章节重排，质量判定不应改变
- **释义不变性**：同义改写一段，判定不应改变
- **单调性**：补足一处缺失证据，判定不应变差

**如果 Gate 分数在章节重排后大幅摆动，那它就是噪声，不是度量。**
这是一个**几十行代码就能做的实验**，且能立刻证伪 Gate 的稳定性。

### 2.3 变异测试：验证检查器的标准手法

静态分析领域早已有成熟做法——**用测试代码变异体（mutants）检测分析器的假阴性**
（Park & Choi 等）。核心思想：要证明检查器有效，就注入已知缺陷，看它抓不抓得到。

这与"金/毒样本元测试"是同一个东西——**作者自己在
`docs/GATE_SCORE_095_TOP_THINKING_20260909.md` 里已经提出了这个方法**，
然后同一天提交了放宽检查器的改动。方法是对的，缺的是**机制**（见 §四 R5）。

### 2.4 奖励劫持 / Goodhart 分类：本项目是教科书案例

Goodhart 定律的现代分类（Manheim & Garrabrant）中，本项目属于 **causal Goodhart
（因果型）**：代理指标本身成了操作杆，团队直接去推指标，而不是去改目标。

铁证是 `commit 3d3e50f`："同文本 error_mean 0.885 → 0.950"，7 处改动全是
**消除检查器误报**，报告一个字没改。这不是作弊，是**在错误的层级上努力**——
每一次改动单独看都合理，累积效果是"指标不再度量它名字所说的东西"。

## 三、外部结论 × 本项目证据的对照

| 外部原理 | 项目现状 | 缺口性质 |
|---|---|---|
| 裁判必须用留出集标定 TPR/TNR | 105 项检查全部未标定；阈值 0.78 来源不明 | **不可证伪** |
| 二元断言优于连续分 | 0–1 连续分 + error-severity 均值 | **可躲进中间值** |
| 100% 通过是警报 | 0.95 被当作成就庆祝 | **信号方向反了** |
| 不变量优于枚举 | 96% 检查是冻结的模式清单 | **不可收敛**（O(已发现失效) vs 开放输出空间） |
| 约束需要机制强制 | 197 份 md，同日自我违背 | **无强制力** |

**一句话概括**：项目把"验证"做成了**规模**（105 项检查、8893 行验证代码），
但没有做成**度量**（不知道任何一项的灵敏度和特异度）。规模不等于有效性。

## 四、具体建议（按"确定性 × 影响"排序）

### R1 ⭐ 金样本缺陷语料 + 门禁变异测试（核心建议）

**这是唯一一条"做了就能让 105 这个数字获得意义"的建议。**

**做法：**

1. **取 30 份已知合格报告**（`output/` 与 `tests/golden/` 中筛选，剔除含已知缺陷的）
2. **为 105 项检查各构造至少 1 个变异体**：向合格报告注入该项检查所针对的失效
   （如 `_check_template_leak` → 注入一行 `组1输出（合并润色版）`）
3. **断言两条**：
   - 合格原文 → Gate **必须通过**
   - 注入变异体 → Gate **必须失败**
4. **产出每项检查的 TPR**（该检查抓到自己的变异体 = 1）

**判读规则（关键）：**

| 结果 | 含义 | 处置 |
|---|---|---|
| TPR = 1，TNR = 1 | 检查有效 | 保留 |
| **TPR = 0**（抓不到自己的变异体） | **该检查是死的** | **删除或修复** |
| 合格原文被判失败（TNR 低） | **检查在误报** | 修检查，**不得改合格样本** |
| 多个检查抓同一个变异体 | 重复检查 | 合并 |

**为什么这条建议确定性最高：**

- 两个原料**已经存在**，不需要新基础设施，是"接线"而非"建设"
- **完全确定性**，不需要 LLM 调用 → 可进 CI、秒级、无成本
- 它是**可证伪的**：现在项目无法证明 Gate 有效，做完之后可以
- 预期收益：相当比例的检查会 TPR=0 而被删除。**105 缩到 40 但每项都有据，
  远胜 105 项都靠信念。**"检查数"这个指标本身应该消失

**验收**：产出一张 `check_id → TPR → 变异体样例` 的表，随 CI 一起跑。

---

### R2 用二元断言替代连续分数作为**放行权威**

- **放行判据改为二元**：一组必须全过的"硬断言"（结构完整性、数字可溯源、无内部标识泄漏……）。
  任何一条失败 → 不放行。不做均值、不做加权。
- **0–1 分数降级为监控信号**：可以继续记录，但**不得**作为放行依据；对外报告时
  附置信区间，而不是一个孤立小数。
- **每个失效模式拆成独立的二元子检查**，而不是给它打一个 3.5/5。
  例：不评"事实准确度 3.5"，而记"5 项必需事实命中 4 项"。
- **重设心理预期**：在一个真正有压力的语料上，**目标通过率约 70%**。
  回到 0.95 应被解读为"语料太弱"或"检查器被放宽"，而不是"质量提升"。

---

### R3 把枚举改成不变量（让检查可收敛）

枚举的复杂度是 O(已发现失效)，而输出空间是开放的——**这条差距不可能靠加检查收敛**。
替换为不变量，一条可覆盖上百条黑名单模式：

| 不变量 | 取代的黑名单类 |
|---|---|
| 报告中每个数字，必须可溯源到 fingerprint 里的 datapoint，**或**显式标注为估计 | 各"禁用词/编造数据"模式 |
| 三表勾稽恒等式成立（资产=负债+权益；营收−成本=毛利） | 各"财务异常"模式 |
| 每个引用可解析到真实来源；来源与标的**必须相关** | "假机构署名"（A5） |
| 单位一致性（数值与单位符号不得错配） | A2 类"孤儿单位"残骸 |
| 内部节点标识（`组N输出`/`node_*`）不得出现在正文 | `_check_template_leak` 的 4 个陈旧模式 |
| **顺序不变性 / 释义不变性**（§2.2） | ——（新增能力） |

**判据**：一条不变量若能同时解释 5 个以上历史黑名单模式，就删除那些模式。

### R4 先修验证底座（部分已完成，是 R1–R3 的前提）

**不能在跑不起来的测试套件上做变异测试。** 已完成：收集期 570s → 14.1s；
全量 1138 passed / 0 failed。**剩余**：

1. **3 个永久挂死的 e2e 用例**：根因在 `pipeline/agent_graph.py:203`——
   节点不声明 `timeout_s` 就等于**没有任何超时**。必须给**每个节点**设一个有限
   默认超时，并让超时成为**可见的失败**而不是静默等待。
2. **测试非 hermetic**：一次全量 run 向生产 `track_record.json` 追加了 652 条记录。
   所有默认指向生产路径的组件，在测试中必须注入 `tmp_path`。

### R5 治理：让约束变成会失败的东西（这条能防止复发）

**当前最重要的治理事实**：作者在同一天既写出了"防止指标游戏"的顶级思考，
又提交了放宽检查器的改动。**说明 md 文档不是约束卡**——这正是作者自己提出的
"原理四：没有强制力的约束必然失效"。所以不要写更多文档，把约束做成机制：

1. **指标冻结规则（CI 强制）**：任何对 `PASS_THRESHOLD`、`JUDGE_VERSION`、
   检查集合的改动，**必须**附带金样本语料在改动前后的 TPR/TNR 对照表；
   缺表则 CI 失败。
   → **这一条规则本身就能拦住 `3d3e50f`。**
2. **Gate 配置哈希必须覆盖检查器实现**（现在只覆盖 threshold + formula），
   否则跨版本分数静默不可比。
3. **能力"执行证明"测试**（见 R6）。

### R6 每个宣称的能力，都要有"证明它真的执行了"的测试

本次审计发现的"幻影能力"全部是同一模式：**功能存在、有名字、有文档、有测试，
但从未执行**。这类缺陷对"接线正确性"测试完全隐形。

| 幻影 | 症状 | 执行证明测试 |
|---|---|---|
| `CacheEngine` | 硬编码假数据，违反溯源契约 → 必然抛异常 | 断言 fetch 返回非空且字段合规 |
| `prediction_validator` | 读一个**不存在**的文件 → 读入 0 条 | **断言输入基数 > 0**（不是断言输出） |
| `render.py` 防注入 | PEP 701 语法，3.11 下无法导入 | 断言 `### x` 被转义 |
| `_dim_kb_map` fail-open | 异常被吞，报告静默降级 | 断言注入内容真的出现在 prompt 里 |
| LLM 响应缓存 | 测试夹具被防污染门槛正当拒绝 | **断言底层 HTTP 计数器为 1**（不是断言返回值） |

**通用规则**：验证"能力是否生效"时，**永远检查输入基数或底层副作用计数，
不要检查返回值**——因为失败与成功经常返回同样的东西。
（`prediction_validator` 修复前后都返回 `total=0`，这就是它藏了几个月的原因。）

## 六、怎么知道做成了（验收标准）

- [ ] Gate 有一张公开的 **TPR/TNR 表**（在留出语料上，非训练集）
- [ ] 每一项**存活**的检查，都能指出它抓到的至少 1 个变异体
- [ ] 放行判据是**二元硬断言**；分数仅作监控，且带置信区间
- [ ] 在压力语料上的通过率落在 **60–80%**，而非 95%+
- [ ] **改动检查器而不附语料对照表 → CI 直接失败**
- [ ] 全量测试 **< 2 分钟**、hermetic（不写生产数据）、无挂死用例
- [ ] 每个对外宣称的能力，都有"执行证明"测试
