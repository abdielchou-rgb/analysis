## 一、怎么给董事长提供"市场信息+增量信息"

### 增量信息的定义
**增量 = 董事长不知道的**。他熟悉柯力（产能/毛利/战略），不熟悉油位市场。所以增量信息的三大来源：

### 1.1 市场真相层（他不知道的硬数据）
| 信息 | 来源 | 增量价值 |
|------|------|---------|
| 招标真实份额 | 中石化/中石油电子招标平台（政府采购网） | 谁在赚钱、价格趋势，这是最硬的增量 |
| 磁致伸缩丝垄断格局 | TDK专利/日企产能/河南长润国产化进度 | 柯力进去会不会被卡脖子 |
| 加油站改造真实执行率 | 环保部/地方环保厅公开数据 | 不是"利好"，是"哪年放量"的真相 |
| 华虹真实产能 | 华虹产线/产能利用率/认证清单 | 它吃得下吗，要花多少钱扩产 |
| 久通渠道含金量 | 久通客户名单（海关/物流）+订单量级 | 80+国家是真金白银还是宣传话术 |
| 对手成本结构 | 川仪/正星/汉威财报分部数据 | 柯力的成本优势到底多大 |

### 1.2 判断层（董事长想不到的）
| 增量判断 | 怎么得出 |
|---------|---------|
| "生产主体选华虹" | 技术栈适配+认证现成+并表利润，三方对比 |
| "磁致伸缩丝是真正卡点" | BOM拆解+上游垄断格局 |
| "政策窗口2026H2-2027，错过等2年" | 美国EPA对标+执行率传导链 |
| "久通渠道价值在海关，不在物流" | 客户结构分析 |

### 1.3 呈现层（让董事长一眼懂）
- 竞争份额 → 饼图
- 三浪放量 → 瀑布图
- 生产主体三选 → 对比矩阵表
- 财务测算 → 收入/利润柱状图
- 风险上限 → 损失矩阵

## 三、训练模式执行（LLM 先用 Marvis，再用 DeepSeek）

### 执行命令
```bash
cd D:\2hao-analyst
# 训练模式：LLM_PROVIDER=agent_provider（Marvis），DeepSeek 校验
python scripts/run_reports.py "油位传感器" --type industry_deep \
  --mode train --workers 1 \
  --enrich-file data/keli_oil_enrich_20260805.json
```

### 双 LLM 分工
| 阶段 | LLM | 作用 |
|------|-----|------|
| 初稿生成 | **Marvis**（agent_provider，train模式） | 用训练数据/行业知识起草，质量优先 |
| 校验/修订 | **DeepSeek**（对侧provider） | 独立视角审查初稿，发现Marvis盲点 |
| 终稿 | DeepSeek（性能） | 全局编辑统一口径/删套话 |

### 为什么先用 Marvis
- Marvis 有 2hao 历史报告训练记忆（传感器行业），起草更贴合
- DeepSeek 做对侧校验，避免"自采自校验"（FP2b 对侧 provider）
- 训练模式 = Marvis 起草 + DeepSeek 独立评审，双重质量门

### 配置要点
- `LLM_PROVIDER=agent_provider` 让 Marvis 起草
- `HAS_AGENT=1` 确保 agent_provider 被选中
- DeepSeek key 必须存在（.env 已有）作校验端
- 需要 Marvis responder 在跑（`python scripts/agent_llm_responder.py watch`）

## 四、排除所有可能导致延迟的因素

### 延迟来源排查表
| 延迟点 | 根因 | 排除方案 |
|--------|------|---------|
| 数据采集慢 | akshare/Tavily 网络 | **复用已缓存数据**（enrich-file 注入），不重新采集 |
| 写改循环慢 | 3-5轮全量重写 | 强约束prompt一次写对 + 局部修订（R80已接线） |
| 每次重跑重采 | 无缓存命中 | R48 `_cached_collected` + enrich-file 直接注入 |
| LLM 串行 | 段落顺序生成 | 独立section并行（--workers 可调） |
| Gate 打回重写 | 生成端不约束 | 反方三段式/数据纪律prompt已注入（R80） |
| PDF 导出慢 | LibreOffice 冷启动 | 提前启动 soffice headless 常驻 |
| 模板句重写 | 命中黑名单全段重写 | 局部改写（R79定位段） |

### 零延迟执行清单（关键）
1. **数据零采集**：直接 enrich-file 注入已论证数据，管线 data 节点跳过网络
2. **一次写对**：R80 反方三段式+数据纪律prompt 已注入，减少打回轮次
3. **checkpoint 续跑**：中断不重头（R78），失败从断点继续
4. **局部修订**：Gate 失败只重写失败段（R66/R80）
5. **并行执行**：独立 section 并行生成
6. **Marvis responder 常驻**：避免 agent_provider 心跳等待（R77）
7. **数据契约预校验**：enrich-file 先过 `validate_enrich_file`，不合格提前发现

### 预估耗时
```
旧流程（全量重采+多轮重写）：40-60分钟
新流程（数据复用+一次写对+训练模式）：15-25分钟
```
