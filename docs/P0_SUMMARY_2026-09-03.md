## 一、交付清单

### 1. 价格接真价 (P0-1)

| 文件 | 用途 |
|------|------|
| `core/price_feeder.py` | akshare/yfinance 真实取价后端 |
| `tests/test_price_feeder.py` | 14 个测试用例 |

**核心 API：**
```python
from core.price_feeder import get_price, get_price_or_unverifiable

# 取价成功返回 float，失败返回 None（绝不编造）
price = get_price("300750", "2026-01-15", asset_type="A")

# 显式标注状态
result = get_price_or_unverifiable("300750", "2026-01-15")
# {"price": 260.0, "status": "resolved", "detail": ""}
# {"price": None, "status": "unverifiable", "detail": "akshare failed: ..."}
```

**防护机制：**
- `None` ≠ `0`：取不到价返回 `None`，不返回 `0`
- `unverifiable` ≠ `pending`：无法验证的 outcome 明确标注，不混入 pending 池
- 双后端 fallback：akshare → yfinance → None

### 2. MC 前置 Guard (P0-2)

| 文件 | 用途 |
|------|------|
| `core/significance.py` | `InsufficientOutcomes` 异常 + guard |
| `tests/test_significance_guard.py` | 12 个测试用例 |

**核心逻辑：**
```python
from core.significance import (
    InsufficientOutcomes,
    _require_valid_outcomes,
    monte_carlo_direction_significance
)

# 有效 outcome < 20 → 拒跑 MC
try:
    _require_valid_outcomes(predictions, min_valid=20)
except InsufficientOutcomes as e:
    print(f"数据不足: {e}")

# outcome 只认 correct/incorrect
# pending / unverifiable / pending_review → 不计入有效池
```

**为什么需要：**
- 10 条 correct + 90 条 pending → 跑 MC → p=0.001 → "显著" → **假阳性**
- Guard 拒绝：有效池只有 10 条，不足 20

### 3. ArgumentEngine 修复 (P0-3)

```python

```

**连锁效果：**
- argument 失败 → scaffold=None → D1 看到证据清单有 "argument" → 拦截
- 不再需要手动检查：代码路径自动阻断
