# 元评论语言根治落地（metacomment_blacklist + 作者姿态约束）

> 日期：2026-08-08
> 触发：用户指出"建议来源为合作方自述，可调内部台账验证"太 AI → 要求根治
> 结果：**系统检测器落地 + 工作台作者姿态约束 + v4.3 全部清零**

---

## 一、系统落地（防再犯）

### 1. `metacomment_blacklist`（core/template_blacklist.py）
新增元评论语言黑名单 + `scan_metacomment()`：
```
建议以 / 建议来源为 / 建议对 / 建议签署 / 待客户访谈 / 验证后升级 /
升级为实际值 / 值得关注的是 / 需提示的 / 需要说明 / 需评估 / 可考虑 /
建议以客户访谈 / 可直接调取 / 本方案测算主体为
```
与 `WORK_PROCESS_BLACKLIST`（修改痕迹）互补——前者抓"AI 助手姿态"，后者抓"工具痕迹"。

### 2. IronGate 接入
`_check_aigc_fingerprint` 同时扫工作过程语言 + 元评论语言，**任一命中 → 阻断（passed=False）**。

### 3. 工作台作者姿态约束（core/context_compiler.py）
`compile()` 新增"作者姿态"最高优先级约束：
```
你是报告作者，不是写作助手。正文必须：
· 只陈述事实/数据/分析/结论——不出现'建议验证/待核实/值得关注/需要说明'
· 不教读者'如何验证/如何尽调'——验证方法放附录
· 不解释'本报告如何得出'——直接给结果与依据
· 不自指'见某节/本报告'
· 不出现'可考虑/需评估/建议对'——直接给判断
```

## 三、根因 vs 根治对照

| 根因 | 根治 |
|------|------|
| AI 助手默认姿态 | metacomment_blacklist 自动拦截 + 作者姿态 prompt 约束 |
| 补丁式修复越改越"助手味" | 作者姿态约束让每次生成直接以"报告作者"口吻 |
| 缺元评论检测器 | scan_metacomment 接入 IronGate |
| 无风格基准 | 作者姿态约束明确"只陈述、不指导" |

---

## 四、一句话总结

**元评论语言根治落地：metacomment_blacklist 自动拦截"AI 助手姿态"（建议验证/需提示/值得关注/需要说明），工作台 prompt 加"作者姿态"最高约束（只陈述事实、不教读者、不自指、不解释过程），v4.3 报告元评论+工作过程语言全部清零。** 从此 AI 生成的报告保持"报告作者"姿态，而非"写作助手"姿态——这是质量体系的根本防线。
