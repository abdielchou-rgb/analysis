## 一、qwen call_llm 包装兼容【已修复】

### 根因
`qwen/qwen3.6-flash` 是推理模型，返回 `content: null`，推理过程在 `message.reasoning` 字段，最终答案在 reasoning 尾部。`call_llm` 原样返回 → 调用方 `content` 为空 → 报 `NoneType` subscript。

### 修复
`core/deepseek_client.py` 新增 `_normalize_llm_response(data)`：
- content 非空 → 直接用
- content 为 None 但 reasoning 有内容 → 提取 reasoning 尾部实质内容作为最终答案
- 所有 HTTP 响应统一过此规范化

### 验证
- `qwen/qwen3.6-flash` 真实调用 ✅ "中国的首都是北京。"
- DeepSeek 正常路径 ✅ 未受影响

**意义**：OpenRouter 的 flash 小模型现在可作 L1 路由（轻量提取/分类），不再阻塞。

## 二、P2-1 内容包预检【已落地】

### 新增 `core/content_precheck.py`
- `ContentPrechecker.check()`：按 SAC 维度统计数据充足度（维度→数据键提示词匹配）
- `decide()`：仲裁——score<0.3 降级（诚实留白）/ 0.3-0.6 精简 / >0.6 全写
- `build_prompt()`：生成给写作层的预检指令

### 接线
`section_writer.py` 的 `_write_group`（维度并行默认路径）：
- 写组前先算该组数据充足度，注入 prompt
- 空维 → "数据有限/待尽调核实，禁止编造"（防空维硬写幻觉）

### 验证
- 模拟：financial 数据足 → 正常；scarcity 缺 → 降级留白 ✅
- 中英键提示词覆盖（financial/valuation 补英文 revenue/net_profit/market_cap 等）

## 四、Marvis P2 预取通道【已落地】

### 新增 `core/marvis_prefetch.py`
- `submit(asset, seg, prompt)`：后台线程走 agent_provider 产候选（不阻塞主链）
- `poll(asset, seg)`：取可用候选（存在+未过期+非占位）
- `cleanup()`：清理过期候选
- **安全开关**：`MARVIS_PREFETCH=1` 才启用；responder 心跳 30s 内才算在线
- **失败即弃**：候选不可用/过短/异常 → 静默，主链照常

### 接线
`section_writer.py` 的 `_write_group`：
- 写组前先 poll 候选，有 → 采用（省一次付费调用）
- 无 → 正常 DeepSeek 写
- 候选来源标记 `channel=marvis`（free），绝不进终稿合并层

### 验证
- 无 responder 时 `enabled()=False`（安全关闭）✅
- 语法/回归全过 ✅
