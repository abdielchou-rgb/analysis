# 油位 v4.2 元评论语言清除 + 根因诊断

> 日期：2026-08-08
> 触发：用户指出"建议来源为合作方自述，可直接调取集团内部台账验证"太 AI
> 结果：**10 处元评论语言全部清除，v4.2 校验 PASS**

---

## 一、什么是"元评论语言"

元评论 = AI 在向读者**解释它的工作过程 / 教读者如何验证**，而非陈述分析结论。

| 类别 | 例子 | 问题 |
|------|------|------|
| **教读者尽调** | "可直接调取集团内部销售台账验证真实销量" | 报告不该教读者怎么做，直接给结论 |
| **教读者验证** | "待客户访谈与供应商尽调验证后升级为实际值" | 元评论，不是事实陈述 |
| **教读者交叉验证** | "建议以细分行业报告进一步交叉验证" | 元评论 |
| **AI 口癖** | "值得关注的是" "需提示的" "可考虑" | 填充词，非分析 |
| **解释工作过程** | "需要说明：4.6节盈亏平衡计算采用30%" | 在解释口径差异，而非直接给口径 |

**本质**：严肃报告 = 陈述事实 + 给出结论。元评论 = AI 跳出报告角色，变成"写作助手"在指导读者。

## 三、为什么反复发生（根因诊断）

### 根因 1：AI 的"助手默认姿态"
每次 patch 时，AI（我）倾向于**解释自己做了什么、建议读者怎么用**——这是"助手模式"的本能，不是"报告作者模式"。工作台模式（Claude 直接改 docx）没经过 StyleCompiler 去 AI 化，所以这些语言直接进了正文。

### 根因 2：补丁式修复 vs 重写
v2.3→v4.2 十几次 patch，每次都在"原文本 + 修改"——AI 在改的同时加入解释性语言，越改越"助手味"。**没有一次是"用专业报告标准重写全篇"**。

### 根因 3：缺"元评论检测器"
现有检查抓"工作过程语言"（补采/差距量化/战略部），但**没抓"教读者怎么做/解释工作过程"**这类元评论。这两类是不同的问题：
- 工作过程语言 = 我的修改痕迹（补采/R87/---）
- 元评论语言 = 我的助手姿态（建议验证/需提示/值得关注）

### 根因 4：风格基准缺失
没有"顶级报告风格基准"作为对照——如果每次 patch 前先对照"高盛/中金报告会怎么写这段"，就不会产出"待验证后升级"这种助手语。

---

## 四、根治方案（非打补丁）

### 1. 新增 `metacomment_blacklist`（元评论检测）
```
建议以 / 待客户访谈 / 验证后升级 / 值得关注 / 需提示 / 需要说明 /
建议来源为 / 可直接调取 / 交叉验证 / 建议对 / 可考虑 / 需评估
```
命中即 warning：报告混入"助手姿态"语言，需改写为直接陈述。

### 2. 工作台模式加"作者姿态"约束
`workbench_executor` / `context_compiler` 的 prompt 增加硬约束：
```
你是报告作者，不是助手。禁止：教读者怎么做/解释工作过程/建议如何验证。
只陈述事实、数据、分析、结论。所有"如何验证"信息放附录，不进正文。
```

### 3. 重写而非补丁
后续大改走"基于完整大纲重写"，而非"原文+插入"——减少 AI 解释性语言混入的机会。

### 4. 风格基准注入
`style_profiles` 增加"顶级报告风格 DNA"：对照高盛/中金原文，让 AI 学"作者姿态"而非"助手姿态"。

**油位 v4.2 清除 10 处元评论语言——报告从"AI 助手在教读者"回归"报告作者在陈述"。根因四层：①AI 助手默认姿态（解释自己做了什么）、②补丁式修复越改越"助手味"、③缺元评论检测器（现有只抓修改痕迹，不抓教读者语言）、④无顶级报告风格基准。根治：加 metacomment_blacklist + 工作台"作者姿态"约束 + 重写替代补丁 + 风格基准注入。**
