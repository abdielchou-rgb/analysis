# 同行顶级启发：投行/四大/MBB/券商/学术/GitHub——对 FP0 与工作台设计的映射

> 日期：2026-08-07
> 目的：把六类同行的顶级做法，映射到我们的 FP0（意图第一公民）+ 光谱架构 + 工作台设计
> 结论先行：**同行一致指向三个共识——① 假设驱动（MBB/投行）→ 我们叫意图驱动；② 审计式验证（四大）→ 我们的程序化校验；③ 编译式上下文工程（DSPy/学术）→ 工作台上下文模板的自动化。我们缺的不是方法论，是"把同行几十年沉淀的隐性规则显性化到 AI 管线"。**

---

## 第一部分 顶级投行/券商（高盛/大摩/中金/中信）

### 调研发现

| 打法 | 机制 | 我们的映射 |
|------|------|-----------|
| **Client Question First** | 研报先明确"客户要回答什么问题"，报告结构由问题驱动 | **FP0 意图第一公民**的直接证据 |
| **Conviction Through Questions**（Upstream/Woozle） | 好问题比好答案更能建立信念 | 意图解析层应产出"必答问题清单"，问题质量决定报告质量 |
| **Output-Format 契约**（equity-research-skill GitHub） | 研报有严格输出格式模板（评级/目标价/催化剂/风险） | SAC 已有，但需加"必答问题段" |
| **分析师操作规范**（外资投行手册） | 数据源标注/利益冲突披露/假设透明 | 对应 FP2a 数据履约 + R87 分级 |
| **分层报告**（Lionbridge） | 深度报告 vs 简评 vs 首次覆盖，篇幅分层 | **光谱选择**的证据——不同类型任务不同深度路径 |

### 关键启发
1. **投行研报本质是"回答客户问题"，不是"写满模板"**——这正是 FP0 的行业共识基础；
2. **问题清单先行**：大摩/高盛分析师开工前先列"本报告必答问题"；
3. **篇幅/深度分层**：不是所有报告都 40 页——光谱选择在投行是常态。

## 第二部分 四大会计师事务所

### 调研发现

| 打法 | 机制 | 我们的映射 |
|------|------|-----------|
| **分析性程序（ISA 520）** | 用财务比率/趋势/异常波动验证数据合理性，而非逐笔核对 | **data_caliber 已有**——毛利/PE/营收矛盾检测就是分析性程序 |
| **专业怀疑（Professional Skepticism）** | 审计师默认"可能有错"，主动找反证 | **反方论证（三段式）已有** + 应升为默认姿态 |
| **证据充分性** | 结论必须有充分适当证据支撑 | 对应证据链 / evidence_chain |
| **重大错报风险导向** | 先评估哪最可能错，重点审 | **数据矛盾优先级**——先查最可能的幻觉点 |

### 关键启发
1. **审计的"合理保证"而非"绝对保证"**——对应我们"幻觉无法消除只能隔离"；
2. **分析性程序 = 数据矛盾检测**：四大的财务分析程序就是我们的 data_caliber；
3. **专业怀疑应成为写手的默认姿态**——不是写完再查，是写的时候就假设可能有错。

## 第三部分 MBB（麦肯锡/BCG/贝恩）

### 调研发现

| 打法 | 机制 | 我们的映射 |
|------|------|-----------|
| **假设驱动（Hypothesis-Driven）** | 先假设结论，再找证据验证，而非先收集再归纳 | **FP0 意图驱动** + 决策引擎先出卡位评分假设 |
| **问题树（Issue Tree）** | 把问题拆成互斥穷尽的子问题（MECE） | SAC 26 维已是问题树，需加"从必答问题反推" |
| **金字塔原理** | 结论先行，论据分层 | 执行摘要先行（已有）+ 全文金字塔结构 |
| **SO WHAT 链** | 每个分析回答"所以呢" | So What 链已有（R35） |
| **事实基础** | 所有建议建立在事实而非观点 | FP2a 数据履约 |

### 关键启发
1. **假设驱动是最强的意图对齐工具**——先让决策引擎出"卡位评分假设"，再让写手验证，比"写完再看"高效得多；
2. **问题树应从必答问题反推**——不是从 SAC 模板正向铺开，而是从老板的问题拆解；
3. **金字塔 = 执行摘要先行**——已实现，但需确保摘要真正回答必答问题。

## 第四部分 学术大牛

### 调研发现

| 打法 | 机制 | 我们的映射 |
|------|------|-----------|
| **DSPy（Stanford）** | 编译式 prompt：把"写 prompt"变成"编程 + 自动优化" | 上下文模板可 DSPy 化——意图解析+写作约束程序化 |
| **Cognitive Prompt Research** | 认知科学验证：分认知模式提升输出 | 意图/数据/约束/示例分段 = 认知模式分离 |
| **Co-STORM / ConvergeWriter** | 多视角提问 → 证据驱动写作 | 意图解析层的多视角提问（前面已调研） |
| **IS-CoT / Semantic Early-Stop** | 生成中防崩溃 + 收敛早停 | 已实现（P1 补丁） |

### 关键启发
1. **DSPy 编译式是终极形态**：把"上下文工程模板"从手写变成"自动优化"——我们的工作台上下文模板是手写版，DSPy 是自动化版；
2. **认知模式分离**：意图（为什么）/数据（事实）/约束（边界）/示例（风格）分开注入，正是我们的上下文模板设计；
3. **学术验证了意图驱动的价值**：Co-STORM 证明多视角提问优于直接生成。

## 第五部分 GitHub 大牛

### 调研发现

| 打法 | 机制 | 我们的映射 |
|------|------|-----------|
| **agent-style（21 写作规则）** | AI 写作/代码风格规则，可 drop-in 到 Claude Code | 我们的 StyleCompiler 类似，可吸收其规则 |
| **agentic-context-engineering（ACE）** | 上下文自我演化 playbook | 工作台第四层"纠偏沉淀"的工程化 |
| **equity-research-skill** | 研报输出格式契约开源 | SAC 输出契约的参考 |
| **iterative-development** | 抽需求→骨架→审计 sprint | 工作台六步的参考 |

### 关键启发
1. **规则可 drop-in**：agent-style 证明写作规则能模块化，我们可吸收到 StyleCompiler；
2. **上下文自我演化**：ACE 证明"纠偏沉淀"不是概念，是可工程化的——对应我们 FP5 升级的纠偏学习。

## 第六部分 综合：对我们的最大启发（按价值排序）

### 启发一：假设驱动 = 意图驱动的最强执行机制
**MBB 假设驱动 + 投行问题清单 → 我们应先让决策引擎出假设，再让写手验证。** 这比"写完再对答案"高效 10 倍。落地：意图解析层产出必答问题 → 决策引擎先出初步答案（卡位评分/投入/最坏损失）→ 写手围绕验证组织。

### 启发二：专业怀疑 = 写手默认姿态
**四大专业怀疑 → 写手写的时候默认"可能有错"，主动找反证。** 落地：写手任务加"你写的数据可能哪里错？"自检步（已有 IS-CoT 反思，升级为怀疑姿态）。

### 启发三：DSPy 编译式 = 工作台模板的终态
**学术 DSPy → 上下文模板从手写升级为程序化自动优化。** 落地：P3 阶段把 workbench-context-template 变成可编译的模块（意图/数据/约束/示例分段 + 自动调优）。

### 启发四：问题树从必答问题反推
**MBB 问题树 → SAC 维度应从"老板的问题"反推，不是从模板正向铺开。** 落地：SAC 意图驱动重构时，每个维度标注"回答哪个必答问题"。

### 启发五：报告分层 = 光谱选择
**投行分层报告 → 光谱选择在行业是常态。** 落地：任务路由器天然符合投行实践。

## 第七部分 落地优先级（映射到我们的升级）

| 启发 | 落地 | 优先级 |
|------|------|--------|
| 假设驱动 → 意图驱动 | 意图解析层 + 决策引擎先出假设 | **P0**（柯力任务即用） |
| 专业怀疑 → 写手默认 | IS-CoT 反思升级为怀疑姿态 | P1 |
| 问题树反推 | SAC 意图重构 | P2 |
| DSPy 编译式 | 上下文模板程序化 | P3 |
| 报告分层 | 任务路由器（已设计） | P1 |

## 一句话总结

**六类同行的顶级启发高度收敛：投行/券商证明"客户问题第一"（FP0 的行业共识）、MBB 提供"假设驱动"的执行机制（意图驱动最强工具）、四大提供"专业怀疑+分析性程序"的验证姿态（写手默认怀疑）、学术 DSPy 指向"编译式上下文工程"的终态、GitHub 证明写作规则可模块化 drop-in。我们缺的不是方法论，是把同行几十年隐性规则显性化到 AI 管线。** 柯力任务应立即启用：**必答问题清单 → 决策引擎先出假设 → 写手围绕验证 → 专业怀疑自检 → 用户门禁**。
