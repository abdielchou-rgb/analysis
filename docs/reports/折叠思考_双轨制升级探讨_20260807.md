## 一、思考起点

用户问两件事：① 双轨制升级（工作台模式替代管线写作层）对不对；② 同行顶级打法是什么。

**先不下结论，拆成可验证的问题**：
- "意图丢失"这个诊断是否成立？对哪些任务成立？
- 工作台模式（人定意图+AI写+代码算+工具校验+记忆纠偏）是否真的比管线好？
- 同行怎么处理"确定性管线 vs 交互式写作"的分工？

---

## 二、第一层思考：双轨制是伪二分吗？

### 2.1 管线 vs 工作台的本质差异

```
管线模式：AI 写 → AI 评 → AI 改（闭环内没有用户）
工作台模式：AI 写 → 用户审 → AI 改（闭环内用户是裁判）
```

管线的闭环缺陷：**优化"AI 自评 AI"这个本身有缺陷的闭环**（R47：系统奖励看起来完整，惩罚诚实留白）。这是 8 版不收敛的根因。

工作台的闭环优势：**反馈回路最短，用户意图零损耗**。

### 2.2 但"双轨制"是伪二分

- 真实任务很少"纯批量"或"纯交互"
- 柯力任务 = 数据层（确定性计算）+ 写作层（交互）+ 校验层（确定性）
- 同行共识（deepset）：Workflows 和 Agents 是**光谱**，不是两个轨道

**修正**：不是"二选一"，是"按任务性质在光谱上选位置"。

---

## 三、第二层思考：工作台缺什么？

对照文档"幻觉防线四层"，逐层比对 2hao 现状：

| 防线 | 2hao | 工作台 | 结论 |
|------|------|--------|------|
| 算术外置 | compute_engine | 代码算 | 重合 |
| 数据锚定 | R87 分级 | 事实库分级 | 重合 |
| 程序校验 | IronGate | 校验脚本 | 重合（可复用） |
| **人类在环** | **缺** | **有但弱** | **真缺口** |

**关键发现**：工作台文档把"人类在环"当第④层，但实战中它才是收敛命门。用户一眼看出"华虹无关""终值差10倍"，任何 agent 做不到——因为评审依据是用户意图。

**但工作台也缺两件**：
1. **强制用户审核节点**（文档当可选项，实际是命门；WDSS 证实高险文档必须 human-gated）
2. **上下文工程能力**（工作台有效性依赖操作者的 prompt 手艺，需可复用模板）

---

## 四、第三层思考：同行顶级打法

### 4.1 光谱共识
- **deepset**：Workflows 和 Agents 是光谱非二分，按任务确定性需求选位
- **Pipeline-over-Prompt**：确定性管线优于 prompt 工程，稳定可测
- **When to Stop Using Agents**：任务确定时回归管线

### 4.2 人类在环
- **WDSS**（PeerJ）：human-gated 多 agent + 双向引用溯源——高险文档必须有门禁+溯源
- **Sst Iterative Writer**：先大纲→逐节写→评审修订，大纲冻结防漂移
- **iterative-development**：抽需求→walking skeleton→审计 sprint，先审骨架

### 4.3 合规
- **RAGF**：确定性策略强制，监管域 agent 行为受限
- **ORCHID**（ACL 2026）：高风险分类编排 RAG + 智能决策

---

## 五、最终结论

### 5.1 升级对错
- **方向对**：意图丢失是真问题，人类在环是最强校验
- **表述错**："双轨制"应改为"光谱选择"——按任务性质（意图强度/风险等级/批量 or 单份）选架构位置

### 5.2 修正后的光谱
```
批量定期跟踪          → 确定性管线（2hao E2E）
单份深度报告+个性化意图 → 混合（2hao 数据层 + Claude 直接写）
高险决策文档          → 混合 + 强制用户门禁 + 双向溯源（WDSS 式）
```

### 5.3 柯力任务落地
走"高险决策文档"档位：2hao 数据层（7锚点+决策引擎）+ Claude 直接写 + **强制用户门禁** + **结论可回溯**（evidence_chain/data_provenance 补）
