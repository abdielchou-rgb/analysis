# 光谱选择 / 工作台思路下的 FP 宪法升级设计

> 日期：2026-08-07
> 承接：《探讨_双轨制升级与同行顶级打法》——"光谱选择"替代"双轨制"
> 对象：FP1-FP7 宪法（v3.2）升级设计 + 架构升级 + 方法论/计算模块增补
> 结论先行：**新增 FP0 意图第一公民（最高优先级）+ 新增 FP8 路径光谱化（架构选择原则）+ 升级 FP5/FP7 覆盖交互闭环。架构加任务路由器 + 工作台执行器。方法论加意图解析层、上下文模板、人类门禁状态机、双向溯源。**

## 第一部分 FP 宪法升级

### 1.1 核心诊断：现有 FP 缺什么

```
FP1 系统本质      ← 没提"报告给谁、做什么决策"
FP2a 数据履约     ← 数据真实，但没提"是否回答了用户的问题"
FP2b 分析履约     ← 分析深刻，但"深刻"是机构标准不是用户意图
FP3 超级维度      ← 超越人类分析师，但人类分析师"懂用户要什么"这个维度没覆盖
FP4 人感约束      ← 像人，但没提"像用户期望的那个人的沟通方式"
FP5 智能演化      ← 每次分析变聪明，但没提"从用户纠偏中变聪明"
FP6 推理透明      ← 可审计，但没提"审计是否含用户意图回溯"
FP7 反脆弱性      ← 系统在混乱中变强，但没提"意图不确定时怎么办"
```

**缺的共性 = 意图维度**。现有 FP 定义了"系统对自己负责"（数据真/分析深/像人/可审计），**没定义"系统对用户负责"（回答用户的问题）**。这正是工作台文档诊断的"意图丢失"在宪法层的缺失。

### 1.2 新增 FP0：意图第一公民（最高优先级）

> **FP0 — 意图第一公民（Intent-First）**
> 2hao 的第一职责不是"写一份标准的报告"，而是**回答委托方的决策问题**。所有数据采集、分析框架、写作组织、校验标准，必须从"委托方要做什么决策、必答问题是什么"倒推。
> 推导约束：
> - 每个任务启动必须先做**委托方问题清单确认**（谁读/决策点/必答问题）——缺此步不得进入写作
> - 报告结构由必答问题驱动，不由 SAC 固定模板驱动
> - Gate 必须增加**意图符合性检查**（必答问题是否被回答），不只是结构/格式检查
> - 用户纠偏是最高优先级输入，优于任何自动评审
> 否决条件：任何"结构正确但没有回答用户问题"的报告，视为未通过。
> 与 FP2a 关系：FP2a 管"数据真不真"，FP0 管"答没答对题"。数据真但答非所问 = 失败。

### 1.3 新增 FP8：路径光谱化（架构选择原则）

> **FP8 — 路径光谱化（Architecture Spectrum）**
> 任务在"确定性管线 ↔ 交互式工作台"光谱上选择执行路径，按任务性质决定：
> - 批量/定期/标准化任务 → 确定性管线（E2E + SAC + IronGate）
> - 单份/深度/个性化任务 → 工作台混合（数据层 + Claude 直接写 + 用户审核）
> - 高险决策文档 → 工作台 + 强制人类门禁 + 双向溯源
> 推导约束：
> - 光谱选择是**元认知决策**（FP8 升级：从"选子框架"到"选执行路径"）
> - 选择必须可解释（为什么这个任务走管线/工作台）
> - 两条路径共享数据层/校验层/记忆层（不是两套系统）
> - 高险文档必须 human-gated（WDSS 式），用户审核不可跳过
> 否决条件：任何"用错路径"的任务（批量走工作台 / 高险走管线）必须被路由纠正。

### 1.4 升级现有 FP

| FP | 现状 | 升级 |
|----|------|------|
| **FP2a 数据履约** | 四元组标签 + 多源比对 | 加 **intent-tagged**：数据点必须标注"回答哪个必答问题"，无归属数据视为冗余 |
| **FP5 智能演化** | 知识库吸收 + 基准校准 | 加 **纠偏学习**：用户每次纠偏沉淀为规则（工作台第四层），从用户反馈中变聪明 |
| **FP7 反脆弱性** | 优雅降级 + 期权性 | 加 **意图不确定降级**：必答问题不明时，先出"问题清单"而非硬写报告（诚实留白的宪法化） |
| **FP6 推理透明** | 可审计 | 加 **意图回溯**：每个结论可回溯到"哪个必答问题 + 哪个数据源"（双向溯源） |

### 1.5 升级后的 FP 关系

```
FP0 意图第一公民   ← 为什么做（最高优先，先于一切）
FP1 系统本质       ← 我是谁
FP2 数据+分析履约   ← 说得真 + 答得对（FP0 的执行）
FP3 超级维度       ← 上限（含"懂委托方"维度）
FP4 人感约束       ← 下限
FP8 路径光谱化     ← 用什么架构（FP0 的映射）
FP5 智能演化       ← 时间轴（含纠偏学习）
FP6 推理透明       ← 空间轴（含意图回溯）
FP7 反脆弱性       ← 生存轴（含意图不确定降级）
```

## 第二部分 架构升级

### 2.1 新增：任务路由器（TaskRouter）

```
core/task_router.py（新增）
  输入：任务特征（报告类型/意图强度/风险等级/批量 or 单份）
  输出：执行路径 → {管线, 工作台, 工作台+门禁}
  
  路由信号：
    · 报告类型：decision_memo → 工作台+门禁；listed_company 批量 → 管线
    · 意图强度：用户自定义必答问题 → 工作台；标准 SAC → 管线
    · 风险等级：老板拍板/对外发布 → 门禁；内部跟踪 → 管线
    · 批量标志：--workers>1 → 管线
```

### 2.2 新增：工作台执行器（Workbench Executor）

```
core/workbench_executor.py（新增）
  复用 2hao 数据层：enrich / 决策引擎 / 财务模型 / R87 分级
  替换写作调度层：不用 section_writer，用上下文工程 + Claude 直接写
  流程：
    ① 意图对齐（委托方问题清单）
    ② 数据准备（数据层算好，分级标注）
    ③ AI 直接写（上下文模板：业务命题+数据+约束+示例）
    ④ 程序校验（verify_report：算术/实体/一致性）
    ⑤ 人类门禁（强制：进/不进 + 修改意见 → 决策审计）
    ⑥ 迭代沉淀（纠偏 → fact_base → 下次少犯）
```

### 2.3 架构总览（升级后）

```
┌─ 任务路由器 ─────────────────────────────┐
│  批量/标准化 → 确定性管线（E2E+SAC+IronGate）│
│  深度/个性化 → 工作台（数据层+Claude写+用户审）│
│  高险决策   → 工作台+强制门禁+双向溯源        │
└────────────────────────────────────────┘
        │ 共享底层
        ▼
┌─ 数据层（复用）──────────────────────────┐
│  akshare/enrich/决策引擎/财务模型/R87分级   │
├─ 校验层（复用）──────────────────────────┤
│  verify_report（算术/实体/一致性/渲染）     │
├─ 记忆层（升级）──────────────────────────┤
│  learning_loop + fact_base + 纠偏规则      │
└────────────────────────────────────────┘
```

## 第三部分 方法论框架与计算模块升级

### 3.1 新增方法论模块

| 模块 | 作用 | 形态 |
|------|------|------|
| **意图解析层** | 委托方问题清单 → 必答问题 → 报告结构 | `core/intent_parser.py` |
| **上下文工程模板** | 业务命题+分级数据+约束+示例 → 可复用 prompt | `docs/workbench-context-template.md` |
| **人类门禁状态机** | 进/不进+修改意见 → 决策审计 → 版本推进 | `core/human_gate.py` |
| **双向溯源** | 结论→必答问题→数据源 可回溯 | 复用 evidence_chain + 加 intent 维度 |

### 3.2 计算模块增补

| 模块 | 现状 | 增补 |
|------|------|------|
| **意图符合性检查** | 无 | `intent_gate.py`：必答问题是否被报告回答（嵌入相似度/规则） |
| **决策引擎** | 有（卡位/投入/最坏损失） | 加 **委托方问题注入**：必答问题作为决策引擎输入约束 |
| **财务模型** | 有（NPV/三表/勾稽） | 加 **投入产出比专项**：代工场景的投入拆分/盈亏平衡/期权价值 |
| **enrich 分级** | R87 verified/corrected/unverified | 加 **intent 归属**：每条数据标注回答哪个必答问题 |
| **fact_base** | 无 | 新增 `data/fact_base.json`：行业事实库（油位分级沉淀） |

### 3.3 方法论框架升级（SAC）

```
SAC 升级（decision_memo 强化）：
  顶层加「委托方问题」段（谁读/决策点/必答问题）
  各维度加「必答问题映射」（这个维度回答哪个必答问题）
  写作约束加「意图直达」：围绕必答问题组织，不赘述已知
  
  → 让 SAC 从"机构模板"升级为"意图驱动的分析框架"
```

## 第四部分 落地区分（优先级）

| 优先级 | 项 | 成本 |
|--------|-----|------|
| P0 | FP0 意图第一公民入宪法 + 委托方问题清单强制 | 低（文档+流程） |
| P1 | task_router 任务路由器 + workbench_executor | 中（新模块） |
| P1 | 上下文工程模板 + human_gate 状态机 | 低（模板+脚本） |
| P2 | intent_gate 意图符合性检查 + intent 回溯 | 中（嵌入相似度） |
| P2 | fact_base 行业事实库 + 纠偏学习 | 中（持续积累） |
| P3 | SAC 意图驱动重构（各维度映射必答问题） | 高（框架重构） |

## 第五部分 一句话总结

**FP 宪法新增 FP0（意图第一公民，先于一切）+ FP8（路径光谱化，架构选择），升级 FP2a/FP5/FP6/FP7 覆盖意图维度。架构加任务路由器（光谱选路径）+ 工作台执行器（数据层复用+Claude直接写+人类门禁+双向溯源）。方法论加意图解析层/上下文模板/人类门禁状态机，计算模块增补意图符合性检查/投入产出比专项/intent 归属。** 核心转变：**从"系统对自己负责"升级为"系统对用户负责"**——数据真 + 答对题 + 可回溯 + 用户纠偏。
