# MinerU 产物接入知识吸收流程

> 日期：2026-08-10 · 把 Marvis 用 MinerU 解析的估值方法论/行业框架产物接入 2hao 知识库

## 一、背景

Marvis 在用户 Windows 机部署本地 MinerU 引擎，批量解析了 7 份扫描版 PDF（估值方法论 + 行业框架），产物落盘 `data/基线/解析产物/`（12 个 md + 67 张图）。但产物是**孤立文件**，未进入 2hao 知识库，写报告时无法自动注入。

## 二、接入方案

新增 `scripts/absorb_mineru_outputs.py`，把 MinerU 全文提取提炼成"可执行判断规则"，写入 `methodology_rules.json`：

```
MinerU 产物 *.md → 主题识别（valuation/real_option/industry_framework）
  → 提炼判断规则（方法对比/折现逻辑/期权适用条件/行业框架）
  → save_external_rules(topic, rules) 写入 methodology_rules.json
  → section_writer 写报告时 serialize_rules_for_prompt 注入
```

**关键设计**：不往 `methodology_frameworks_detailed.json`（文件+摘要级）塞全文，而是提炼为**判断规则**（阈值+逻辑+结论指向）——这正是 `methodology_rules.json` 的设计意图（"投喂了没提升深度"的解法），让 LLM 真正按投行方法做判断。

## 三、执行结果

```
扫描 7 份，提炼 7 份，写入 8 条规则
  valuation: +7 条（估值三法对比/DCF折现/实物期权）
  industry_framework: +1 条（汽车行业分析框架）
```

验证：
- `methodology_rules.json` 已生成（valuation 7 + industry_framework 1）
- `load_rules()` 合并默认 + 外部规则 → valuation 共 9 条
- `serialize_rules_for_prompt(['valuation'])` 正常生成注入文本

## 五、后续可扩展

1. **批次化**：后续 MinerU 新产物跑一次 `python scripts/absorb_mineru_outputs.py` 即自动入库
2. **规则细化**：当前规则偏"方法对比/原则级"，可针对具体文档提炼更细的阈值规则（如 DCF 折现率区间）
3. **知识来源标注**：规则已带 `source: MinerU解析-<文档名>`，满足溯源要求
