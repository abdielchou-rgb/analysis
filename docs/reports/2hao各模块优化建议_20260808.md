# 2号分析师各模块优化建议（对照顶级论文/项目）

> 日期：2026-08-08
> 方法：调研 2026 顶级论文/项目（记忆架构/RAG评估/编排框架/多智能体），对照 2hao 各模块
> 结论先行：**6 大模块各有顶级参考可优化——记忆（RAG→分层记忆）、评估（LLM-as-Judge→G-Eval+裁判校准）、编排（手写→DSPy编译+图编排）、写作（单Agent→多角色）、数据（静态→自我演化）、门禁（规则→+LLM双轨）。但核心原则不变：Python 地基保留，优化是加层。**

---

## 一、各模块优化建议

### 模块1：记忆系统（当前：fact_base + learning_loop + edit_learning）
**现状**：fact_base（行业事实）+ learning_loop（教训）+ edit_learning（改写）三库并行，但结构简单。

**顶级参考（2026 记忆架构）**：
| 参考 | 核心 | 启示 |
|------|------|------|
| **Episodic-Semantic 分层** | 情节记忆（事件）+ 语义记忆（事实）+ 程序记忆（技能）三分 | 2hao 已有雏形（fact_base=语义，learning=程序），**补情节记忆**（每篇报告的事件/决策/结果，供回溯） |
| **Engram 记忆架构**（arXiv 2511.12960） | 记忆分层 + 检索 + 遗忘 | fact_base 加**遗忘/衰减**（旧数据标记 stale） |
| **Generative Semantic Workspaces**（AAAI） | 超越向量检索，语义工作区 | fact_base 从"关键词检索"升级"语义检索"（embedding） |

**建议**：
1. fact_base 加 embedding 检索（现仅关键词子串匹配）
2. 补情节记忆：每篇报告存"事件-决策-结果"，供跨报告学习（如"油位报告暴露的框架缺口"）
3. learning_loop 加衰减：旧教训标记 stale，避免过时规则误导

### 模块2：评估/门禁（当前：IronGate 34项规则 + 圆桌）
**现状**：IronGate 规则门禁（确定性）+ 手动圆桌（LLM 评审）。

**顶级参考（2026 LLM-as-Judge）**：
| 参考 | 核心 | 启示 |
|------|------|------|
| **G-Eval** | 用 LLM 按 rubric 打分，结合自洽性 | IronGate 规则 + **LLM 按维度 rubric 打分**双轨 |
| **裁判校准（judging-the-judges）** | LLM 裁判有偏差，需校准 | 圆桌评审加**裁判校准**（评审历史准确性调整权重） |
| **Who Evaluates the Evaluators** | 元评估 | 圆桌评审加**元评审**（评估评估者） |
| **COMPEL 框架** | LLM-as-Judge + 人工复核流水线 | 高险报告：LLM 初审 + 人工终审（已有 human-gate） |

**建议**：
1. IronGate 加 **LLM 维度评分**（rubric 驱动：数据密度/论证深度/去AI化/决策质量），规则门禁抓硬伤，LLM 评分抓软质量
2. 圆桌评审加 **裁判校准**：历史评审准确率（reviewer_reputation 已有雏形）加权
3. G-Eval 的自洽性检查：LLM 评分 + 解释 + 自洽三重（防评分漂移）

### 模块3：编排（当前：手写 pipeline + AgentGraph）
**现状**：E2EOrchestratorV2 手写管线 + AgentGraph 21节点。

**顶级参考（2026 编排）**：
| 参考 | 核心 | 启示 |
|------|------|------|
| **DSPy** | 编译式 prompt/流程优化 | 写作 prompt 从手写 → **DSPy 自动优化**（意图/数据/约束/示例分模块调优） |
| **LangGraph 图编排** | 显式状态 + 图路径 + 条件分支 | AgentGraph 升级：**显式状态** + 条件分支（如"悲观情景矛盾→路由修复"） |
| **Graph-Based Agentic AI**（arXiv 2607.19297） | 长周期有状态业务流程 | 2hao 长报告 + checkpoint：**有状态编排**（中断恢复精确到节点） |

**建议**：
1. section_writer 的 prompt 用 **DSPy 风格**参数化（意图/数据/约束/示例分模块，可调优）——context_compiler 已有雏形，升级为可自动优化
2. AgentGraph 加**显式状态机**：每节点 state + 条件转移（当前是静态 DAG）
3. 长报告 checkpoint 升级：**节点级恢复**（当前是 attempt 级）

### 模块4：写作（当前：section_writer + 工作台）
**现状**：管线（section_writer SAC 驱动）+ 工作台（Claude 直接写）。

**顶级参考（2026 多智能体写作）**：
| 参考 | 核心 | 启示 |
|------|------|------|
| **ADaPT 按需分解** | 执行失败才递归下拆 | 写作模块弹性：**执行失败才拆子模块**（当前固定维度并行） |
| **多角色写作** | 不同 agent 写不同部分 | 工作台可**分角色写**（研究写市场/财务写测算/合规写风险） |
| **Self-Refine** | 生成→批判→精炼 | 小错精炼、大错重建（已有，强化定位精度） |

**建议**：
1. 写作模块加 **ADaPT 按需分解**：组写失败才递归拆（当前固定分组）
2. 工作台分角色：研究/财务/合规 三角色分工（防单 Agent 全写引入 AI 痕迹）
3. Self-Refine 强化：批判反馈定位到段落级

### 模块5：数据系统（当前：akshare + enrich + data_basement）
**现状**：静态数据采集 + enrich 人工补。

**顶级参考（2026 数据/知识）**：
| 参考 | 核心 | 启示 |
|------|------|------|
| **自我演化知识库**（GEIS） | 每次任务更新知识 | 知识库**每次报告后更新**（新增事实/修正错误） |
| **RAG 质量分层** | 检索质量决定输出 | data_basement 加**检索质量评分**（相关度/可信度） |

**建议**：
1. 数据系统加**自我演化**：报告完成后新事实入 fact_base，错误修正（GEIS 式）
2. data_basement 加检索质量评分（相关度/新鲜度/可信度）

### 模块6：门禁双轨（当前：纯规则）
**现状**：IronGate 纯规则（确定性）+ metacomment 黑名单。

**顶级参考**：G-Eval + 规则结合。
**建议**：规则抓硬伤（数字矛盾/口径/AI痕迹）+ **LLM 抓软质量**（论证深度/决策清晰度/可读性）双轨。高险报告 LLM 评分作为 Gate 参考。

## 二、优先级排序（基于油位实战）

| 优先级 | 优化 | 解决什么 | 成本 |
|--------|------|---------|------|
| **P0** | fact_base embedding 检索 | 事实检索不准（油位波导丝靠记性） | 低 |
| **P0** | LLM 维度评分（rubric） | 规则门禁漏软质量（论证深度） | 中 |
| **P1** | 裁判校准（圆桌） | 评审偏差（Marvis 三轮才查全） | 低 |
| **P1** | 情节记忆 | 跨报告学习（油位教训复用到下一报告） | 中 |
| **P2** | DSPy 式 prompt 优化 | 写作 prompt 手写 | 高 |
| **P2** | LangGraph 状态机 | 编排静态 DAG | 高 |
| **P2** | ADaPT 按需分解 | 固定分组 | 中 |

## 三、核心原则（不变）

**Python 地基保留**：财务复算/规则门禁/数据采集——这些都是 0 token 确定性层，Marvis 圆桌认可的"每算必验"就是它们。优化是**加层**（LLM 评分/记忆增强/编译优化），不是替换。

**一句话**：2hao 各模块的优化方向清晰——记忆加分层+语义检索、评估加 LLM 双轨+裁判校准、编排加 DSPy+状态机、写作加按需分解+分角色、数据加自我演化、门禁加软质量评分。**但所有优化都在 Python 确定性层之上叠加智能层，不破坏已验证的地基。**
