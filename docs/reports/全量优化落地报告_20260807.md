### P0-2 模块版本管理地基【新模块】

新建 `core/module_version.py`：
- `commit()` 递增版本，保留 v1/v2/v3 历史（默认 10 版）
- `rollback()` 回滚上一版
- `mark_dirty()` 标记待重校验（影响传播入口）
- `dependents()` 按依赖图返回下游（影响范围传播）
- `frozen_facts` 锚定不可变事实（数字/口径）
- 每报告独立命名空间（工作区隔离，防跨任务污染）

**验证**：5 项单测全过（版本递增/回滚/影响传播/dirty标记/frozen_facts）。

### P0-3 门禁熔断（防局部修复死锁）【圆桌批判 F3】

`pipeline/e2e_orchestrator.py` 修订循环新增：
- 同一失败项被局部修订 N 次（默认 3，`REPAIR_CIRCUIT_BREAK` 可配）仍不过
- → 置 `ctx['circuit_broken']`，本轮降级"该模块全量重写"（不再无限局部精炼）
- 清计数防下一轮立刻触发

**治**：fail-fast 拦 80% 内容 → 无限局部修复循环（新的 300s 空等形态）。

### P0-4 基线测量脚本【新脚本】

- 跑一篇标准报告 → 记录 各阶段耗时 / Gate 轮次 / token / LLM 调用数
- 输出 `benchmark/baseline_*.json` 作为后续验收对照

### P1 补丁 A：IS-CoT 写时结构思考【ACL 2026】

`pipeline/section_writer.py` 写段 prompt 新增三步结构思考：
1. 本段核心判断（claim）是什么

3. 与前后文衔接 / 在报告树的位置

**治**：长文生成到后期崩溃（重复/跑题/逻辑塌缩），生成中防错而非事后纠错。

### P1 补丁 B：语义早停（收敛判定）【2026 论文，省 38% token】

`pipeline/e2e_orchestrator.py` 修订循环新增：
- 两轮之间语义相似度 > 0.90（`EARLY_STOP_SIMILARITY` 可配）且 Gate 未过
- → 判定收敛，提前停止，用 best_so_far 稿交付（防空转把好稿改坏）

**治**：修订循环空转（死等 Gate 全绿），与 STALL（失败项不变）互补。

### P1 补丁 C：反思内建【R2-Write 流派】

`pipeline/section_writer.py` 写段 prompt 新增写后自查三步：
1. 每个数字有标注（A/E/F/B）和来源？无来源=硬伤
2. 有反方论证（三段式）？
3. 与上文数字/口径冲突？冲突必须修正

**治**：写手写完自反思再提交，减少 Gate 返工轮次（R79-R87 振荡的直接缓解）。
