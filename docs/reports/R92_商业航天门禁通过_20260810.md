## 二、2号分析师机制优化（R92 断点修复闭环）

### 1. LLM 校验器不可用降级放行（核心缺陷）
- **问题**：`ai_tone_llm` 在 LLM provider 不可用时强制 error 阻断 → 本该通过的报告被无谓卡死、逼着重跑
- **修复**：`llm_checks_mixin.py` 改为 warning 降级放行 + `_degraded_checks` 标记（不假装通过，但也不卡死），与 `llm_data_verification` 语义一致

### 2. 失败项分类器（check_classify）
```
mechanical    → 数字/格式/标注/口径（规则脚本定向修）
semantic      → 分析深度/论证（LLM 局部重写）
environmental → LLM provider 离线（降级放行，非报告问题）
unknown       → 需人工判断
```

### 3. 定向验证 check_only
- 断点修复后**只重跑失败项对应的检查**，不全量重跑
- `gate.check_only(["numeric_chain_consistency", "layout_quality"])` → 只验这两项

### 4. 断点修复方法论（沉淀）
```
Gate 失败 → report_failures() 分类
  ├─ mechanical → 规则脚本定向修（复用修复器）
  ├─ semantic   → fail_locator 定位失败段 → LLM 局部重写（R54）
  └─ environmental → 降级放行，标记 degraded
→ check_only 定向复验 → 通过则交付（不重跑管线）
→ 同类失败反复出现 → 升级为生成端 prompt 修复（非打补丁）
```
