## 一、route_policy.py 节点级混编路由【已落地】

### 新增 `pipeline/route_policy.py`
- `ROUTE_POLICY`：perf/train 两模式的节点级 provider 映射
- `resolve_provider(node_type, mode)`：节点类型 → provider（环境变量可覆盖）
- `route_info(mode)`：路由策略全览（可观测）
- `is_marvis(node)`：判断是否走 Marvis
- `merge_mode_llm_map()`：兼容旧接口

### 核心设计
| 节点 | perf | train |
|------|------|-------|
| write/skeleton | deepseek | agent_provider（Marvis 免费训练） |
| **merge** | **deepseek** | **deepseek**（质量红线，永不 Marvis） |
| revise | deepseek | agent_provider + DeepSeek 抽检 |
| extract | openrouter | agent_provider |
| roundtable | openrouter | deepseek（异于训练源） |
| prefetch | agent_provider | （训练模式不需） |

### 接线
- `e2e_orchestrator.py`：draft_provider 改用 `resolve_provider("write", RUN_MODE)`
- `run_reports.py`：设 `RUN_MODE` 替代整篇 `LLM_PROVIDER`

### 验证
- perf：write=deepseek / extract=openrouter / prefetch=agent_provider ✅
- train：write=agent_provider / **merge=deepseek**（质量红线）✅
- 别名（assemble/draft）✅ / 旧接口兼容 ✅

## 二、skill_composer.py 柔性化定制【已落地】

### 新增 `core/skill_composer.py`
- `parse_requirement(需求)`：自然语言 → (报告类型, 侧重维度, 框架偏好, 深度, 受众)
  - 12 个需求关键词（并购/估值/尽调/审计/风险/竞争/行业/非上市/股权/ESG/成长/催化剂）
  - 深度检测（简版→shallow / 深度/尽调→deep / 默认 mid）
  - 受众检测（对外→external / 内部→internal）
- `compose_skill_plan(req)`：按需求组装技能方案
  - 框架选择（偏好优先 + 效果记录加权，GEIS 自演化）
  - 深度参数（模块数/每维字数/修订轮数）
  - 侧重维度加权（权重翻倍）
- `record_effect()`：技能自演化（Gate 过加分 / 失败惩罚）

### 接线
- `section_writer.py`：`CUSTOM_REQUIREMENT` 环境变量 → 注入柔性方案（侧重维度/优先框架/深度）到 fp8_plan_str

### 验证
- "侧重并购的尽调报告" → report_type=listed_company, depth=deep, focus=[ma_valuation, governance_esg] ✅
- 回归 12 项全过 ✅

## 三、新增环境变量

| 变量 | 默认 | 用途 |
|------|------|------|
| `RUN_MODE` | perf | 路由模式（perf/train） |
| `CUSTOM_REQUIREMENT` | "" | 柔性定制需求（如"侧重并购的尽调报告"） |
| `NODE_PROVIDER_<NODE>` | 未设 | 单节点 provider 覆盖（如 NODE_PROVIDER_MERGE=deepseek） |

## 四、一句话总结

**双模式升级为节点级混编路由（route_policy.py）：train 模式 Marvis 大量产 + DeepSeek 终审关键链，perf 模式 DeepSeek 主力 + Marvis 后台预取 + OpenRouter 圆桌，合并组装两个模式都走 DeepSeek（质量红线）。柔性化定制（skill_composer.py）：自然语言需求 → 技能组合动态组装，侧重维度加权 + 深度参数 + 框架自演化。** 回归全绿，可独立交付。
