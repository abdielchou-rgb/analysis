## 一、P1-3 Prompt Caching 前缀【已落地】

### 改动
`pipeline/section_writer.py`：
- 新增模块级常量 `_LLM_SYSTEM_PREFIX`（858 字）——写宪章/口径/禁语/IS-CoT/反思等**所有节点共享的静态约束**
- `_call_llm` 改用该常量（原内联字符串重构），保证跨调用 system prompt 稳定一致
- 变量部分（数据/大纲/反馈）放 user 消息，静态前缀不变 → **DeepSeek 自动磁盘缓存命中**

### 原理
DeepSeek context caching 按"前缀 token 自动缓存"计费（命中部分约 1/10 价）。一篇报告 10+ 次 LLM 调用，共享 858 字前缀 → 前缀成本近零。

### 关键点
- 常量变更需手动加版本注释（缓存 key 变化，命中率重置）
- decision_memo 的强制约束（DecisionEngine 数据锚定）**不在**前缀里——它是 per-report 变量，放 user 消息（R85 逻辑不变）

## 二、P1-4 参数调优【已落地】

| 参数 | 原值 | 新值 | 文件 | 依据 |
|------|------|------|------|------|
| `MAX_WAIT_SEC`（agent 兜底等待） | 300s | **120s** | `core/agent_provider.py` | 三通道超时设计：Marvis 120s 上限 |
| `REQUEST_TTL`（请求过期） | 600s | **300s** | `core/agent_provider.py` | 对齐等待上限 |
| `LLM_HTTP_TIMEOUT`（HTTP 请求） | 300s | **90s** | `core/deepseek_client.py` | DeepSeek 关键链 60-90s 设计；可环境变量覆盖 |

**治**：300s 空等是慢速根因之一（虽然 R77 心跳已缓解，但 responder 慢响应仍会等到 300s），下调到 120s/90s 后配合 R77 快速失败，最坏等待时间大幅收敛。

## 三、P1-2 L0 Python 吸收盘点【清单已出】

### 扫描范围
`core/` + `pipeline/` + `scripts/` 全部 LLM 调用点（call_llm/call_deepseek/DeepSeekClient/chat/complete）。

### 分类结论

| 类别 | 代表调用点 | 评估 | 建议 |
|------|-----------|------|------|
| **纯规则可吸收（立即 L0）** | 图表生成（chart_runner）、排版（format_sheriff）、重复检测（template_blacklist）、数字校验（data_caliber） | **已经是 Python**（0 token） | ✅ 维持，KPI 计入 |
| **语义判断类（不宜转规则）** | hypothesis_checker、bold_call_extractor、data_provenance | 转规则会降质；**已有规则 fallback**（regex/rule_based） | 维持 LLM 主 + 规则兜底；已是最优 |
| **轻量提取（可 L1 小模型）** | 标题/摘要抽取、格式归类 | 简单语义，可用 OpenRouter flash 小模型 | P1 后续：模型路由到 flash |
| **评分/质控（不宜 L0）** | quality_scorer、critic_panel | 多维度主观判断，转规则=Goodhart | 维持 LLM，走 L2 |

### 核心洞察
2hao 的"能 Python 的 Python"原则**已基本落地**——图表/排版/校验/检测全是 Python。真正的 token 大头在"语义判断 + 深度写作"（这些**不该**转 L0，转了降质）。L0 吸收的边际收益已小，**下一步应把精力放在模型路由（L1/L2 分流）而非硬转 L0**。
