# 报告质量最好 × 写作效率最高：最优配置

> 日期：2026-08-07
> 问题：柯力油位决策备忘录，报告质量最好 + 写作效率最高，怎么配置？
> 结论：**perf 模式为底 + Marvis 免费预取 + OpenRouter 异源圆桌 + 多轮修订自动收敛**。质量与效率不是二选一，是"付费花在关键链，免费吃在预取，异源保终审"。

---

## 一、最优配置（一句话）

```
python scripts/run_reports.py "柯力传感" \
    --type decision_memo \
    --mode perf \
    --max-attempts 3 \
    --enrich-file enrich_oil_20260807.json \
    --workers 1
```

叠加环境变量：
```bash
MARVIS_PREFETCH=1            # Marvis 后台预取候选草稿（省付费调用）
CRITIC_HETEROSOURCE=1        # 终局圆桌走 OpenRouter 异源（防同源偏差）
RUN_MODE=perf                # DeepSeek 主写关键链
```

---

## 二、为什么这样最好——质量与效率的精确分配

### 2.1 质量最好的三个杠杆

| 杠杆 | 配置 | 为什么 |
|------|------|--------|
| **merge 走 DeepSeek** | route_policy 强制 | 合并组装是质量流失重灾区（ACL 2025），付费精做 |
| **圆桌走 OpenRouter 异源** | `CRITIC_HETEROSOURCE=1` | 与 DeepSeek 不同源，防同源偏差（R47 教训） |
| **决策引擎数据锚定** | enrich 7 锚点 + DecisionEngine | 卡位评分/投入/最坏损失禁 LLM 自编，防事实硬伤 |

### 2.2 效率最高的三个杠杆

| 杠杆 | 配置 | 为什么 |
|------|------|--------|
| **L0 全 Python** | 内置 | 图表/排版/校验 0 token 0 延迟 |
| **Marvis 预取** | `MARVIS_PREFETCH=1` | DeepSeek 写的时候 Marvis 后台产候选，过了 verifier 直接省一次付费调用 |
| **语义早停 + 熔断** | 内置 | 修订收敛就停（省 token），同一失败 3 次降级全量重写（防死锁） |

### 2.3 为什么不选 train 模式（质量角度）

train 模式 write 走 Marvis → 草稿质量波动，即使 merge 走 DeepSeek 兜底，**初稿决定上限**。决策备忘录是给老板拍的板，初稿质量必须高 → **write 走 DeepSeek（perf）**。Marvis 通过预取通道贡献免费草稿（可用则用，不可用 DeepSeek 补），不抢占主写。

### 2.4 为什么不全 DeepSeek（效率角度）

纯 DeepSeek 无预取 → token 成本全付费。Marvis 预取吃免费额度，OpenRouter flash 做轻量提取（L1），三个通道协同 = 成本最低。

## 三、节点级实际路由（此配置下）

| 节点 | provider | 效率贡献 |
|------|----------|---------|
| write（论点单元） | **DeepSeek L2** | 初稿质量最高 |
| write（候选预取） | Marvis 后台（`MARVIS_PREFETCH=1`） | 过 verifier 省付费调用 |
| skeleton | DeepSeek L1 | 骨架一次说清 |
| merge | **DeepSeek L2** | 质量红线 |
| revise | DeepSeek + 语义早停 | 收敛快，不空转 |
| extract（轻量） | OpenRouter flash | 便宜 L1 |
| roundtable | **OpenRouter 异源** | 终审防偏差 |
| L0 | Python | 0 token |

## 五、执行要点（防 R83 事故）

1. **先 `--data-check-only` 查缺口**，确认 7 个 enrich 锚点是否在
2. **enrich 每条带 source**（FP2 零编造），无 source 桥接层拒绝
3. **R83 禁令自动生效**（decision_memo 类型已硬编码禁投资评级）
4. **Gate passed=true 才交付**，附 cost_audit 成本日志
5. 若 Marvis 预取候选质量差 → 静默丢弃，DeepSeek 主写不受影响

---

## 六、一句话总结

**perf 模式（DeepSeek 写核心）+ MARVIS_PREFETCH=1（免费草稿后台预取）+ CRITIC_HETEROSOURCE=1（OpenRouter 异源终审）+ 多轮修订自动收敛 = 质量最好（初稿 DeepSeek + 决策引擎锚定 + 异源圆桌）× 效率最高（L0 全 Python + 预取省付费 + 早停省 token）。** 决策备忘录这种拍板场景，初稿质量决定上限，所以 write 必须 DeepSeek，Marvis 走预取不抢主写。
