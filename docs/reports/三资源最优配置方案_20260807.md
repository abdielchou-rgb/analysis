# 三资源最优配置：免费 Marvis + 付费 DeepSeek + 付费 OpenRouter

> 日期：2026-08-07
> 你的资源：免费 Marvis（时间换 token）、付费 DeepSeek API、付费 OpenRouter API
> 目标：**最节约 token + 写报告效率最高**
> 前提：2hao 管线现有 R13 三算力架构（deepseek/ollama_local/agent_provider）天然支持此配置

---

## 一、配置总原则（先记住这 5 条）

1. **能 Python 的永远 Python**（L0，0 token）——最省的 token 是没发给 LLM 的 token；
2. **付费 DeepSeek 扛"关键链"**（数据收集后的推理/写作/评审——必须实时、必须准）；
3. **免费 Marvis 只做"后台闲活/预取"**（草稿/候选/平行内容——失败即弃，绝不进终稿）；
4. **OpenRouter 只做两件事**：DeepSeek 挂了时的**降级** + 终稿的**异源圆桌**（与 DeepSeek 不同源，防同源偏差）；
5. **不省关键链的 token**——在 2hao 场景，事实错误的成本 > token 成本。省在"可重试的活"上，不省在"不可错的活"上。

## 三、每篇报告的最优 token 分配（"花钱地图"）

```
假设一篇标准 listed_company 报告约 2-3 万字，token 分配策略：

┌─ 阶段 ──────────┬─ 走哪 ───────────┬─ 为什么 ──────────────────────┐
│ 数据收集/清理    │ L0 Python 100%   │ 0 token，akshare/本地库直接算   │
│ 数据补缺(WebSearch)│ DeepSeek L1 chat │ 关键数据必须准，不省             │
│ 内容包预检/骨架  │ L0 + DeepSeek L1 │ 骨架是地基，一次说清省后面返工   │
│ 论点单元写作(并行)│ Marvis 免费预取 + │ 草稿免费通道后台产，关键模块     │
│                  │ DeepSeek L2 审   │ DeepSeek 终审覆盖               │
│ 合并组装(逐层)   │ DeepSeek L2       │ 组装=质量流失重灾区，必须付费精做│
│ IronGate 修订    │ DeepSeek L1/L2    │ 修订是收敛关键，不省             │
│ 终局圆桌         │ OpenRouter 异源   │ 2-3 家异源评审，防同源偏见       │
│ 排版/格式/图表   │ L0 Python 100%    │ 0 token，规则化                 │
└─────────────────┴─────────────────┴───────────────────────────────┘

估算占比：L0 0 token / DeepSeek ~60% / Marvis ~25%（预取替代）/ OpenRouter ~15%（终局）
对比现状（全 DeepSeek）：省 token 主要来自 Marvis 预取 + L0 吸收 + 缓存前缀
```

## 四、关键省钱杠杆（按收益排序）

### 1. Prompt Caching（收益最大，先做）
- **宪章 + 大纲 + 事实库**做缓存前缀，所有节点共享；
- 每篇报告至少 10+ 次 LLM 调用，前缀一致 → 缓存命中 → 成本近零；
- **DeepSeek 口径实测**：DeepSeek 自动磁盘缓存，命中按 1/10 计费（约 -90% 前缀成本）；OpenRouter 部分模型支持 prompt caching，同样实测。

### 2. L0 Python 吸收（0 token 大项）
- 现有 R13 已让 Ollama 扛评分/格式，**升级为全 L0**：
  - 数字校验/口径统一（data_caliber 已有）
  - 图表生成（chart_runner 已有）
  - 排版/格式（format_sheriff 已有）
  - 相似度/重复检测（模板黑名单已有）
- **KPI：用 Python 消化了多少"本会走 LLM"的任务**——并行设计的目标。

### 3. Marvis 免费预取（后台零等待）
```
主链跑 DeepSeek 时，同时让 Marvis 免费通道后台生产：
  → 平行论点/备选措辞/行业背景草稿（channel=marvis 显式标记）
  → 隐藏在主链背后，零等待，产出可选用
  → 失败即弃（历史实证：5 章并行全挂仅留首章，所以绝不依赖它）
```

### 4. 模块级重算（不做全量重写）
- R79-R87 八轮全量重写 = token 黑洞；
- 模块版本管理 + 影响传播：只重跑受影响子树。

### 5. 规模分级（防过度工程）
- 简单标的 8-12 模块，复杂才 40+；
- Anthropic 实测多 agent token ≈ 单聊 15 倍——**并行省时间不省 token**，简单任务别并行。

## 五、配置文件（ProviderRegistry 代码骨架）

```python
import os
from core.deepseek_client import ProviderRegistry, ProviderConfig
from core.agent_provider import AgentProvider

registry = ProviderRegistry()

# P0 主力：DeepSeek（付费，扛关键链）
registry.register(
    "deepseek",
    ProviderConfig(
        name="deepseek",
        api_key=os.environ["DEEPSEEK_API_KEY"],
        base_url="https://api.deepseek.com/v1",
        models=["deepseek-chat", "deepseek-reasoner"],  # L1 chat / L2 reasoner
        priority=0,
    ),
)

# P1 兜底+圆桌：OpenRouter（付费，异源）
registry.register(
    "openrouter",
    ProviderConfig(
        name="openrouter",
        api_key=os.environ["OPENROUTER_API_KEY"],
        base_url="https://openrouter.ai/api/v1",
        models=["deepseek/deepseek-chat", "deepseek/deepseek-reasoner", "qwen/qwen3-turbo"],  # 异源用于圆桌
        priority=1,
    ),
)

# P2 免费预取：Marvis（免费，后台闲活）
registry.register("agent_provider", AgentProvider(priority=10))  # 显式 10，非 -1！

# 环境变量
os.environ.setdefault("LLM_PROVIDER", "deepseek")  # 主模式走 DeepSeek
```

**注意**：`AgentProvider(priority=10)` 是 P0 必修项——当前 `agent_provider.py` 的 `priority=-1` 注释写"兜底"但实际是最高优先级（注册表升序取最小），语义反转。

## 六、铁律（守不住就白配）

| # | 铁律 | 原因 |
|---|------|------|
| 1 | **Marvis 预取绝不进终稿合并层** | 免费通道质量波动（历史实证全挂），只作候选草稿，过 verifier 才能用 |
| 2 | **终局圆桌至少 1 席付费异源模型** | 免费模型圆桌=集体放水，质量红线不可押免费 |
| 3 | **DeepSeek 不可用时 OpenRouter 降级，但主写作仍回 DeepSeek** | OpenRouter 是兜底不是主路 |
| 4 | **不省关键链 token** | 事实错误成本 > token 成本 |
| 5 | **先跑基线再定 target** | 2hao 已有 R77/R53 缓解 300s 空等，别把预算花在已修环节 |

## 八、一句话总结

**DeepSeek 扛实时关键链（写作/组装/修订，60% token），Marvis 免费只在后台预取草稿（25%，失败即弃），OpenRouter 只做降级和终局异源圆桌（15%），能 Python 的全部 L0（0 token），宪章/大纲/事实库做缓存前缀（命中近零）。** 这样省下的 token 主要来自三处：**L0 吸收 + Marvis 预取 + 缓存前缀**，而质量红线（终稿/数字/事实）始终由付费 DeepSeek + 异源圆桌兜底。
