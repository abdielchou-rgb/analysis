# 探讨：双轨制升级对不对 + 同行顶级打法

> 日期：2026-08-07
> 承接：《深度分析_人机协作写作工作台》——工作台 vs 管线的双轨制升级
> 方法：先独立评估（不附和），再对照同行顶级打法
> 结论先行：**升级方向对，但"双轨制"是过渡态不是终态——终态是"按任务性质选光谱位置"。柯力任务证实了意图密集型应走交互，但工作台缺一个关键件：验证不等于人类审核。**

---

## 第一部分 双轨制升级对不对——独立评估

### 1.1 对的部分（3 点）

| 判断 | 证据 |
|------|------|
| **意图丢失是真的** | 2hao R83 事故（写成投资评级而非决策备忘录）就是意图错位；管线的 Gate 查结构不查意图 |
| **人类在环是最强校验** | 用户一句"久通渠道存疑"比 5 个 critic 准——评审依据是用户意图，agent 拿不到 |
| **工作台的前三层与 2hao 重合** | 算术外置/数据锚定/程序校验，2hao 全有（R87），所以混合模式"数据层复用"成本极低 |

### 1.2 需要修正的部分（3 点）

**① "双轨制"是伪二分。** 同行共识（deepset）是 **Workflows 和 Agents 是光谱不是二分**。真实任务很少"纯批量"或"纯交互"——柯力任务也不是纯交互：数据层仍要 2hao 的确定性计算。所以更准确的说法是**"按任务性质在光谱上选位置"**，不是两个轨道二选一。

**② 工作台缺一个关键件：用户审核 ≠ 程序验证。** 文档的"程序化校验器"说复用 IronGate 检查项，但 IronGate 查的是"结构/格式/一致性"（确定性），而油位 v2.3 真正收敛靠的是**用户肉眼纠偏**（非确定性）。工作台若只"复用校验脚本"没有"强制用户审核节点"，会退化成管线换壳。

**③ 工作台没有解决"AI 写初稿质量"的根本问题。** 文档说"AI 直接写上下文工程"，但上下文工程本身是门手艺（文档自己引 Anthropic 方法论）。没有它，工作台的初稿可能比管线更差（管线至少有 SAC 约束）。**工作台的有效性依赖操作者的上下文工程能力**，这是隐性前提。

### 1.3 我的判断

**升级方向对，但要把"双轨制"重新表述为"光谱选择"：**

```
任务类型 → 光谱位置 → 架构
─────────────────────────────────────
批量定期跟踪          → 确定性管线（2hao E2E 强化后）
单份深度报告+个性化意图 → 混合（2hao 数据层 + Claude 直接写 + 用户审核）
高风险决策文档         → 混合 + 强制用户审核节点 + 双向溯源（WDSS 式）
```

**对柯力任务的直接含义**：走混合模式，但必须加"用户审核节点"（非可选项），且上下文工程要写出可复用的 prompt 模板（否则每次手搓）。

## 第二部分 同行顶级打法（调研）

### 2.1 核心共识：光谱而非二分

| 参考 | 主张 | 对本项目的启示 |
|------|------|---------------|
| **deepset**：AI Agents and Deterministic Workflows | 光谱非二分；按任务确定性需求选位 | 双轨制应改"光谱选择"，任务有确定性部分就上管线 |
| **Pipeline-over-Prompt**（myjman 博客） | 确定性管线优于 prompt 工程，稳定可测 | 2hao 的确定性层（数据/校验）是资产，别扔 |
| **When to Stop Using Agents** | agent 有额外成本，任务确定时回归管线 | 批量报告该回管线，工作台只服务意图密集 |

### 2.2 人类在环的顶级做法

| 参考 | 机制 | 启示 |
|------|------|------|
| **WDSS**（PeerJ） | human-gated 多 agent + 双向引用溯源（高险企业文档） | 工作台要加"人类门禁"（不是可选项）+ 结论可回溯到数据 |
| **Sst Iterative Writer**（ClaudSkills） | 长文迭代写作：先大纲→逐节写→评审修订 | 工作台六步已覆盖，可借鉴其"大纲冻结"防漂移 |
| **iterative-development 插件** | 抽需求→walking skeleton→审计 sprint 循环 | 意图对齐可学：先出骨架再填肉，用户先审骨架 |
| **loop engineering**（martech） | 构建反馈循环而非调 prompt | 用户纠偏→记忆→下次少犯，是工作台第四层 |

### 2.3 高险文档的合规参考

| 参考 | 机制 |
|------|------|
| **RAGF**（cronocom） | 确定性策略强制框架，监管域 agent 行为受限 |
| **Auditable LLM-RAG**（Semantic Scholar） | 金融文档决策支持的可审计架构 |
| **ORCHID**（ACL 2026） | 高风险分类的编排 RAG + 智能决策 |

**启示**：柯力决策备忘录属高险文档——需要**结论可回溯**（每个数字能点到数据源）+ **人类门禁**。这正是工作台文档缺的，也是 2hao 的 `evidence_chain`/`data_provenance` 能补的。

## 第三部分 修正后的升级方案

### 3.1 光谱选择器（替代双轨制）

```
新增 core/task_router.py：
  输入：任务特征（报告类型/意图强度/风险等级/批量 or 单份）
  输出：光谱位置 → {架构, 人类参与度, 校验强度}
  
  · 批量定期跟踪 → 管线（2hao E2E）
  · 单份深度报告 → 混合（2hao 数据层 + Claude 直接写）
  · 高险决策文档 → 混合 + 强制用户门禁 + 双向溯源
```

### 3.2 工作台补三件（修正 1.2 的②③）

| 补件 | 解决 |
|------|------|
| `scripts/verify_report.py`（确定性校验，复用 IronGate 检查项） | 程序验证 |
| **强制用户审核节点**（非可选：进/不进 + 修改意见，写入决策审计） | 人类门禁（WDSS 式） |
| `docs/workbench-context-template.md`（可复用上下文工程模板） | 初稿质量隐性前提 |

### 3.3 柯力任务落地（修正后）

```
① 任务路由：柯力油位决策备忘录 → 高险决策文档 → 混合 + 人类门禁 + 双向溯源
② 2hao 数据层：--data-check-only + enrich 7锚点 + 决策引擎（卡位/投入/最坏损失）
③ Claude 直接写：上下文模板（业务命题+分级数据+R83约束+示例）
④ 确定性校验：verify_report（算术/实体/一致性）
⑤ 用户门禁（强制）：老板审 → 纠偏 → 沉淀 fact_base
⑥ 交付：docx + 决策审计 + 双向溯源（结论→数据→来源）
```

---

## 第四部分 一句话结论

**升级方向对，但"双轨制"是伪二分——同行顶级共识是"光谱选择"（deepset/Pipeline-over-Prompt）：批量确定性任务走管线，意图密集型任务走混合，高险决策文档走混合+人类门禁+双向溯源（WDSS/RAGF 式）。工作台本身缺两件：程序校验脚本（待封装）和强制用户审核节点（文档当可选项，实际是命门）。柯力任务按光谱应走"高险决策文档"档位——2hao 数据层 + Claude 直接写 + 强制用户门禁 + 结论可回溯。**
