# 怎么切、怎么组——最优方法与顶级理解

> 日期：2026-08-07
> 承接《模块化写作思路评估_20260807.md》，聚焦两个可操作问题：**模块怎么切最优？组装怎么组最优？**
> 结论先行：**切用"双向树"（自顶向下定骨架 + 自底向上定内容），组用"证据驱动自底向上收敛"（ConvergeWriter），两类方向不是二选一，而是分时复用。**

---

## 一、大方向之争：Top-Down vs Bottom-Up

| 流派 | 代表 | 逻辑 | 强项 | 弱项 |
|------|------|------|------|------|
| **自顶向下（Top-Down）** | STORM / Co-STORM / AgentWrite | 先定大纲骨架，再填充叶子 | 结构清晰、覆盖全面 | 大纲≠内容，易写出"框架正确但证据薄" |
| **自底向上（Bottom-Up）** | ConvergeWriter（arXiv 2509.12811）/ ToM | 先从数据归纳事实单元，再逐层收敛成文 | 数据驱动、事实密度高 | 无骨架引导易松散、层级失控 |

**网上顶级判断**：两者不是替代关系，是**分时复用**。Co-STORM 已经证明"多视角提问→生成大纲"优于直接问；ConvergeWriter 证明"让内容从数据里长出来"优于"先编骨架再填"。最优是——

```
第一阶段（切）：自顶向下定骨架（STORM 式多视角大纲）
第二阶段（长）：自底向上让内容从证据里长出来（ConvergeWriter 式）
第三阶段（收）：自底向上逐层收敛组装（ToM 式树形 map-reduce）
```

---

## 二、怎么切：最优切法（三个层次）

### 2.1 切分的锚点：先有"事实单元"，再有大纲

**关键洞察（ConvergeWriter）**：切分的单位不是"章节"而是"**事实单元（fact unit）**"。流程是——

```
1. 从资料/数据里抽取独立事实点（每点带来源）
2. 事实点按主题聚簇（聚类）→ 自然形成"内容包"
3. 内容包映射到大纲章节 → 章节大小由内容量决定，不按字数拍脑袋
```

这解决了一个根本问题：**按章节硬切会让空章节硬写（幻觉来源），按内容切则每个模块"有话可说"。** 2hao 的 SAC 26 维就是"按框架切"，缺的是"先看这维有多少真实内容、再决定模块大小"。

### 2.2 粒度：双层结构（章节级 + 论点单元级）

```
论文共识：
  章节级（section）   = 骨架，写手视角，大纲冻结
  论点单元级（argument unit） = 肉，200-500 字/个，幻觉最低
```

**切法口诀**：章节按内容包定大小，论点单元按"一个完整论证"切（claim + evidence + reasoning 三件套）。一个论点单元必须自洽——**能独立成立，才配独立成模块**。

### 2.3 接口：模块之间的"契约"

**顶级理解：模块边界 = 数据契约，不是文本边界。**

```
每个模块定义三个接口：
  input_contract   需要哪些上游数据/结论（依赖声明）
  output_contract  产出什么（本模块结论 + 对外承诺的事实点）
  frozen_facts     本模块锚定的不可变事实（数字/口径/引用）
```

→ 这正是 2hao 已有 `output_contract` 的强化版：补上 **input_contract（依赖声明）和 frozen_facts（锚定事实）**。有了这两个，后面"影响范围传播"才有依据（谁能依赖我、我锚定什么）。

## 三、怎么组：最优组法（四个机制）

### 3.1 收敛方向：自底向上，数据驱动（ConvergeWriter）

```
事实单元 → 论点单元（200-500字） → 子章节（3-5 论点） → 章节 → 全文
     ↑ 数据归簇        ↑ 单论点成文        ↑ 小组收敛        ↑ 大组合并
```

**每层收敛的关键**（ACL 2025 反例的正解）：合并时**必须带源上下文**，不是只传摘要——
```
错误：把 5 个论点单元"各写 2 句摘要"→ 丢给上层
正确：5 个论点单元 + 各自的关键证据引用 + 可回溯指针 → 上层据此写综述
```

### 3.2 收敛批大小：7±2（人类认知负荷上限）

**5-8 个一组逐层收敛**。这是"7±2 工作记忆"在组装层的直接映射——每层合并的单元数超过 8，模型注意力就开始漂移，衔接处开始断裂。

### 3.3 收敛时的一致性锚（防漂移）

```
组装层要带三类全局锚：
  ① 大纲锚：当前在全文树中的位置（防止写偏）
  ② 事实锚：共享事实库（数字/口径只读，全局唯一）
  ③ 风格锚：写作宪章（术语/语气/禁语）
```

这三个锚在**每一层合并时都注入**，不是只在开头注入一次。这是长篇写作一致性（"分层记忆+迭代工作流"）的核心机制。

### 3.4 组装后校验：三查

| 检查 | 查什么 | 反例 |
|------|--------|------|
| 覆盖度 | 大纲每个要点都被内容覆盖？ | 大纲有"风险"章节，内容没写 → 漏 |
| 衔接度 | 相邻章节过渡自然？ | 上一章结论与下一章开头矛盾 → 断 |
| 一致度 | 数字/术语/口径全文统一？ | 前一章 PE 65，后一章 PE 79.79 → 矛盾 |

**校验也要分层做**：每层收敛做轻量校验（fail-fast），全文完成做终局校验（圆桌）。

## 四、综合最优方案：三步走

```
STEP 1 切（自顶向下）
  多视角调研（STORM 式）→ 大纲草案 → 主 Agent 冻结大纲
  + 每个章节先查"有多少真实内容"（内容包），空章节降级或合并

STEP 2 长（自底向上）
  事实单元抽取（带来源）→ 聚簇 → 映射到大纲 → 论点单元级并行写作
  每个论点单元带 input_contract / output_contract / frozen_facts

STEP 3 收（自底向上收敛）
  5-8 一组收敛，每层带源上下文 + 三类锚（大纲/事实/风格）
  每层 fail-fast 校验 → 全文终局圆桌
  出错：模块级版本管理 + 影响范围传播，只重跑受影响子树
```

**一句话**：切用"先看内容再定骨架"（自顶向下），组用"让内容从数据里长出来、逐层带锚收敛"（自底向上）。骨架冻结、内容生长、锚定收敛、按需修复。

## 五、对 2hao 的具体映射

| 机制 | 2hao 对应 | 动作 |
|------|----------|------|
| 多视角大纲 | report_planner + SAC 26 维 | ✅ 已有，可加"STORM 式多视角提问"增强 |
| 内容包（先查内容再定章节） | **缺** | 新增：写前先统计各维数据充足度，空维降级/合并（防硬写幻觉） |
| 论点单元 200-500 字 | 维度并行（段级，粒度粗） | 细化：维度内按论点单元拆（dimension_grouper 增强） |
| input/output contract + frozen_facts | output_contract 已有 | 补 input_contract + frozen_facts |
| 5-8 组收敛带源上下文 | _editor_merge（只传摘要） | **重写合并层**：传摘要+证据引用+指针 |
| 三类锚每层注入 | StyleCompiler/SAC 开头注入 | 改为每层合并时注入 |
| 模块版本+影响传播 | 无 | 从零建（最大缺口） |

---

## 六、一句话总结

**最优切法 = 先看内容再定骨架（STORM 式大纲 + ConvergeWriter 式内容包）**，**最优组法 = 自底向上带锚收敛（ToM 式树形 map-reduce + ACL 2025 源上下文合并）**。骨架冻结、内容生长、每层带锚、按需修复。对 2hao 而言，最值钱的三件事：**内容包预检（防空维硬写）、合并层重写（带证据链）、frozen_facts 锚定（给影响传播打地基）**。
