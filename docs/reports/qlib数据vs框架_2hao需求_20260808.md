# qlib_bin（数据）vs qlib（框架）：2hao 到底需要什么

> 日期：2026-08-08
> 触发：用户下载了 qlib_bin，问"还需要 qlib 的意义在哪里"

---

## 一、先分清：qlib_bin 是数据，qlib 是框架

```
qlib_bin（你下载的）= 数据
  ├── calendars/  交易日历（day.txt）
  ├── instruments/ 股票池（all/csi300/csi500/csi800）
  └── features/    个股特征数据（bj430017 等）
  → 本质：格式化好的 A股行情+特征数据

qlib（微软框架）= 引擎
  ├── 数据加载器（读 qlib_bin 格式）
  ├── 因子库（Alpha158/Alpha360 等）
  ├── 模型训练（LightGBM/GRU/TFT 等）
  ├── 回测引擎（Backtest）
  └── 机器学习管线（数据→因子→模型→回测）
  → 本质：把"数据+因子+模型"串成量化研究闭环的框架
```

**关键**：只有 qlib_bin 数据、没有 qlib 框架，数据是"死的"——没人读、没因子、没回测。**qlib 的意义 = 让 qlib_bin 数据活起来**。

---

## 二、2hao 到底需不需要 qlib 框架？

### 现状
- 2hao 有 144 个引擎（财务/估值/框架），但**没有量化因子/回测闭环**
- 有 qlib_bin 数据（没框架），有 qlib_bin 目录（之前 R62 提到预测闭环）
- 2hao 的 prediction_loop 是"记录预测→验证"，不是"因子研究→回测"

### 需要 qlib 的 3 个场景

| 场景 | 价值 | 优先级 |
|------|------|--------|
| **因子研究** | 用 Alpha158/360 因子库，量化选股/择时 | 🟡 有提升但非核心 |
| **预测回测** | 用 qlib 回测引擎验证策略，替代手写 | 🟡 增强预测闭环 |
| **机器学习模型** | LightGBM/深度学习预测股价 | 🟢 可选增强 |

### 不需要 qlib 的 3 个原因

| 原因 | 说明 |
|------|------|
| **2hao 是"研究+写作"系统，不是"量化交易"系统** | 核心是产报告，不是跑策略回测 |
| **财务/估值引擎不依赖量化因子** | 基本面分析用财务数据，不用 Alpha 因子 |
| **qlib 学习曲线高** | 集成成本 > 收益，除非专门做量化章节 |

---

## 三、结论：qlib_bin 怎么用才合理

### 方案 A：只留数据（推荐）
```
qlib_bin 作为 A股行情/特征数据源：
  2hao 用 pandas 直接读 features/（不装 qlib 框架）
  → 补充基本面分析之外的技术面/行情数据
  → 用于技术指标（pandas-ta）、资金面、市场热度章节
```

### 方案 B：装 qlib 框架（量化增强）
```
装 qlib → 读 qlib_bin → 因子库 + 回测
→ 新增"量化验证"能力：策略回测、因子有效性检验
→ 适合未来做量化研究章节（如选股因子报告）
成本：集成 qlib 依赖较重，学习曲线高
```

### 方案 C：暂时不用（当前状态）
```
qlib_bin 数据先存着，2hao 核心是基本面报告，量化非刚需
→ 等有明确量化报告需求再装 qlib 框架
```

---

## 四、一句话总结

**qlib_bin 是数据（日历/股票池/特征），qlib 是框架（因子/模型/回测）——数据没框架是死的。** 对 2hao 而言：**当前不需要装 qlib 框架**（2hao 是研究+写作系统，非量化交易系统，基本面分析不依赖 Alpha 因子）。合理用法是**方案 A：用 pandas 直接读 qlib_bin 数据**，补充技术面/行情数据到基本面分析；未来若有量化报告需求再装 qlib 框架。
