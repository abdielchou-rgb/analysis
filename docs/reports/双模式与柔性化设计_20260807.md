# 升级版 2hao 设计：双模式 + 柔性化定制写作

> 日期：2026-08-07
> 问题一：训练模式 LLM 全 Marvis / 性能模式才 DeepSeek，怎么设计？
> 问题二：基于现有框架+知识库，柔性化定制写作，需补什么知识/框架？网上顶级参考？
> 结论先行：**双模式应从"整篇切换"升级为"节点级混编路由"；柔性化应从"固定 SAC 模板"升级为"技能组合 + 框架注册表动态组装"。**

---

## 第一部分 双模式设计（训练 / 性能）

### 1.1 现状（已存在，但粗）

```
--mode perf   → LLM_PROVIDER=deepseek        （整篇走 DeepSeek）
--mode train  → LLM_PROVIDER=agent_provider  （整篇走 Marvis）
```

现有 `run_reports.py` 的 `MODE_LLM` 映射是**整篇切换**——一个模式一个 provider 全用。问题：
- **train 模式全 Marvis**：Marvis 慢（队列轮询）+ 质量波动，关键链（合并/修订）也用它会降质
- **perf 模式全 DeepSeek**：Marvis 免费额度完全没用上，token 成本高
- **没有"混编"**：两种资源没有协同，浪费一半

### 1.2 升级设计：节点级混编路由（双模式 = 路由策略差异，不是 provider 全换）

核心思路：**双模式不是"用哪个 LLM"，而是"路由策略偏好"**。同一个管线，每个节点按模式 + 节点难度选 provider：

```
┌─────────────────────────────────────────────────────┐
│  路由策略表（perf vs train 的差异）                     │
├──────────────┬──────────────────┬───────────────────┤
│ 节点类别       │ perf 模式         │ train 模式         │
├──────────────┼──────────────────┼───────────────────┤
│ L0 确定性计算 │ Python（0 token） │ Python（0 token）   │
│ 数据收集/清理  │ Python            │ Python             │
│ 数据提取/分类  │ OpenRouter flash  │ Marvis（免费训练）  │
│ 骨架/大纲      │ DeepSeek L1       │ Marvis（免费训练）  │
│ 论点单元写作   │ DeepSeek L2       │ Marvis（免费训练）  │
│ 合并组装       │ DeepSeek L2（必须付费，质量重灾区）│ Marvis + DeepSeek 终审 │
│ 修订（Gate反馈）│ DeepSeek L1/L2   │ Marvis + DeepSeek 抽查 │
│ 终局圆桌       │ OpenRouter 异源   │ DeepSeek（异于 Marvis 训练源）│
│ 排版/格式/图表 │ Python            │ Python             │
└──────────────┴──────────────────┴───────────────────┘
```

**关键设计决策**：

1. **合并组装永不走 Marvis**——质量重灾区（ACL 2025 反例），train 模式也要 DeepSeek 终审；
2. **train 模式 = Marvis 大量产草稿 + DeepSeek 抽检修订**——免费额度吃满，但关键链付费兜底；
3. **perf 模式 = DeepSeek 主力 + Marvis 后台预取候选**（P2 已有，`MARVIS_PREFETCH=1`）；
4. **L0 全 Python**——两个模式都是 0 token，这是"模式无关"的底座。

### 1.3 落地：per-node routing（节点级 provider 选择）

```python
# pipeline/route_policy.py（新增，替代 run_reports 的 MODE_LLM 整篇映射）
ROUTE_POLICY = {
    "perf": {
        "write": "deepseek",        # 写作走 DeepSeek
        "merge": "deepseek",        # 合并走 DeepSeek（必付费）
        "extract": "openrouter",    # 轻量提取走 OpenRouter flash
        "prefetch": "agent_provider",  # 后台预取 Marvis
        "roundtable": "openrouter",   # 终局圆桌异源
    },
    "train": {
        "write": "agent_provider",  # 写作走 Marvis（免费训练）
        "merge": "deepseek",        # 合并仍 DeepSeek（质量红线）
        "extract": "agent_provider",# 提取 Marvis
        "prefetch": "",             # 训练模式不需要预取（自己就是免费）
        "roundtable": "deepseek",   # 圆桌走 DeepSeek（异于训练源）
    },
}

def resolve_provider(node_type: str, mode: str, fallback: str = "deepseek") -> str:
    """按节点类型 + 模式解析 provider；未配置/不可用 → fallback。"""
    policy = ROUTE_POLICY.get(mode, ROUTE_POLICY["perf"])
    return policy.get(node_type, fallback)
```

### 1.4 train 模式的核心价值：自迭代学习闭环

train 模式不应只是"用 Marvis 写"——它是**训练回路**：
- Marvis 产草稿 → DeepSeek 终审 → Gate 反馈 → **learning_loop 沉淀教训**
- 教训回写 `framework_registry` + `edit_learning.db`（已有）
- 多轮训练（MAX_ATTEMPTS 5-10）让 Marvis 逐步逼近 DeepSeek 质量

**train 模式的验收标准**：Marvis 稿在"不经 DeepSeek 修订"时，Gate 通过率逐步上升（>50%）。这说明 Marvis 在学。

### 1.5 双模式补充建议

| 建议 | 说明 |
|------|------|
| 模式切换粒度 | perf/train 之外加 `--mode hybrid`（默认），按节点难度自动路由 |
| 模式可观察 | 成本日志按模式聚合（`cost_audit(mode=...)`），看哪个模式真的省 |
| train 的预算 | train 模式免费 ≠ 无成本（Marvis 队列轮询），设"每报告训练轮上限" |
| 防混编污染 | Marvis 草稿标记 channel=marvis，进终稿前必须过 verifier（R67 护栏已有） |

## 第二部分 柔性化定制写作能力

### 2.1 现状（已有但固定）

- SAC 26 维固定模板（listed/unlisted/industry_deep/decision_memo 四类）
- framework_registry（7 框架）+ methodology_rules + knowledge_injector
- 缺：**按用户需求动态组合**（"我要一份侧重并购的尽调报告"→ 现在只能选固定模板）

### 2.2 升级设计：技能组合 + 框架注册表动态组装

```
① 技能库层（已有雏形）
   = 沉淀的标准模块：调研/证据/图表/摘要/门禁/估值/并购/瓶颈引擎...
   → 升级为"可组合技能"（每个技能带 input/output contract）

② 组装层（升级）
   用户需求 → 复杂度评估 → 选技能组合 → 生成写作宪章+证据锚点
   "侧重并购的尽调" → [尽调骨架] + [并购估值技能] + [审计核查技能] + [反方论证]
   
③ 执行层（已有）
   论点单元级并行 → 5-8 组收敛 → 影响传播
   
④ 门禁层（已有）
   IronGate + 圆桌
```

### 2.3 需补充的知识/框架（对照顶级参考）

| 缺口 | 顶级参考 | 补充什么 |
|------|---------|---------|
| **技能可演化** | Skill-MAS（蚂蚁+港科大）、SkillOpt（微软） | 技能要能"练"——用效果回测自动改进技能 prompt，不是一次性写好 |
| **技能自设计** | Memento-Skills / LatentSkill | 让 LLM 从用户需求**设计新技能**，而不是只在已有库里选 |
| **参数化技能组合** | SkillSmith | 技能带参数（深度/侧重/篇幅），组合时按需求调参 |
| **自适应长文** | WriteHERE | 写作中动态调整结构（不只开头定死），按内容长度/复杂度 |
| **方法论知识扩展** | （现有 knowledge 2517 篇未全吸收） | 补充：并购估值、审计核查、ESG 实质性、非上市估值、行业生命周期 |

### 2.4 具体的柔性化落地路径

```
STEP 1 技能注册表升级（现有 framework_registry 扩展）
  - 技能带 input/output contract + 参数 + 适用场景 + 效果记录
  - 用户需求 → 匹配技能组合（相似度/规则）

STEP 2 需求解析层（新增）
  "侧重并购的尽调" → 解析出：报告类型=尽调 + 侧重=并购 + 深度=中
  → 查技能库 → 组合 [尽调骨架+并购估值+审计核查]

STEP 3 柔性参数（新增）
  - 深度（浅/中/深）→ 模块数 8/20/40
  - 侧重（某维度权重高）→ SAC 维度裁剪/加权
  - 受众（内部/对外）→ 风格 + 结论强度

STEP 4 技能自演化（P3，GEIS 式）
  - 每次报告后记录技能效果 → 效果好的技能权重高 → 下次优先选
  - 用户反馈 → 技能 prompt 微调
```

| 领域 | 现状 | 补充 |
|------|------|------|
| 并购估值 | 有 consolidation 模块 | 补：并购溢价/协同效应量化/整合风险/交易结构 |

## 第三部分 综合结论

### 双模式设计（问题一）

**不要"整篇切换"，要"节点级混编路由"**：双模式 = 路由策略差异，不是 provider 全换。train 模式 Marvis 大量产 + DeepSeek 终审关键链；perf 模式 DeepSeek 主力 + Marvis 后台预取。合并组装是质量红线，两个模式都走 DeepSeek。落地 `route_policy.py` 替代 `MODE_LLM`。

### 柔性化定制（问题二）

**从"固定 SAC 模板"升级为"技能组合 + 框架注册表动态组装"**：需求解析 → 技能组合 → 柔性参数 → 技能自演化。需补的知识：并购估值细化、审计核查、ESG 行业对标、非上市退出概率、行业生命周期信号表。顶级参考：Skill-MAS（可演化技能）、Memento-Skills（技能自设计）、SkillSmith（参数化组合）、WriteHERE（自适应长文）。
