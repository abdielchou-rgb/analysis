# 深度分析：人机协作写作工作台 vs 2hao 管线

> 日期：2026-08-07
> 对象：`docs/human-ai-writing-workbench.md`（油位 v0.86→v2.3 实战提炼）
> 方法：诊断评估 → 处方对照 → 范式分歧 → 工具链核实 → 柯力任务结论 → 宪法冲突
> 结论先行：**文档诊断成立、处方大半已内建于 2hao、真正的缺口是"人类在环"；它不是要取代 2hao，而是定义了 2hao 管线的适用边界。柯力决策备忘录应走工作台混合模式。**

---

## 一、诊断评估：意图丢失链——成立，但要说清边界

文档的意图丢失链：`用户意图 100% → 计划 70% → SAC 维度 50% → LLM 写 40% → Gate 只查结构`。

**这个诊断对"个性化深度报告"成立，对"批量标准报告"不成立。**

- 2hao 管线的设计哲学是**机构级标准化**：SAC 26 维是投行模板，目标是"可复现、规模化、像中金"——本来就不是"用户个性化意图"。
- 当用户要的是"老板要的一份决策备忘录"，个性化意图是核心资产，管线每层压缩它 → 低效成立。
- 当用户要的是"每月批量出 10 份行业跟踪"，标准化意图就是目标，管线效率反而是优势。

**关键教训（文档没明说但隐含）**：2hao 的 Gate 查"结构对不对"不查"符不符合你想的"，这在**决策备忘录场景是致命的**——因为决策备忘录的价值 100% 在"符不符合老板想问的"（R83 事故：写成了投资评级报告而非董事长决策备忘录，正是意图错位）。

---

## 二、处方对照：幻觉防线四层 vs 2hao 现状

| 文档防线 | 2hao 现状 | 判断 |
|---------|----------|------|
| ① 算术外置（代码算） | compute_engine / predict_model / three_statement | ✅ **已有**，且比文档更系统 |
| ② 数据锚定（事实库分级） | R87 verified/corrected/unverified | ✅ **已有**，同源同体系 |
| ③ 程序化校验（事后） | IronGate + data_caliber + 语义早停 | ✅ **已有**，更自动化 |
| ④ 人类在环（用户纠偏） | **缺**（用户只看 Gate 报告） | 🔴 **真缺口** |

**核心发现**：文档的"幻觉防线四层"，前三层 2hao 全部已有——因为这份文档本身就是从油位 v2.3 提炼的，而 v2.3 的数据分级/校验正是 R87 的产物。**2hao 与工作台不是对立，是同一套防线在不同壳里。**

真正缺的是第④层：**2hao 管线的闭环是"AI 写 → AI 评 → AI 改"，没有"用户意图"进闭环**。用户只在最后收到 Gate 报告，无法在过程中纠偏。这就是为什么管线迭代 8 版不收敛——它在优化"AI 自评 AI"这个本身有缺陷的闭环（R47：系统奖励看起来完整，惩罚诚实留白）。

## 三、根本分歧：优化管线 vs 换范式——适用边界

文档主张"替换写作调度层（SAC/section_writer/IronGate）→ Claude 直接写 + 用户审核"。

这与本轮 P0-P3 全量优化（模块级重算/版本管理/语义早停/门禁熔断）**表面矛盾，实际互补**：

```
管线模式（2hao 强化后）          工作台模式（文档）
─────────────────              ─────────────────
批量、标准化、机构级             单份、深度、个性化
SAC 26 维固定模板               人定意图直达
可复现、规模化                  反馈回路最短
AI 自评审闭环                   人类终审
适合：定期跟踪/批量出报告         适合：决策备忘录/老板深度报告
```

**P0-P3 优化没有白做**——它让管线在它的适用域内更快更省更稳。但**决策备忘录不属于管线适用域**，属于工作台域。

## 五、与柯力任务的关系：该走哪个模式

**柯力油位决策备忘录 → 工作台混合模式**（文档第五节）。

判断依据：
1. **个性化意图极强**：市场规模/投入产出比/战略卡位/衍生价值 是老板的具体问题，不是 SAC 维度能表达的
2. **对象错位风险极高**：R83 已栽过（写成投资评级），正因管线不懂"老板要什么"
3. **人类在环价值最大**：老板一句"久通渠道真实性存疑"比 5 个 critic 都准

**混合模式执行链**：

```
2hao 数据层（算好，可靠）          Claude 直接写（意图）          用户审核（纠偏）
├── akshare/enrich 7锚点          ├── 上下文工程：业务命题+      ├── 老板拍板：进/不进
├── 决策引擎（卡位评分/投入/最坏损失）│    数据+约束+示例             ├── 纠偏沉淀 → fact_base
├── 财务模型（NPV/投入产出/代码算）  ├── 一次产出 → 校验脚本        └── 迭代 → v2/v3
└── R87 数据分级                  └── 用户一句反馈 → 直接改
```

即：**用 2hao 的"数据层 + 校验层"（可靠），替换掉"写作调度层"（SAC/section_writer/IronGate）为"Claude 直接写 + 用户审核"**。

## 六、宪法冲突：需要用户明确授权

我的 CLAUDE.md 宪法明写：**"你只管调度管线，不准亲自写"** + "LLM 只走 DeepSeek，agent 兜底回流管线"。

工作台模式 = 让 Claude 直接写正文 + 用户审核，**与宪法直接冲突**。

处理：
- 用户提供这份文档 = **隐含授权**该场景绕过管线（文档第五节的"替换写作调度层"就是授权声明）
- 但宪法是硬约束，需要用户**明确一句**："柯力任务走工作台混合模式，授权 Claude 直接写"
- 或者：保持宪法，把工作台封装为"合法通道"——写进 CLAUDE.md 第〇原则补充，明确决策备忘录/单份深度报告走工作台，批量标准报告走管线

**建议后者**：宪法升级为双轨制，避免每次都要口头授权。

## 七、落地建议

### 立即做（柯力任务）
1. 用户确认工作台混合模式
2. 跑 2hao 数据层：`--data-check-only` + enrich 7 锚点 + 决策引擎算卡位/投入/最坏损失 + 财务模型算 NPV/投入产出

- `docs/workbench-guide.md`：操作手册

### 宪法升级（双轨制）
```
CLAUDE.md 补充：
  第〇原则-双轨制
  ├─ 批量标准报告 → 管线模式（SAC/E2E/IronGate）

```

## 八、一句话结论

**文档诊断成立（意图丢失是真问题）、处方与 2hao 高度重合（前三层已有）、真缺口是"人类在环"、工具链有水分（3 组件待封装）。它不推翻 2hao，而是划定 2hao 的适用边界：批量标准化走管线（P0-P3 优化没白做），决策备忘录走工作台混合模式（2hao 数据层 + Claude 直接写 + 用户审核）。柯力任务应走后者，但需用户明确授权绕过宪法，建议宪法升级为双轨制。**
