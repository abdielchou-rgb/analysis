# 多报告并行/主题相近防串——顶级打法调研

> 问题：2hao 支持多份深度报告，但"液位传感器"被归到"油位传感器"行业键——主题相近会串数据
> 对标：企业级多智能体并行架构、Agent 上下文隔离、RAG 检索隔离、数据仓库租户隔离
> 日期：2026-08-06

---

## 一、问题本质

多报告并行时，防止串标的 = **上下文隔离（Context Isolation）+ 数据隔离（Data Isolation）+ 检索隔离（Retrieval Isolation）** 三层。2hao 已具备进程级隔离（subprocess 每标的一进程），但**行业键匹配**（`_infer_industry_key` 把液位归油位）是"检索隔离"层的漏洞。

---

## 二、顶级打法总览

| 层 | 打法 | 对标机构/体系 |
|----|------|--------------|
| 上下文隔离 | 每标的独立上下文窗口，不共享 | 企业多智能体架构（百度/阿里） |
| 数据隔离 | 每标的数据沙箱，物理隔离 | 数据仓库租户隔离（Snowflake） |
| 检索隔离 | 行业/标的归一化，精确匹配 | RAG 检索隔离（Agentic RAG） |
| 命名隔离 | 标的名规范化，防止近义混淆 | 主数据管理（MDM） |
| 校验隔离 | 交叉验证防串 | 数据血缘（dbt lineage） |

---

## 三、逐项顶级打法详解

### 3.1 上下文隔离——每标的独立上下文窗口

**顶级打法**：企业多智能体架构（百度/阿里实践）——每个 Agent 有独立上下文窗口，任务级隔离，不共享状态。

**2hao 现状**：✅ 已具备——`subprocess` 每标的一进程，内存/上下文物理隔离。这是最强保障。

**强化**：在 scheduler 入口打印"标的锚定"日志（`[ANCHOR] 本次分析标的：油位传感器`），任何上下文注入前先确认标的。

### 3.2 数据隔离——数据沙箱

**顶级打法**：数据仓库租户隔离（Snowflake）——每个租户数据物理/逻辑隔离，查询只命中自己的数据。

**2hao 现状**：⚠️ 部分具备——checkpoint 按 asset 主键隔离、data_dict 按 asset 保存。但**行业数据底座（unlisted_players.json）是全局共享的**，靠行业键路由。

**强化**：数据读取时增加"标的确认"——`data_basement` 读取行业数据前，校验行业键与标的匹配。

### 3.3 检索隔离——行业/标的归一化精确匹配（核心漏洞）

**顶级打法**：RAG 检索隔离——查询前先做**实体归一化**，确保检索的 context 只属于当前主题。

**2hao 漏洞**：`_infer_industry_key` 用关键词模糊匹配：
```
油位传感器 → 油位传感器 ✓
液位传感器 → 油位传感器 ✗（串！）
物位传感器 → 传感器（更宽）
油位 → 传感器（过宽）
```

**修复打法（RAG 归一化思路）**：
1. **精确匹配优先**：完整标的名精确查行业键映射表，命中即用，不再模糊
2. **关键词优先级排序**：按"最长匹配"而非"包含匹配"——"液位传感器"应优先匹配"液位"而非被"油位"包含
3. **行业键白名单**：`unlisted_players.json` 的实际键（油位传感器/液位仪表/传感器...）作为白名单，匹配不到返回"enrich"而非错误归并
4. **边界冲突检测**：如果两个报告标的映射到同一行业键且主题词不同（油位 vs 液位），告警提示"可能串"

### 3.4 命名隔离——主数据管理（MDM）

**顶级打法**：MDM（主数据管理）——企业统一实体命名，防止"苹果 vs Apple vs 苹果公司"同义混淆。

**2hao 强化**：建立**标的别名表** `data/asset_alias.json`：
```json
{
  "油位传感器": ["油位", "油位传感器", "油位液位计"],
  "液位仪表": ["液位传感器", "液位仪表", "液位计"],
  "物位": ["物位传感器", "物位计"]
}
```
`_infer_industry_key` 先查别名表精确匹配，再fallback关键词。

### 3.5 校验隔离——交叉验证防串

**顶级打法**：数据血缘（dbt lineage）——每个数据点可追溯来源，串标一眼可见。

**2hao 强化**：报告生成后，校验"行业数据是否与标的匹配"——如果油位报告用了液位的玩家清单，Gate 应能发现（unlisted_players 行业键 vs 标的行业键不一致 → warning）。

## 四、2hao 具体修复方案（按优先级）

### P0：修 `_infer_industry_key` 精确匹配（立即）

```python
# pipeline/universe_build.py 强化 _infer_industry_key
_INDUSTRY_KEY_MAP = {
    "油位传感器": "油位传感器",
    "液位传感器": "液位仪表",
    "物位传感器": "传感器",
    "液位仪表": "液位仪表",
    "油位": "油位传感器",
    "液位": "液位仪表",
    "物位": "传感器",
}
# 先精确匹配（完整名 or 别名），再关键词
for alias, key in _ALIAS_MAP.items():
    if alias in str(asset):  # 最长匹配优先
        return key
```

### P1：行业键白名单 + 边界冲突检测

- 匹配不到白名单键 → 返回 enrich（提示补行业数据），不错误归并
- 油位 vs 液位同会话并发 → 告警提示

### P2：标的锚定日志 + 数据血缘校验

- scheduler 入口打"标的锚定"日志
- Gate 增加"行业键 vs 标的"一致性校验

---

## 五、一句话总结

**2hao 已有最强隔离（进程级），但"行业键模糊匹配"让主题相近的报告可能串数据底座。** 顶级打法（RAG 检索隔离 + MDM 命名隔离）给出的解：**精确匹配优先 + 别名表 + 白名单 + 边界冲突检测**。修 `_infer_industry_key` 一个函数 + 加别名表，就能根治"液位归油位"这类串标。
