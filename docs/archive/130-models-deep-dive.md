# 130 家估值模型深入拆解：对 V51 compute engine 的差异分析

**分析样本**：宁德时代（A股）、美团（港股）、NVDA（美股）三家模型
**对标对象**：V51 `core/compute/valuation/dcf.py` + `models.py`

---

## 一、总体结构对比

### 130 家模型的共同结构

```
Cover（封面）
├── 使用说明 / 假设总表           ← V51 没有
├── 核心业务模型（驱动因子分解）   ← V51 有但输出格式不同

│   └── 量/价/结构三重拆解

│   └── 利润率/周转率假设
├── DCF 估值                      ← V51 有
```

## 二、关键差异点

### 差异 1：缺少"关键假设"独立页面

130 家模型都有**单独的假设总表**——所有可调参数集中在一处，用黄色底色标记，其他所有公式引用这些单元格。

美团模型的关键假设页面（"1. 核心业务模型"）包含：
```
外卖：
  中国餐饮外卖规模（亿）: 2019E 6,144 → 2023E 10,550
  美团外卖份额: 2019E 63% → 2023E 65%
  每单均价: 45 元 → 缓慢增长
  抽佣率: 12% → 14%（逐步提升）

到店酒旅：
  中国到店餐饮规模: 2019E 1,350亿 → 2023E 1,650亿
  美团到店份额: 50% → 55%
  ADR: 430 → 480
```

**V51 的现状**：`WritingBrief` 有 `key_variable` 和 `core_thesis_point`，但没有结构化的"假设树"。计算机的输出是孤立的 DCFResult，没有"如果外卖份额从 63% 降到 60%，估值影响多少"的场景切换能力。

**差距本质**：V51 的 compute engine 是**计算引擎**，不是**财务模型**。计算引擎是给定输入算一个输出；财务模型是"所有假设集中可控，改任何一个假设整表自动重算"。

### 差异 2：WACC 拆解粒度不够

| 维度 | 美团模型 | V51 DCF |
|------|---------|---------|
| 无风险利率 | 3.0%（明确标注来源：美国10年期国债） | 硬编码或从配置读 |
| 股权风险溢价 | 6.0% | 硬编码 |
| Beta | 1.35（与可比公司对标） | 从配置读或默认 |
| 资本结构 | 0（无债）→ 明确 | 计算但输出不够透明 |
| 税后债务成本 | 3.0% | 存在但细节不公开 |
| WACC 结果 | **11.1%**（每一步拆解可见） | 仅输出最终值 |

**差距本质**：V51 的 DCF 在计算上是正确的，但 WACC 的结果缺乏"审计性"。机构分析师看到 WACC=11.1% 时需要检查：Beta 选了多少、无风险利率用的什么、风险溢价取的什么倍数——这些应该与假设在同一张表上。

### 差异 3：敏感性矩阵维度不同

| 模型 | 敏感性矩阵 |
|------|-----------|
| 美团 DCF | WACC × 永续增长率（二维矩阵）→ 输出目标价区间 16-48 港元 |
| V51 DCF | 存在 sensitivity_matrix 字段，但在报告中**作为文本输出而非表格** |

美团模型的敏感性矩阵：

```
            g=1.5%    g=2.0%    g=2.5%    g=3.0%
WACC=9%    45.4      48.2      ---       ---
WACC=11%   32.1      33.2      34.4      ---
WACC=13%   24.2      24.8      25.4      26.1
WACC=15%   19.7      20.1      20.4      20.8
```

这个矩阵的价值在于：**读者一眼看到估值在不同假设下的分布范围**。V51 输出的是一个数字（加权目标价），但这个矩阵才是有经验的分析师真正想看的。

### 差异 4：驱动因子拆解层级

美团模型的收入预测拆解了 4 层：

```
Layer 1: 行业总规模（TAM）
  Layer 2: 在线渗透率 → 在线可触达市场
    Layer 3: 美团份额 → 美团 GMV
      Layer 4: 抽佣率/变现率 → 美团收入
```

每一层都有历史数据验证 + 预测假设 + 明确标注的增长率减速假设。

**V51 当前**：`core/compute/financial/revenue_bridge.py` 有驱动因素拆解，但输出格式是文本段落（收入桥），不是树状的假设-价值对应表。不能做到"改一个底层假设自动重算上层"。

## 三、差距总结表

| 维度 | 130家模型标准 | V51 当前 | 差距等级 |
|------|-------------|---------|---------|
| 假设集中管理 | 所有假设一张表，改任何一个全表重算 | 假设分散在多个模块 | 🔴 大 |
| WACC 审计性 | Beta/无风险利率/ERP/资本结构逐项可见 | 仅输出最终 WACC 值 | 🔴 大 |
| 敏感性矩阵 | 双变量（WACC×g）输出目标价矩阵 | 存在字段但未在报告中表格化输出 | 🟡 中 |
| 驱动因子树 | TAM→渗透率→份额→收入，四层 | 收入桥存在但只有两层 | 🟡 中 |
| 三张表预测 | IS/BS/CFS 联动（利息影响现金、现金影响债务） | 独立的 FinancialSummary，无联动 | 🟡 中 |
| 可比估值 | PE/PB/EV/EBITDA + 行业特定倍数 | PE/EV 已有，但缺少行业特定倍数 | 🟢 小 |
| 历史数据 | 3-5 年历史 + 3-5 年预测 | 缺少 akshare 数据时为空 | 🔴 大（已知） |
| Excel 导出格式 | 投行级配色/布局/假设标记 | .xlsx 导出现有但未格式化 | 🟢 小 |

## 四、对 V51 的具体行动建议

### 建议 1（P1）：新增"假设树"数据结构

```python
# core/models.py 新增
@dataclass
class AssumptionTree:
    """从驱动因子到财务预测的完整假设树。"""
    industry_tam: list[dict]          # [{year, value, growth_rate}]
    penetration_rate: list[dict]      # 在线渗透率
    market_share: list[dict]          # 公司份额
    revenue_model: dict               # 量/价/结构拆分
    margin_assumptions: dict          # 毛利率/费用率预测
    wacc_assumptions: dict            # Beta/无风险/ERP/资本结构
    terminal_assumptions: dict        # 永续增长率/Exit Multiple
```

这个不是让 LLM 生成的——是让 agent+T1+T2a 结构化的。美团那个模型的实际公式全部是 Python 可以复现的确定性计算。

### 建议 2（P1）：升级 DCF 输出为双变量敏感性矩阵

`dcf.py` 的 `compute_dcf()` 已经生成 `sensitivity_matrix`，但在 V51 报告管线中只以文本形式出现。需要：

1. 在 export 模块中将矩阵渲染为表格（markdown + xlsx）
2. 在报告正文中加入"敏感性分析"章节（当前只有 Conviction Matrix 的三情景目标价）

### 建议 3（P2）：建立"假设合理性"对标数据库

从这 130 个模型中提取行业假设分布：

```python
# 美团模型中的关键假设（作为行业中观基线）
假设库 = {
    "外卖行业": {
        "TAM CAGR (2019-2023)": {"均值": "18%", "P25": "12%", "P75": "22%"},
        "在线渗透率": {"当前": "19%", "稳态": "30-35%"},
        "美团份额": {"当前": "63%", "稳态假设": "65-70%"},
    },
    "宁德时代所在的新能源车": {
        "营收CAGR": {"一致预期": "25%", "模型假设": "22-30%"},
        "毛利率": {"当前": "25%", "模型假设": "18-22%"},
    }
}
```

V51 的 Conviction Matrix 在设定 base/bull/bear 概率时，不是拍脑袋——是对照行业假设分布定位自己在哪个百分位。

### 建议 4（P3）：用这些模型做"反向回测"

选择 10 个 2018-2020 年间创建的模型，提取它们的预测值，与实际业绩对比：

```
宁德时代 2020 年某模型:
  预测 2022 年营收 1,800 亿
  实际 2022 年营收 3,286 亿
  偏差 -45%（系统性低估）

→ 训练 V51 的历史校准因子
→ 当 V51 的预测与历史模型的同类预测出现类似偏差模式时自动告警
```

## 五、一句话

> **这 130 个模型的真正价值不是估值方法——V51 的 compute engine 已经实现了那些方法。价值在于"输出标准"和"假设可视化"。一个投行分析师的模型是给人读和改的；V51 的计算引擎是给机器读的。下一步要打通这个——让 V51 输出的东西，一个分析师打开后可以直接修改任一假设、整表自动重算、像真正的财务模型一样工作。**
