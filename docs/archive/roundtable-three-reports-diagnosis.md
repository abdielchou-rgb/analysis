## 二、系统性问题（根在 V51 架构层）

### 问题 1：图表引擎仍在，但三份报告图表=0

这是最刺眼的数据。17 套配色、4 种专业图表、敏感性热力图——全部存在，但三份报告一张图都没用上。根因不在 agent——在 workflow 管线中，`ChartEngine.generate_all()` 依赖 `kp.data_points` 有数字数据。当数据点为 0（非上市企业）或格式不匹配（行业深度），ChartEngine 返回空路径，图表就不生成。**这不是 agent 的错——是管线没有兜底机制**：当数据点不足以生成图表时，系统应该从报告正文中提取数据来补图，而不是跳过图表。

### 问题 2：Style Compiler 对于 AI 免责声明的切除只覆盖了部分模式

三份报告中字节跳动和具身智能都有"本研究基于公开信息和行业调研...不构成投资建议..."——这不是 `_rule_remove_ai_patterns` 检测的"仅供参考"字样，而是一段完整的免责声明。agent 写的免责不是直接用"仅供参考"三个字，而是"本研究基于公开信息和行业调研，所有判断均为作者自身观点，不构成投资建议"。**模式匹配没覆盖到换一种措辞的免责声明。**

### 问题 3：Conviction Matrix 和敏感性矩阵在不同报告中不一致

字节跳动有 Conviction Matrix 但没有敏感性矩阵；茅台有敏感性矩阵但没有 Conviction Matrix；具身智能两者都没有。这说明**研究协议中有要求，但 agent 执行不一致**——不是系统强制要求的。SAC 的 `value` 维度要求"估值"，但没有指定"必须包含敏感性矩阵"。这是 SAC 定义层的问题，不是 agent 层的问题。

### 问题 4：具身智能报告的"数据来源标注"断崖式偏低（仅 2 次）

字节 66 次、茅台 8 次、具身智能 2 次。具身智能报告有大量数字（"2024年出货量将首次突破1,000台""单台成本仍在$50,000-$100,000"）但几乎不做来源标注。**行业深度 SAC 没有"数据来源标注"的强制 evidence_min 要求**——而行业深度报告的数据来源需求比个股更高（个股可以用年报，行业报告需要引用第三方数据）。

### 问题 5：茅台报告字数从原来 3,492 降到了 2,777

之前的茅台报告是完整的，现在上传的这份只有 2,777 字。缺少了财务分析、竞争格局、估值分析等多个章节。说明 agent 没有完整执行 pack 指令的"覆盖全部维度"要求。**约束力链条的中段（pack 指令 → agent 执行）仍然脆弱。**

## 三、执行问题（根在 agent/指令执行层）

### 执行问题 1：AIGC 元数据——agent 100% 写入了禁止内容

三份报告的 YAML frontmatter 都有完整的 AIGC: 元数据块。虽然 Style Compiler 的第 6 条规则 `strip_aigc_metadata` 会在后处理中切除——但 agent 在生成时就写入了禁止内容，说明对 protocol.py 的禁令遵守率为 0%。修复已在 Style Compiler 层完成，但这说明指令层面的约束力为零。

### 执行问题 2：具身智能报告尾部夹带"参考文献"——不符合分析师报告要求

`[1] Goldman Sachs. Humanoid Robot: Investment Implications of the Next Wave of AI. 2024.` 等 10 条学术引用格式。这不是分析师报告该有的结尾——这是学术论文的结尾。风格是"高盛"（pack 指令指定的），但结尾却变成了学术论文体。**agent 没有维持风格一致性。**

### 执行问题 3：三份报告数据来源标注格式极度不一致

字节跳动用 `| 来源标注 |` 表格列，茅台用 `（数据来源：公司年报）` 内联标注，具身智能几乎不做标注。同一个系统、不同的标注格式——说明 pack 指令没有统一规定数据来源的标注格式。**协议中只说"数字自然标注来源"，但没有定义"怎么标"。**

### 执行问题 4：茅台报告日期错误

`2025年7月25日`——应该是 2026 年。agent 没有检查当前日期。

## 四、优化方案

### 系统层（V51 代码修改）

| 优先级 | 优化项 | 改什么 |
|--------|--------|--------|
| **P0** | 图表引擎兜底——当 data_points 不足时从正文提取数字生成图表 | `core/chart_engine.py` 新增 `generate_from_text()` |
| **P0** | Style Compiler 免责声明模式扩展 | `_rule_remove_ai_patterns` 增加 `研究.*仅供.*参考\|不构成投资建议\|市场有风险` |
| **P1** | SAC value 维度增加"必须包含敏感性矩阵"的 evidence_min 要求 | `core/protocol.py` 行业/个股 SAC |
| **P1** | 行业深度 SAC 增加"数据来源标注"的强制要求 | `IND_DIMS` 增加 evidence_min=2 for source |
| **P2** | 数据来源标注格式统一化 | `core/style.py` 增加 `_rule_normalize_citations()` |

### 执行层（pack 指令改进）

| 优先级 | 优化项 | 改什么 |
|--------|--------|--------|
| **P0** | pack 指令统一数据标注格式"（来源：XX）" | `output/pack_*.md` 规则部分增加 |
| **P1** | pack 指令强制要求"每张表/每个数字必须跟来源" | 写入自检清单 |
| **P2** | 增加风格一致性检查——检查末尾是否有学术文献引用 | 自检清单增加 |

## 五、圆桌结语

> **三份报告的扫描数据揭示了一个结构性矛盾：V51 方法论层已经实现 90 分（SAC 覆盖、辩论协议、反方论证），但执行层只有 60 分（AIGC 元数据、免责声明、图表缺失）。这不是 agent 的能力问题——是 V51 的约束力链条在"协议→执行"的接口上断裂了。协议写清楚了，agent 没遵守，系统后处理也没兜住。**
>
> **好消息是：9 个问题中有 6 个可以通过修改 Style Compiler + workflow.py 管线在 1 小时内修复——不需要改架构，只需要把"建议"变成"强制"。**
