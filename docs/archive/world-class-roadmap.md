# 对标世界级报告：缺口分析与推进计划

---

## 第一部分：我还发现了什么新缺口

回顾过去几轮讨论，我意识到之前所有的思考都集中在一个方向上——**让系统的分析能力更强**。但世界级报告之所以是世界级，不止因为分析强。

以下是逐层对标发现的缺口：

### 缺口 1：说服力架构（Persuasion Architecture）

**现状**：系统优化的是正确性——数据准确、结构完整、结论有据。但一份让客户愿意付 10 万美元的报告，不是因为它正确，而是因为它**让人信服**。

**世界级报告的结构弧线**：
```
Hook（第一句话就抓住你）
  → Context（为什么现在讨论这个）
    → Analysis（我们的证据）
      → Counter-argument handling（为什么反对者错了）
        → Conclusion（所以你应该…）
          → Call to action（具体怎么做）
```

**当前系统没有这个弧线设计。** SAC 管论证维度（要覆盖哪些问题），不管叙事节奏（先讲什么后讲什么、哪里该强化、哪里该省略）。

**差距**：不是功能缺失，是设计哲学缺失。系统需要一份 Onion Architecture（洋葱架构）：

```
外层：叙事弧（Hook → Build → Convince → Act）
 中层：SAC 维度（行业/公司/估值各维度）
  内层：数据证据链（每个判断都有数据支撑）
```

### 缺口 2：与共识的对话（Consensus Dialogue）

**现状**：consensus_connector 能拉一致预期数据，但报告里没有一个专门的地方说"市场共识是什么、我们为什么不同"。

**世界级报告的标配章节**：
- **Consensus vs. Our View** 对比表
- **Where We Differ** 明确列出与市场共识的差异点
- **What Would Change Our Mind** 什么情况下我们会改变判断

**当前系统没有这个。** Conviction Matrix 有 consensus_gap 这个信号，但信号没有被结构化成章节。

### 缺口 3：报告结构可配置化

**现状**：所有的报告类型走同一个 SAC 框架。但行业深度报告（40-60页）、公司首次覆盖（20-30页）、业绩点评（3-5页）、行业周报（1-2页）——它们需要的篇章结构完全不同。

**需要的是 Report Blueprint**——每个报告类型对应一个预设的篇章结构模板：

```yaml
# 公司首次覆盖 20页模板
blueprint:
  sections:
    - name: executive_summary
      pages: 1
      must_include: [investment_thesis, key_metrics_table, rating]
    - name: industry_context
      pages: 2-3
      charts: [market_size_trend, competitive_landscape]
    - name: company_analysis
      pages: 5-8
      charts: [revenue_trend, margin_trend, peer_comparison]
    - name: financial_forecast
      pages: 3-4
      charts: [dcf_sensitivity, scenario_comparison]
    - name: risk_factors
      pages: 1-2
    - name: appendix
      pages: 2-3
      content: [methodology, disclaimers, data_sources]
```

没有这个，回测 20 篇报告时每篇结构都不一样，没法横向对比。

### 缺口 4：多期追踪能力

**现状**：系统每次生成报告都是"第一次写这个公司"。但真实分析师的工作是**持续覆盖**——第一期报告建立框架，第二期报告说"上次的判断对不对、什么变了"。

**差距**：没有版本记忆。去年写的宁德时代报告和今年的之间没有关联。在真实场景中，追踪报告的价值 > 首期报告的价值。这件事不做，P3（中金）永远不会把系统当真——因为他的团队 80% 的工作是更新已有覆盖，不是写新覆盖。

### 缺口 5：报告附录标准化

**现状**：系统生成的报告结尾有一个免责声明，但附录内容不完整。世界级报告的标准附录包括：
- 方法论说明（估值方法、数据来源、假设列表）
- 财务模型摘要（3-5年关键财务数据表）
- 风险因素清单
- 术语表
- 评级体系说明

**这些不是可选的，是合规和专业的底线。**

## 第二部分：完整的推进计划

### 总体架构（五轨并行）

```
Track A: 数据与应用          Track B: 分析与洞察          Track C: 风格与表达
━━━━━━━━━━━━━━━━━━        ━━━━━━━━━━━━━━━━━━          ━━━━━━━━━━━━━━━━━━
A1 数据血统+置信度          B1 说服力架构                C1 风格DNA
A2 ChartPlanner            B2 Consensus Dialogue        C2 Executive Summary
A3 图表类型扩展              B3 报告Blueprint              C3 附录标准化
A4 批量提取修复              B4 多层So What链              C4 术语与引用

Track D: 验证与回测          Track E: 生产化
━━━━━━━━━━━━━━━━━━        ━━━━━━━━━━━━━━━━━━
D1 回测报告生产 (20篇)       E1 协作工作流
D2 Prediction Audit         E2 多期追踪
D3 盲测实验                  E3 责任边界
D4 校准曲线校正              E4 部署与监控
```

### 时间线：六个迭代

---

#### Iteration 1（第 1-2 周）：让报告"看起来"像专业报告

**目标**：最小的工程投入，最大的视觉变化——解决"不像专业报告"的问题。

**交付**：
- **A2 ChartPlanner MVP**：5 条必须规则 + 3 种已有图类型（bar/line/pie）
- **A3 瀑布图+龙卷风图**：两个最常用的金融图表类型
- **B3 报告 Blueprint v1**：公司深度报告 20页模板、行业深度报告 30页模板
- **C2 Executive Summary 模板**：第一页结构化输出（投资论点+关键指标+评级）

**验收条件**：
- [ ] 生成一份公司深度报告，包含至少 5 张图表
- [ ] 图表不是事后配的，报告正文明确引用每张图（"如图C1所示"）
- [ ] 第一页有结构化的 Executive Summary
- [ ] 报告的篇章结构符合 Blueprint 预设

---

#### Iteration 2（第 3-4 周）：让数据"值得信任"

**目标**：解决"凭什么相信这些数据"——所有数据可追溯、有时效标注。

**交付**：
- **A1 数据血统**：assumption_db.json 每条记录加 provenance 字段（来源文件/单元格/提取时间/置信度）
- **A1 Conviction 输出改版**：每个假设附加 n_models、data_freshness、staleness_warning
- **A4 批量提取修复**：目标 PE 提取、.xls 文件兼容优化、模板探测自动化
- **B2 Consensus Dialogue 章节**：报告新增"市场共识 vs 我们的判断"对比表

**验收条件**：
- [ ] Conviction Matrix 输出每个假设都标注了样本量和数据时效
- [ ] 报告中有一个专门的"与市场共识对比"章节
- [ ] batch_extract.py 能提取目标 PE
- [ ] 对新文件的提取质量从当前 ~30% 提升到 >50%

---

#### Iteration 3（第 5-6 周）：让报告"有声音"

**目标**：解决"写得太平均"——每份报告有自己的机构 DNA。

**交付**：
- **C1 风格 DNA v1**：writing_dna schema + 3 个初始 profile（中金/高盛/麦肯锡）
- **C1 StyleCompiler writing_dna 执行器**：在报告生成阶段应用风格规则
- **B1 说服力架构 v1**：叙事弧约束（LLM prompt 中加入 Hook→Build→Convince→Act 结构指引）
- **C3 附录标准化**：方法论说明 + 财务模型摘要 + 风险因素清单 + 评级体系

**验收条件**：
- [ ] 同一份数据用不同 profile 生成的报告读起来像不同机构写的
- [ ] 报告结构从"数据堆砌"变成"有叙事弧线"——第一段有 Hook，最后一段有 Call to Action
- [ ] 附录包含方法论 + 财务摘要 + 风险因素 + 评级说明四个部分

---

#### Iteration 4（第 7-9 周）：验证与校准

**目标**：产生第一份可量化的质量证据——回测报告 + 盲测结果。

**交付**：
- **D1 回测报告 20 篇**：覆盖 A 股(8)+港股(6)+美股(6)，选择 6 个月前的事件
- **D2 Prediction Audit Report v1**：Conviction Matrix 概率 vs 实际走势的校准曲线
- **D3 盲测实验**：20 篇系统报告 + 10 篇真实研报，请 3 位分析师盲评
- **B4 多层 So What 链**：从"数据在 P85"→"这意味着偏乐观"→"建议降低 base 概率 5%"→"因为历史上类似情况 70% 未达预期"

**验收条件**：
- [ ] 20 篇回测报告全部使用统一的 Blueprint 结构，可横向对比
- [ ] Prediction Audit Report 显示校准偏差方向（系统偏乐观还是偏保守？偏差多少个百分位？）
- [ ] 盲测实验至少 20 份有效评分，FP4 有第一次定量数据
- [ ] So What 链至少覆盖 3 层深度

---

#### Iteration 5（第 10-12 周）：学习与闭环

**目标**：让系统能记住、能学习、能改进。

**交付**：
- **D4 校准曲线校正**：根据回测结果自动调整 Conviction 概率（如果历史上偏乐观 5%，自动下调 bullishness）
- **E2 多期追踪 v1**：首次覆盖报告 → 追踪报告的数据模型（记录变化、判断更新、新增证据）
- **E1 协作工作流 v1**：Draft/Review/Final 三态 + 版本对比

**验收条件**：
- [ ] Conviction Matrix 概率已经根据历史准确率自动校准
- [ ] 系统能生成"追踪报告"——相比上次覆盖，判断变/没变、为什么
- [ ] 支持草稿→审阅→终稿三态流转

---

#### Iteration 6（第 13-16 周）：生产化与边界

**目标**：达到可署名的专业级质量。

**交付**：
- **E3 责任边界**：版本水印 + 人类复核 checkpoint + 错误率公开基准
- **E4 部署与监控**：API 接口、请求日志、性能监控
- **C4 术语与引用标准化**：自动术语表 + 规范脚注格式
- **B1 完整说服力架构**：Onion Architecture 完整实现（外层叙事/中层SAC/内层数据）

**验收条件**：
- [ ] 系统支持 API 调用，可嵌入团队工作流
- [ ] 每份报告有唯一版本标识，可追溯"是谁在哪个版本上做了什么修改"
- [ ] 公开发布错误率基线（如"Conviction 方向准确率 72%，行业分布校准误差 +3pp"）
- [ ] 说服力架构完整：Hook→Context→Analysis→Counter-argument→Conclusion→CTA

### 资源估算

| 迭代 | 工作量 | 新增代码 | 主要风险 |
|------|-------|---------|---------|
| I1 | 5-7 人天 | ~600 行 | ChartPlanner 与现有 workflow 的集成 |
| I2 | 5-7 人天 | ~400 行 | batch_extract 修复需要大量测试 |
| I3 | 7-10 人天 | ~800 行 | 风格 DNA 的效果评估比较主观 |
| I4 | 10-15 人天 | ~300 行 + 大量人工 | 回测报告撰写 + 盲测组织最耗时 |
| I5 | 7-10 人天 | ~500 行 | 多期追踪的设计比较复杂 |
| I6 | 7-10 人天 | ~500 行 | 责任边界的商业/法律层面非纯技术 |

**总计：约 45-60 人天，约 3000 行新增代码。**

### 关键里程碑与决策点

```
Week 2:  第一份带 5 张图 + Executive Summary 的完整报告
          ↓ 如果质量不合格 → 回退到修复基础能力

Week 4:  数据可追溯性上线 + 市场共识对比章节
          ↓ 如果数据血统验证通过 → 进入风格层

Week 6:  第一份有机构DNA的报告诞生
          ↓ 如果风格差异可感知 → 进入验证层

Week 9:  第一份 Prediction Audit Report 出炉
          ↓ 如果校准偏差可测量 → 进入学习层

Week 12: 系统能生成追踪报告 + 自动校准概率
          ↓ 如果循环闭合 → 进入生产化

Week 16: 达到可署名的专业级质量
```

---

### 迭代评估规则

每个迭代结束时有一道**是否继续的阈值判断**：

```
如果当前迭代的交付在内部评审中得分 < 6/10：
  → 不做下一个迭代
  → 修复当前迭代的问题再继续

如果得分 6-7/10：
  → 继续下一个迭代，但当前迭代的修复项排入 backlog

如果得分 > 7/10：
  → 正常进入下一个迭代
```

## 第三部分：一句话

> **之前我所有的分析都围绕"让系统更聪明"——数据更多、分析更深、图表更丰富。但对标世界级报告后，我发现真正缺的不是分析能力，而是"说服力架构"和"生产化标准"。系统能不能写一份有叙事弧线、有与共识的对话、有多期记忆、有标准化附录的报告——这些才是从"分析工具"到"专业服务机构"的跃迁。以上 6 个迭代、16 周的计划，就是一次完整的跃迁路径。**
