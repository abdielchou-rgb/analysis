# 1号分析师 V51 优化方案（总合成）

**基于**：
- FP1–FP4 顶层宪法（图灵测试是终极裁决）
- 6 方机构圆桌评价
- 9 个 investment-tools 项目的 Ultra Think
- 644 行风格指纹与回测基准方案
- 审计报告 + design-rationale（F1/F2/F3）
- 当前代码库的实际状态

---

## 零、一个事实判断

**V51 当前的处境是：方法论 90 分、写作 85 分、洞察 60 分、数据 65 分。**

这在投资工具赛道里是一个罕见的分布——方法论文档驱动这个方向在全球范围内做得最早最深，但洞察和数据拖后腿到了不可忽视的程度。

**FP4（图灵测试）给出了终极标尺：不是"看不出是 AI"，而是"看起来就是十年以上的资深分析师"。** 每一个优化动作都必须通过 FP4 的检验：这件事做了，离通过图灵测试更近还是更远？

---

## 一、架构诊断：五个结构性矛盾

### 矛盾 1：T0.5（假说验证）是空壳

V51 的架构文档（design-rationale §方向五）写得清清楚楚：T0.5 是"写之前先想清楚"的关键节点。但实际实现中，T0.5 只有一个占位的 HypothesisVerifier，输出是空壳。agent 拿到系统后，没有被强迫进入"先验证假说再写报告"的工作流。

**FP4 检验**：一个十年以上的分析师不会在不确定的时候硬写报告。他会先问："手上有什么证据支持这个判断？有什么反对？还需要什么数据？" 没有 T0.5 的系统在这一点上就不像人。

### 矛盾 2：Devil's Advocate 是事后自审，不是事前辩论

当前 Devil's Advocate 是 agent 写完报告后自己给自己挑错。这是"写→查"的逻辑（违反 F2），不是"想→验证→写→改"的逻辑。一个人可以自己挑错，但效率远低于两个独立的人面对面辩论。

**FP4 检验**：资深分析师不会等报告写完了再找反方——他在形成判断的过程中就会主动寻找反对证据（"如果这个判断错了，最可能因为什么？"）。TradingAgents 的 Bull/Bear 独立辩论是对这个行为更逼真的模拟。

### 矛盾 3：Conviction Matrix 没有数据根

Conviction Matrix 的概率分配全靠启发式（base 55%, bull 20%, bear 25%），没有历史回测校准、没有一致预期对标。这是 FP2（数据不能有任何错误）的直接违反——因为一个没有数据支撑的数值本身就是一个错误。

**FP4 检验**：资深分析师给的 target price 可以错，但不会没有逻辑根。当前的 Conviction Matrix 看起来像分析师给了目标价，但稍微认真看就会发现概率分配经不起质问。

### 矛盾 4：CognitiveBaseline 有数据库无回路

CognitiveBaseline 有完整的 data model、持久化存储、prediction_history——但它只记录不反馈。预测写进去了，6 个月后没有人回头看。EditCase 也是同样的情况：修改记录持久化了，但从不影响下一次生成。

**FP4 检验**：资深分析师的标志不是判断力永远不会错——是犯了错之后会修正认知（"上次我对这个变量的判断错了，这次我调整了我的框架"）。CognitiveBaseline 只写不读，不满足这个条件。

### 矛盾 5：去 AI 化做的是负面检查，不是正面认证

当前的去 AI 化策略是"检查 AI 痕迹并移除"——Style Compiler 的 3 条规则、反 AI 指纹库、protocol.py 的 11 条禁令，全部是负面检查。FP4 要求的是：系统不是"看不出来是 AI"，而是"看起来就是人"。

**FP4 检验**：一个从来不承认自己不确定、从来不引用过往经验、从来不使用隐喻和类比的分析师，即使每一句话都不像 AI，整体读下来还是不像人。

## 二、三个战略选择

### 选择 1：做什么类型的产品？

| 选项 | 对应 FP | 理由 | 反对理由 |
|------|--------|------|---------|
| **写作系统**（输入→报告→交付） | FP1 已实现 | 当前就是 | 洞察不足，FP4 过不了 |
| **决策系统**（假说→辩论→信号→仓位→回测→学习） | FP2 + FP4 | 图灵测试的分析师是做决策的不是写文章的 | 工程量大，1-2 年 |
| **回答系统**（问一个问题→给出分析判断+证据） | FP4 | 分析师的工作流是"问问题"多于"写报告" | 产品形态不确定 |

**我的判断**：在 FP1（写作系统）的底座上，用"决策系统"的方向做优化。不丢掉写作能力（这是 FP1 的承诺），但补齐洞察、辩论、回测、学习这四个写作上游环节。最终形态是"一个在 agent 上运行的、能写能想能学的分析师"。

### 选择 2：先补数据还是先补洞察？

审计报告说"数据 P0"，圆桌说"洞察 P0"，风格指纹方案说"风格指纹 P0"。三者的依赖关系是：

```
数据 → 洞察 → 写作 → 风格检查 → 回测 → 学习
        ↑ (没有数据，洞察就是空谈)
                     ↑ (没有洞察，写作漂亮也没内容)
```

数据是洞察的前提，洞察是写作的前提。**数据优先是唯一正确的顺序。** 但数据管线建设有外部依赖（数据源接入、合规、权限），不能等全部就绪再做洞察。两条腿一起走：先用手动/半自动方式收集分析师需要的核心数据补齐 T0.5，同时建立与数据源的技术接入。

### 选择 3：单 agent 还是多 agent？

**保持单 agent。** V51 的架构已经做了正确的事情——T2a（论证引擎）是确定性 Python，T2b（行文引擎）是 LLM，计算与生成分离。多 agent 在当前阶段增加的是复杂度而非价值。瓶颈不在 agent 数量，在 agent 能访问的数据质量和工具链。

但是，TradingAgents 的 Bull/Bear 辩论结构值得做一个**局部的辩论协议**——同一 agent 被要求**扮演两个独立角色并依次输出**（先 Bull 出完整的看多逻辑，再 Bear 出完整的看空逻辑），而不是"写一份报告然后给自己挑错"。这个不需要多 agent，只需要修改研究协议中的 Devil's Advocate 部分。

## 三、优化方案（分三层，接地线）

### Layer 1：修复"写"环节——写得像人一样（4-6 周）

目标：解决矛盾 5（去 AI 化是负面检查）。让 agent 第一次生成的文本在 FP4 的初步检查中达到"不让人一眼看出是 AI"。

| 编号 | 项目 | 当前状态 | 目标状态 | 关键动作 |
|------|------|---------|---------|---------|
| **L1-1** | 写作指令注入"人感"DNA | 研究协议（protocol.py）只有规则没有正面引导 | 在协议的 Writing Rules 中加入"正面示范"——不仅告诉 agent 不能做什么，还给一个十年资深分析师的真实写作样本做 reference | protocol.py 的 to_agent_brief() 加入"写作风格参考样本"段落（约 300 字范文），包含：不确定性表述的自然方式、经验引用的句式、数据可信度判断的措辞 |
| **L1-2** | Devil's Advocate 升级为辩论协议 | 事后自审（"写完后换位为买方研究员"） | 事前独立看空逻辑（"写正文前，先独立输出一份 300 字的 bear case，包含完整逻辑链和证据"） | T2 行文引擎的 prompt 中加入：先写 bear case → 再写 bull case → 再合并。bear case 和 bull case 在 prompt 中先后独立而非交叉 |
| **L1-3** | 反 AI 指纹库 P0 级（12 项自动切除）+ 3 项正面增强 | 仅靠 protocol.py 的 11 条禁令 | 12 项 P0 级自动切除 + 3 个"人类感"正面指标（经验引用、不确定性精确限定、类比/隐喻自然出现） | 新增 core/ai_fingerprints.py，12 项正则 + 3 项正面检测。Style Compiler 在 T2b 后运行 |
| **L1-4** | 智能跳过 SAC 清单体结构 | 当前 SAC Gate 检查维度覆盖时，维度标题在报告中出现的风险 | SAC Gate 改为后置审计（检查论点类型而非章节标题匹配）。论证引擎输出的 section 不包含"维度名称" | core/argument.py 修改 section 的 position 映射：去掉维度 ID 作为标题的回退逻辑 |

**FP4 增量**：L1-1 到 L1-4 完成后，随机抽一页读下来，不容易产生"这不是人写的"直觉。

### Layer 2：补齐"想"环节——让系统地思考（6-10 周）

目标：解决矛盾 1（T0.5 空壳）和矛盾 2（Devil's Advocate 不够深）。这是从"写作工具"到"思考伙伴"的关键一跃。

| 编号 | 项目 | 当前状态 | 目标状态 | 关键动作 |
|------|------|---------|---------|---------|
| **L2-1** | T0.5 假说验证器 MVP | 空壳 | 输入假说 → 输出支持/反对/缺口/类比四块内容的 500 字验证报告 | 1）study prompts 模块读取已有研究报告和公开市场观点 → 2）提取支持/反对论点 → 3）标识数据缺口 → 4）输出分歧地图 |
| **L2-2** | Bull/Bear 辩论协议 | 无 | 每份报告在 T1 知识包之后、T2 行文之前，先输出 Bull Case 和 Bear Case 两份独立论点清单 | workflow.py 中增加一个 step：`generate_viewpoints()`→输出 `ViewpointPair(bull=Viewpoint(...), bear=Viewpoint(...))` → 进入 T2a 论证引擎 |
| **L2-3** | Conviction Matrix 符号级升级 | 启发式概率（55/20/25） | 至少加入一个外部信号校准（如一致预期偏离度），概率分配有可追溯的根 | core/conviction.py 中新增 `calibrate_probabilities()`：如果有一致预期数据则用偏离度校准；如果无则输出带警告的"信噪比不足"状态而非假精确数字 |
| **L2-4** | 稀缺性信号词库 MVP | 无 | 当 SAC 特定维度（如行业深度分析的竞争格局）被激活时，自动注入瓶颈视角的判断词库 | 从 Serenity 的 9 大瓶颈原型中提取粒度最粗的 4 类（资源独占 / 技术代差 / 规模壁垒 / 时间窗口），在行业深度 SAC 的 comp 维度引入信号词检查 |

**FP4 增量**：L2-1 到 L2-4 完成后，agent 在写报告之前经过了"验证假说→辩论→校准信号→注入稀缺性判断"四个步骤。系统产出的不是"模板填充"，而是"经过思考的产物"。

### Layer 3：封闭"学"环节——让系统越用越好（8-12 周）

目标：解决矛盾 4（CognitiveBaseline 只写不读，EditCase 不闭合）。这是 F3 的实现——修改学习是唯一的不可复制的护城河。

| 编号 | 项目 | 当前状态 | 目标状态 | 关键动作 |
|------|------|---------|---------|---------|
| **L3-1** | 时序验证 MVP | CognitiveBaseline 有 prediction_history 但"只看不回看" | 报告生成后 6 个月自动触发"回头看"——读取历史 prediction，对比实际结果，写入准确率 | 新增 core/temporal_verifier.py：1）读取 prediction_history → 2）根据实际数据计算 PredictionAccuracy → 3）写入 validation_history → 4）若准确率 < 0.5 标记 active_hypotheses 为"需重新检验" |
| **L3-2** | EditCase 闭合 MVP | 修改记录写入 SQLite，但生成侧从来不用 | 当同类场景再次出现时，T2b 的 prompt 中注入一条"场景匹配的历史修改建议" | core/edit.py 新增 `get_suggestions_for_scenario()` → 按 report_type + section_type 匹配 Top 3 EditCase → 注入 T2b prompt |
| **L3-3** | Conviction Matrix 回测校准 | 无回测校准 | 系统积累 10+ 条 prediction_history 后，用历史命中率校准概率分配 | core/conviction.py 新增 `historical_calibration()` → 计算过去同类判断的准确率 → 调整 base/bull/bear 概率的默认值 |
| **L3-4** | 对标库初始化 | benchmark 1 篇产出 vs 2 篇真实研报 | 至少 10 份真实券商研报的同指标基线值 | 收集可公开获取的券商研报（5 份国内 + 5 份国际），按 D1-D8 维度打分，建立基线 |

**FP4 增量**：L3-1 到 L3-4 是 FP4 的终极测试场景。一个持续积累的系统和一个从零开始的系统在 6 个月后的质量差距——前者会越来越像人，后者不会。

## 四、不做清单

| 不做什么 | 为什么 |
|---------|--------|
| **事件驱动机制**（财报日历订阅→自动触发分析管线） | 依赖数据管线先就绪。现在做是做空中楼阁，Prefect 调度是最轻松的部分，数据源接入和模板适配才是大头 |
| **Interactive Mode（一问一答）** | 审计报告已做过这个结论，我认同：T0.5 假说验证器覆盖了"问一个问题"的核心场景，不需要单独的交互模式 |
| **多 agent 架构** | 瓶颈不在 agent 数量，在 agent 能访问的数据质量。两个 agent 配坏数据不比一个 agent 好 |
| **Quarto PDF 导出** | L1/L2/L3 全部优先于排版优化。排版是最后一公里的事——先让路通了再修路 |
| **P2 级反 AI 指纹（跨风格差异 6 项）** | 维护成本 > 收益。6 项跨风格差异不值得引入条件路由的复杂度 |
| **叙事弧线百分比分配** | 违反设计原则 4（深度来自批判循环，不来自前置规则）。做软指导不做硬约束 |
| **8 风格 × 10 维矩阵的全部精确数值** | 当前无数据支撑这些数值（文档自身在 R3 也承认了）。保留框架，数值标为"待校准" |

## 五、三维评分预期提升

| 维度 | 当前 | L1 后 | L2 后 | L3 后 | 终局目标 |
|------|------|-------|-------|-------|---------|
| 写作（结构/去AI/风格） | 85/100 | **88/100** | 88/100 | **90/100** | 95/100 |
| 洞察（判断锐度/分歧深度/反方） | 60/100 | 65/100 | **75/100** | **82/100** | 90/100 |
| 数据（来源/交叉验证/缺口） | 65/100 | 65/100 | **70/100** | **75/100** | 85/100 |
| 学习（预测跟踪/修改闭合/回测校准） | 0/100 | 0/100 | 0/100 | **55/100** | 85/100 |

**FP4 验收标准**——每一层完成后做一次双盲测试：
- L1 后：随机抽取 3 页报告，让 3 个有 5 年以上经验的分析师判断是人写还是系统写。**目标：不被 100% 识别为 AI。**
- L2 后：完整的 15-20 页报告，双盲判断。**目标：50% 以上判断为"不确定"或"人类"。**
- L3 后：完整报告 + 持续跟踪的预测记录。**目标：70% 以上判断为"人类"。**

## 六、一句话

> **V51 已经有了全世界最好的分析师写作方法论。下一步不是让它写得更好——是让它想得更深、学得更快、假得更像真的。FP4 给出了唯一正确的标尺：如果系统产出的报告不能让一个资深分析师在双盲条件下说"这是同行写的"，那就不是 1 号分析师的目标状态。**
