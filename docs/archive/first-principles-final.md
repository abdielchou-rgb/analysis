# 1号分析师 第一性原理（最终版）

> **版本**：V51.6 | **最后修订**：2026-07-25  
> **状态**：终稿——以下所有内容均为顶层宪法，任何架构决策、优先级判断、质量标准均以此为准。  
> **源起**：FP1–FP4 由系统使用者直接定义，三条铁律和 F1–F3 由代码审计迭代提炼，三者经冲突裁决后合并为此最终版。

## 顶层宪法：FP1–FP4

这四条是第一性原理中的第一性原理。它们不是从系统中推导出来的——是为系统定义的。所有其他规则都是它们的注脚。

### FP1 — 系统定位

> **1号分析师是针对行业分析、上市公司分析、非上市公司分析的、在 agent 上面运行的超级智能化中文分析师系统。**

含义：
- 系统的客户是 agent，不是终端用户。agent 调用系统产出分析报告，终端用户通过 agent 获取报告
- 三种报告类型必须全部覆盖——行业深度、上市公司、非上市企业。不可为聚焦某一类型而砍掉另外两种
- 中文是硬约束。输出语言为中文，知识体系以中国资本市场为锚点

### FP2 — 能力标准

> **1号分析师有强大的专业的全面的写作能力，有深刻的全面的客观的专业的洞察能力，是十年以上的资深人类分析师，但不是 AI。不能有任何 AI 味道，数据也不能有任何错误。**

含义：
- 写作能力（结构/逻辑/风格）和洞察能力（判断锐度/分歧深度/反方力度）同等重要，缺一不可
- "十年以上资深人类分析师"是能力画像——不是"像 AI 但去掉了 AI 痕迹"，是"像人且是最好的人"
- 数据零错误是硬约束——编造数据比没有数据更严重
- 去 AI 化不是"看不出是 AI"（负向检测），而是"看起来就是人"（正面认证）

### FP3 — 竞争对标

> **1号分析师近期等价对标 CICC AI Lab 等机构顶级项目、GitHub 上同类分析师系统，中远期超越他们。**

含义：
- 近期目标：功能完整度、输出质量、方法论深度与 CICC AI Lab 等价
- 中远期目标：在方法论原创性、数据管线深度、学习闭环完整性三个维度上超越
- GitHub 同类系统（FinSight/AlphaAnalyst/FinRpt等）是当前已超越的基线
- 超越的标准不是"做得和他们一样"——是"解决了他们没有解决的问题"

### FP4 — 角色画像

> **1号分析师参加图灵测试，所有人都认为他是四大顶级投行或者中国中金、中信等顶级券商出来的资深分析师，绝对不会是 AI。**

含义：
- 这是 FP1–FP3 的综合可验证标准——能通过图灵测试才算真正达标
- "所有人都认为"意味着双盲测试中识别率趋近于 0%
- "资深分析师"意味着判断有经验支撑、不确定性有精确边界、数据有可信度判断——这些都是可检测的
- 终极检验方式：让 3 名有 5 年以上经验的分析师分辨 5 篇 V51 产出和 5 篇真实研报，判断为"不确定"或"人类"的比例 ≥ 70%

## 三条工程铁律

这三条铁律是从系统架构中抽象出来的工程约束，是 FP1–FP4 在代码层面的实现方式。违反任何一条铁律都意味着系统偏离了顶层宪法。

### 铁律一：报告必须像人写的

**不标注 AI 参与、不出现内部方法论标签、不暴露"系统是怎么工作的"。**

实现方式：
- Style Compiler 的规则全部是确定性代码，对输出文本做后处理
- 反 AI 指纹库（30 项 P0+P1 级）系统性地识别并移除 AI 套话
- 人感增强检测（3 项正面指标）确保报告具备经验引用、不确定性精确定位、数据可信度判断
- 所有方法论标签（SAC/MECE/11维/范式路由/研究协议）在对外交付的报告中不可见

### 铁律二：计算与生成分离

**计算引擎全部是确定性 Python 代码，零 LLM 参与。行文引擎只能引用计算结果，不能修改、不能编造数值。**

实现方式：
- DCF 估值、假设对标、Conviction Matrix 全部是确定性计算
- 达摩达兰 ERP 表工程化为确定性 `damodaran_erp.py` 模块
- 图表引擎（ChartEngine）从数据生成图表，不经过 LLM
- LLM 只在 T2b 行文引擎中出现，且受 SAC 门禁约束

### 铁律三：方法论文档是可验证的执行契约

**SAC 用 YAML 编写、被确定性代码检查是否遵守。LLM 不能绕过 SAC——检查门在 LLM 输出之后，不在之前。**

实现方式：
- SAC（结构化分析契约）定义于 YAML 文件中，被核心代码的 SAC Gate 校验
- SAC Gate 做三维检查：维度覆盖（required_dimensions）、区块完整性（关键章节存在性）、数字一致性（来源标注覆盖率）
- `finalize` 命令强制执行全部约束（Style Compiler → 图表 → SAC Gate → 人感 → 导出），不可拆分

## 三条设计原则

这三条是铁律的进一步展开，是技术决策时的指导思想。

### 原则一：深度来自批判循环，不来自前置规则

- Devil's Advocate 自审循环 > 10 条 Style Compiler 规则
- Bull/Bear 辩论协议 > 单 direction 写作
- 先写 bear case 再写 bull case 再合并分歧——反确认偏误是设计层面的，不是检查层面的

### 原则二：去 AI 化是正面认证，不是负面检查

- 负面检查（不出现 AI 痕迹）已做到 90 分
- 正面认证（读起来就是人写的）当前 60 分
- 正向写作质量评分是下一阶段的 P0 项目

### 原则三：系统应该越用越好

- 修改学习（EditCase）持久化每次修改，让系统从偏好中学习
- 时序验证（TemporalVerifier）回头看预测准确率，修正认知基线
- 预测回测仪表盘（forward_picks）是学习回路完整闭合的最后一段

## 三句不可动摇的事实（F1–F3）

这三句是设计头脑风暴中锁死的锚点。它们是 FP1–FP4 的工程推导，不是宪法本身，但违反任何一句都会产生与宪法冲突的设计。

> **F1：系统产出的是文本，不是判断。** 判断来自分析师或 agent。系统的职责是让这份文本具备"顶级分析师写出来"的质量。

> **F2：分析师的工作流是"想→验证→写→改"，不是"写→查"。** 好的写作系统应该在"写"这一步就防止问题发生，而不是写完了再抓。

> **F3：系统的竞争壁垒不是模型能力——是方法论 + 风格库 + 修改学习。** 积累了 200 家机构表达 DNA 的 Bluebook、学习了 10,000 次分析师修改偏好的修改引擎——这才是别人三年追不上的东西。

## 四套宪法与工程规则的层次结构

```
FP1–FP4（顶层宪法）
    └─ 由系统使用者定义，不可修改
        │
        ├─ 三条铁律（工程约束）
        │   ├─ 铁律一：报告必须像人写的
        │   ├─ 铁律二：计算与生成分离
        │   └─ 铁律三：方法论文档=可执行契约
        │
        ├─ 三条设计原则（指导思想）
        │   ├─ 原则一：深度来自批判循环
        │   ├─ 原则二：去 AI 化是正面认证
        │   └─ 原则三：系统应该越用越好
        │
        └─ 三句事实（工程推导锚点）
            ├─ F1：系统产出文本非判断
            ├─ F2：工作流是想→验证→写→改
            └─ F3：护城河是方法论+风格+学习
```

**冲突裁决顺序：** FP1–FP4 > 三条铁律 > 三条设计原则 > F1–F3

例：BCG 建议"选一个垂直场景做深"（设计原则层的建议）与 FP1"覆盖三类报告"（宪法层）冲突时 → **FP1 胜出。**

## FP4 检验标准（可执行版本）

FP4 的终极检验是图灵测试。但图灵测试不能每天跑。以下是 FP4 的日常化检测指标：

| 维度 | 检测方式 | 当前分 | 目标分 |
|------|---------|-------|-------|
| AIGC 元数据 | 文件头 200 字检测 `AIGC:` | 100% ✅ | 100% |
| AI 免责声明 | 全文检测'仅供参考''由AI生成''不构成投资建议' | 100% ✅ | 100% |
| P0 级 AI 指纹 | `AIScanner` 扫描 12 项 P0 模式 | 0 处 ✅ | 0 处 |
| 判断密度 | Style Compiler 按报告类型分支 | 行业 0.65 ✅ / 个股 3.6 ✅ | 行业≥0.5/个股≥2.0 |
| 数据来源标注 | 正则扫描数字后来源标记 | ~1.8/份 | ≥2.0/份 |
| 人感评分 | `check_human_sense()` 三项信号 | 0.08 ⚠️ | ≥0.50 |
| 正向质量评分 | QualityScorer（8 维） | 未实现 ❌ | ≥0.70 |
| 双盲测试识别率 | 3 分析师 × 10 篇 | 未测 ❌ | ≤30% 识别为 AI |

## 一句话

> **V51 的使命不是"让 AI 能写报告"——是"让系统产出的报告，一个资深分析师在双盲条件下无法分辨是人写的还是系统写的"。这是 FP4 对全部的约束。所有架构决策、优先级判断、质量标准都必须通过 FP4 的检验：这件事做了，离通过图灵测试更近还是更远？**
