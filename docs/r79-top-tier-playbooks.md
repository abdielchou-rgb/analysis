## 二、逐项顶级打法详解

### 2.1 激励倒挂——评估与生成解耦

**顶级打法**：Goodhart 定律治理的核心是**"指标必须锚定不可游戏化的真实目标"**。

**行业实践**：
- **Anthropic/OpenAI 的 eval 方法论**：不用单一可刷指标，而是用"eval 集 + 黄金标准 + LLM-as-judge 交叉评审"。判断质量由独立 judge 模型评估，而非规则正则。
- **Google 的"指标分层"**：表面指标（字数/关键词）只做下限，真正质量看"人类评估等价物"（如 helpfulness/honesty 评分）。
- **Rubric 化评估**：写评估 rubric（好判断的标准定义），让 judge 模型按 rubric 打分，而非数关键词。

**2hao 落地**：
- 判断质量不用"数判断词"，用 **LLM-as-judge + rubric**：定义"好洞察 = 非显而易见 + 可证伪 + 有数据锚点 + 有信息增量"，让对侧 provider 按 rubric 打分
- 生成端与评估端用不同模型（已有对侧 provider 基础，扩展到写作质量）

### 2.2 模板套话——语义去重 + 生成端约束

**顶级打法**：
- **DeepMind 的语义去重**：不只查字面重复，用 embedding 查**同义变体**（"这一趋势若被证实"vs"若该趋势兑现"语义相同）
- **约束生成（Constrained Decoding）**：生成时用负向约束（ban-list + 语义相似惩罚），让 LLM **一开始就不产出**模板句
- **改写即成本**：对模板句，LLM 必须改写为具体论证才能通过，否则继续迭代

**2hao 落地**：
- 模板黑名单升级为 **embedding 语义黑名单**（本地 sentence-transformers），查同义变体
- section_writer prompt 加"禁止以下句式结构"（不是禁止字面，是禁止结构）
- Gate 拦截后**强制局部重写**（已有 `_locate_failed_segments` 基础）

### 2.3 数据溯源——数据契约 + 血缘 + 无依据不写

**顶级打法**：
- **LSEG（伦敦证交所）**："licensed data + provenance + no-training rule"——每个数据点必须有授权来源、可追溯血缘、禁止凭空生成
- **dbt/Great Expectations**：数据契约（schema + freshness + 对账），表字段必须有血缘 lineage，无 source 的字段视为违约
- **数据分级标注**：世纪证券"数据分级 + 真实性追溯"——A 级=官方披露，B 级=权威第三方，E 级=估算（必须带估算依据），F 级=预测（必须带模型）

**2hao 落地**：
- enrich-file 数据契约已有（R78），扩展：**每个 E 级数据必须有"估算依据"字段**，无依据的 E 级视为违约
- 报告引用数据时，溯源到"哪个表哪个字段哪个来源"，而非一个孤立的 (E)

### 2.4 交付脆弱——唯一出口 + 端到端验证 + 降级显式化

**顶级打法**：
- **CI/CD 理念**：构建产物必须通过全部检查才能发布，任何环境缺失**显式失败**而非静默降级
- **Temporal durable execution**：长任务状态可恢复，失败重试不重头（2hao 已有 checkpoint）
- **金丝雀验证**：交付前自动验证产物质量（PDF 是否含图、docx 是否无空段、页数是否合理）

**2hao 落地**：
- export_report 唯一出口（已有 R78），补**产物验证**：PDF 大小/图片数、docx 空段率、页数，未达标准报错
- 环境依赖（LibreOffice）缺失 → **显式阻断 PDF 导出**，不降级

### 2.5 打地鼠迭代——总编辑 + 复盘闭环

**顶级打法**：
- **主编制（高盛/麦肯锡）**：初稿后由主编**一次整合**——统一口径、删套话、调详略、补判断。不是逐项打回，是一次到位
- **Post-mortem 文化**：每次失败沉淀为"防再犯机制"，不是"修一个 R 号"
- **单次写对（First-time-right）**：通过更强的生成约束减少迭代轮数，而非靠 Gate 打回

**2hao 落地**：
- `_global_edit` 节点（总编辑）一次整合全文
- roundtable-backlog 沉淀机制，问题必须映射"防再犯"才关闭

## 三、顶级机构的报告生产流程（对标）

**高盛/中金深度报告生产流程**：

```
分析师初稿 → 主编整合（统一口径/删冗余/调结构）→ 合规审查（数据溯源/利益冲突）
→ 编辑校对（排版/图表随文）→ 终审发布
```

**2hao 应有流程**：

```
LLM 分段生成 → _global_edit 总编辑整合 → IronGate 全量门禁（含 LLM-as-judge 洞察评估）
→ export_report 唯一出口（含产物验证）→ 四件套发布
```

## 四、核心洞察一句话

**顶级打法的共性：把"事后检查"改为"事前约束 + 事中生成端引导 + 事后独立评估"三层，而不是单一的事后正则拦截。**

- 事前：prompt 约束（反方三段式/数据无依据不写）
- 事中：生成端 semantic 约束（禁止模板结构）
- 事后：独立 judge 评估（LLM-as-judge rubric）+ 产物验证

2hao 目前只有"事后正则拦截"一层，所以打地鼠。补齐前两层是根本解法。
