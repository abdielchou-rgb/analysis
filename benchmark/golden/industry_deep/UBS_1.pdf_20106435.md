## Model setup and variables included

Our objective is to build a model that can predict whether the S&P 500 will move up 5% or down -5% over the next month. To do this we set up and defined the dependent variable as a multi-classification problem - 0: between +/-5%, 1: <-5%, 2: >+5%.

The next step in the model development process is variable selection. One of the major benefits of XGBoost is that it's robust to including irrelevant features. Although too many variables can still risk the model learning spurious patterns, we can include a large number of variables and XGBoost will determine which variables are important while ignoring the irrelevant features. This allows us to include a large number of variables without making any pre-determined decision beforehand and test a large number of transformations such as 1m, 3m and 6m chg as well as the change in change.

We originally started with \~100 variables (with data going back to 2002) before narrowing it down to our final selection of 30. To whittle down the number of variables we used SHAP to identify variable importance and remove irrelevant and non-important features. Our final selection of variables includes factors around economic activity, earnings momentum, rates, inflation, volatility, positioning and options.

In order to ensure that our model was not over fitting, we split our data into train (2002- 2017), validation (2017-2020) and test (2020-2022) periods. The model was originally fitted on the training set, and the validation data was used to refine the hyperparameters (parameters that help with the model learning process). The enhanced model was then used on the test data to ensure the relationships the model learned appear consistent through time.

## A brief overview of XGBoost

XGBoost (Extreme Gradient Boosting) is a machine learning technique which follows the principles of decision trees and is a very flexible, versatile and commonly used method with the ability to tackle a wide range of problems. Below we explain XGBoost in a little bit more detail by looking at the evolution of different tree-based algorithms:

Decision trees: The foundation of XGBoost is decision trees. A decision tree asks a series of questions - such as, is the ISM > 50, etc. - to come to a final decision. To start a decision tree we must know what question to begin with (i.e. which variable to choose). Simplistically, the process takes every variable and every possible value of that variable and decides which criteria provides the best split. The best split is the one where the purity of the node is highest (i.e. in our example, the criteria which separates all the times that equities fall by more than 5% or not). This process is repeated on each newly partitioned data until we can no longer improve our prediction.

Gradient boosting: The problem with decision trees is that they are inherently bad predictors. To overcome this we start "boosting" the model by combining our weak decision tree with other decision trees in the hope we get a collectively better model. To enhance the model's predictive process the decision trees work as a team, where each subsequent decision tree is fit to try and predict the error terms of the original model (i.e. learn where the previous model went wrong). This process is repeated many times - the second decision tree corrects the first decision tree, the third decision tree predicts the errors from provided by the first and second decision tree. In order to reduce the errors, the model's objective is to minimize a loss function using gradient descent.

XGBoost: XGBoost sits within the the gradient boosting family but is more scalable and more accurate. The eXtreme component comes from its slightly different algorithm which helps control over-fitting (by adding a penalty for additional model complexity) and is more computationally efficient. XGBoost has become a key and widely used algorithm in machine learning due to its success and accuracy.

## FAQ on XGboost:

\- How does multicolinearity impact XGBoost? The inclusion of correlated variables shouldn't impact the performance of the model significantly, particularly compared to OLS regressions. For example, if you have 2 variables which are highly correlated when deciding upon a split in a tree the model will only choose one of them, whereas an OLS regression would use both. Additionally, what usually happens is once a link between a feature and an outcome has been learnt the model will often try and refocus on it.

\- How do you handle imbalanced datasets? The dataset we use is imbalanced -- 20% of observations fall into either the >+5% or <-5% category. Imbalanced datasets can often incentivize models to predict the variable which is overrepresented. For example, if we had a dataset skewed 19:1 for positives to negatives then if the model only predicted positives we would have an accuracy of nearly 95%! To overcome this we can weight the different classes in relation to their frequency. In practice this scales the errors terms of the minority class in order to encourage the model to focus correcting them.

\- What hyperparameters are you focused on? Hyperparameters are parameters which can control the learning process for our model. This is key to prevent over/ underfitting. Some of the hyperparamters which we focus on the most include the max depth of the tree, the learning rate (to slow down the learning), the number of trees in our ensemble and minimum samples in a single leaf.
